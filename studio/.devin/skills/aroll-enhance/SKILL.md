# aroll-enhance — 口播增强(字幕层 + 镜头呼吸,直接出片)

输入提示：`[视频路径] [srt路径]`

**这是编排型总入口,自己不实现任何效果**:两条支线各自是现成管线,本 skill 只负责
并行推进、内部自检并直接出片,以及交付时说清楚在剪映里怎么叠。
学习来源:高高lindsey 拉片(蓝图与参考帧见 `docs/reference/INDEX.md` 的 lindsey 条目)。

**REQUIRED REFERENCE:** 镜头支线开始前完整阅读 `references/shot-switching.md`。镜头变化按信息重量和叙事目的规划，不再按字幕停顿自动生成。

当前效果基准：镜头支线同时阅读[口播镜头风格 v2](../../../docs/aroll-camera-style.md)。未指定新风格时执行2026-09-10用户批准的v2：变化可见、全景为主、次数不限、硬切少用。只有明确要求复现0904才读历史配方；防抖实现继续复用。

## 输入

- 用户的实拍口播视频(mp4/mov;**处理不动原声、不动时长、不剪任何内容**)
- 对应的 SRT；只有音频时先用本机 Whisper 生成 SRT。已有 `caption-script.json` 就直接复用
- 可选:画幅说明(横片要在 caption-script.json 顶层写 `"canvas":{"width":1920,"height":1080}`)

## 流程(默认连续执行)

```
建项目目录 projects/<yyyy-mm-dd>-<短名>/  (视频、srt 拷进去)
   │
   ├─ 支线 A:字幕层(既有管线,一步不减)
   │    SRT → 语义分句提炼成 caption-script.json(遵守字幕层排版四条硬规则:
   │      错位随行宽收敛/只有铺垫→结论才错位/结论行升档位/文案要提炼——
   │      **不是逐句照抄 SRT**,是提炼;时间轴对齐 SRT)
   │    → node tools/lint-caption-script.mjs <脚本> --duration <音频秒>
   │    → node tools/caption-iterate.mjs <项目名>       # 低分辨率整片 + 接触印张
   │
   ├─ 支线 B:有目的镜头切换
   │    完整读 SRT + 听语气/停顿 + 查看候选点表情动作 + 盘点证据素材
   │    → 按 references/shot-switching.md 写 version=2 shot-plan.json
   │    → node tools/aroll-breath.mjs check <视频> <shot-plan.json>
   │
   ▼
【内部自检】真实查看字幕接触印张，并抽查镜头变化前后帧、眼位锚点与裁切安全。
      两边通过就直接继续；印张和 shot-plan.json 保留为可追溯的 review 产物。
   │
   ├─ 支线 A:node tools/caption-finalize.mjs <项目名> --tag <名字>
   │    → <tag>-hevc.mov(字幕层,带 alpha)+ <tag>-preview.mp4
   │
   ├─ 支线 B:node tools/aroll-breath.mjs apply <视频> <shot-plan.json>
   │    → <视频名>.shots.mp4(音轨原样拷贝,时长零漂移——工具自检会报)
   ▼
交付
```

## 交付约定

用户已明确：默认只交两个独立产物——透明字幕MOV，以及保留原声、不烧字幕的镜头视频。不得默认制作或交付两者组合的preview/final；已有管线自动生成的合成预览仅供内部检查，不作为用户交付物。只有用户另行明确要求才交合成版。

## 交付时必须说清的三件事

1. **剪映里的叠放顺序**:呼吸视频在底、字幕层 mov 在顶。字幕层**不跟着变焦**
   (字是屏幕层不是场景层,Lindsey 原片同款逻辑)——所以必须分两层交付,
   不许把字幕烧进呼吸视频再交。
2. **画质**:呼吸处理是一次重编码(hevc_videotoolbox q65,视觉无损档);
   4K 素材出 1080 时，小幅数字变焦有分辨率余量，但仍有重采样和有损编码，不承诺数学无损。
3. **配套模板**:控制台「做片子」里的 pill-stack(胶囊标签层)/ word-cascade
   (逐词动字)导出的双通道 .mov 也是往同一条时间线上叠的,列举段可以配着用。

## 硬约束

- 两条支线**并行推进**,不许串行等。
- 没有明确目的时保持当前镜头；不得按标点、固定秒数或字幕段落自动推拉。
- A/B/C 试片起点为 1.00/1.12/1.18，可只用两档；正常速度下推拉须可见，保护头顶、肩部与手势。快推快拉先试0.25–0.50秒，慢推慢拉1.5–3秒。
- 证据、操作、数据或对比画面优先于人物变焦；素材不存在就记录缺口，不虚构。
- 不限制变化次数，不按固定秒数生成。基础全景以75%–85%为试片目标；推进、近景保持、拉回合计计入非全景时间。每个近景段规划回程；check 的观感复核项必须逐项处理，低于半数全景须返工或有明确用户例外。
- 首次使用v2先生成20–30秒代表试片，真实查看正常速度下的慢推、快拉及全景占比，再扩展全片；不能仅看印张宣布运动可见。
- 默认不中途确认，内部查看印张和标记后直接出片；用户明确要求先审版时才暂停。
- 只有输入时间轴明显错位、素材身份无法判断或可能覆盖原素材时停下；一次列全问题。
- apply 必须写到新文件，绝不原地覆盖用户素材。
- apply 自检(时长漂移 ≤0.1s)不过不许交付;字幕层照旧走 caption 管线自己的门禁。
- SRT 时间轴与视频对不上(明显错位/超长)先停下来问,不要硬对齐。
- 本 skill 不出 Styleframe、不走 motion 的 13 步生产序列——它是素材处理不是创作。

## 统一产物位置

执行前读取 `docs/artifact-layout.md`。统一入口 `../output/<SC-XXXX>/` 只放可直接使用的资源，分类目录内平铺中文内容名文件；无内容不建目录。合同、报告、日志、工程与旧版本留在仓库 workspace 或隐藏 `.制作资料`。内部验收后同步可用资源到用户目录，不再放 README 和制作流程目录。

## 上游 B-roll 调用与可编辑镜头

自媒体工作流调用与本仓库直接调用使用同一 v2 流程。接收已有 SRT、实测时间轴和节奏证据时复用，禁止重复转写。用户只要求推拉或上游指定仅镜头支线时不新增字幕。控制台 source.cameraPlan 保存完整 version=2 计划，参数面板支持预设动作、时间、倍率、速度曲线与锚点，预览及导出共同使用 src/editor/aroll-shot-plan.mjs；CLI 通过 tools/lib 同源导出。source 必须是未经推拉处理的原片，避免双重缩放。

## 口播镜头效果块（2026-10-09）

交付编辑工程时，按“推近—保持—回程”将每组变化转成独立镜头效果块，放在口播镜头轨道。调用 `templates/remotion-base/src/editor/camera-clips.mjs` 的 `cameraClips(plan)` 与 `withCameraClips(plan, clips)`，将返回完整计划写入 source.cameraPlan。clipGroups 是可编辑块，events 是同源执行结果；不得分别手改两份数据。原生验证拒绝二者不一致。已迁移计划逐帧核对无变化。每块独立倍率、启用状态和进/停/出时长；预览、拖拽与导出均读取同一计划。切换模板保持块的起止范围，拖边按比例调整三阶段；复制只放空位，不覆盖相邻镜头。
