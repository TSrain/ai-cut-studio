# 声音设计

## 口播制作新约定（2026-10-11，优先于下文历史条款）

口播项目以 `../workflow/config/sound-design.md` 与 `docs/sound-design-contract.md`（同上游仓库）为方法论和合同。package 同时设计画面与声音作用，broll 对齐真实转写/动画事件并落独立音轨。下文 S3“声音只能画面定稿后做”、S4“动作与声音严格等长”、固定禁合成音仅作历史，不继续约束口播。声音意图早设计，实际落点晚绑定；尾音可自然延续并淡出。

当前 181 条文件存在已核实，旧 33+149 数字有偏差；本轮没有声称逐条试听。模板配方见 `tools/editor/sound-recipes.mjs`，27 个注册模板都有候选或明确留白；模板侧栏可添加默认声音，再在独立音轨改时间、音量、静音、淡入淡出。候选目前标“待试听”，逐期做音画试听后再固化。

`tools/editor-sound-design.mjs` 接收已经对齐的 sound-cues.json，通过 load/save API 校验 revision 导入；保留手调、删除、锁定和其他配乐。模板侧栏添加的声音也是普通独立音轨，当前不会自动追随后续模板移动，需同时选中移动或重新对齐。Remotion 负责确定性播放与混音，不替代声音创意与听验。


> 2026-08-20 建。此前本项目**没有声音方法论**——SFX 库只有 33 个梗音效,无 BGM、无卡点、无选音判据。
> 本文的判例与卡点方法来自 video-shotcraft(Apache-2.0)的实战积累,已按本项目语境改写。
> 编号 `S1`–`S6` 与 `docs/taste-rules.md` 的 S 段是同一套,review 里可以直接引编号。

## S1. 按**片种**选音,不按**事件**选

**结论**:先定这支片子是什么片,再定音色词汇表;不要看到"点击"就去找点击音。
产品/信息类片子的词汇表是:`riser → impact → sparkle` 加 `whoosh` 与 `transition`,
音色是电影系;游戏音包那种 8-bit / 合成 tone 一律不用。

**禁音色不禁动作**:画面里真有点击、开关、翻页,就该配那个动作的拟音——
禁的是音色(合成 tone / bleep / 通知音),不是"不许配交互音"。

`ui/` 是全库唯一**内部质感分裂**的类别:18 个里只有 4 个是真实物件拟音。
目录已逐条标了 `verdict`:`ok`(可直接用)/ `maybe`(必须在成片语境里试听再定)/ `no`(合成音,默认不用)。
**不许整目录放行。** `data/` 与 `scifi/` 同理,只是那两类的用途本就是"数字/科技质感",不容易被误用。

**落点**:`资产`(CATALOG.json 的 verdict 字段)+ `仅文档`

## S2. 连发音效要双样本交替 + 音量阶梯递减 + 间隔加速

**结论**:同一个音连响三次以上就是机枪声。

**做法**:准备两个同类不同音色的样本交替使用;音量按 1.0 / 0.85 / 0.72 递减;
间隔逐次缩短(如 8f / 6f / 5f)。三件事一起做才像"一串",只做一件仍是复读。

**落点**:`仅文档`

## S3. 声音在画面锁定之后做;时间线一动,SFX 全表重钉

**结论**:先做声音等于白做——画面改一帧,所有钉点全废。

**做法**:阶段顺序是 画面定稿 → 渲出成片 → 配音效 → 重渲。
中途若改了时间线,**不要局部微调钉点**,整表重钉:局部调过的表下一次改动时没人知道哪些是对的。

**落点**:`仅文档`

## S4. 拟音优先于装饰音,且音频裁到与动作严格等长

**结论**:画面上有什么动作,就配那个动作的真实声音;不要为了"有点声音"加装饰音。

**做法**:音频长度裁到与动作等长(靠 `<Sequence>` 截断,不要靠淡出蒙混)。
长于 5s 的样本(库里有若干)默认要截。

**落点**:`仅文档`

## S5. 钉帧一律相对 shot 起点,不用绝对帧

**结论**:这条和本项目「一切从 `useCurrentFrame()` 推导」是同源的确定性要求。

**做法**:SFX 的 `from` 写成 `shotStart + offset`,不写死绝对帧。
拼接顺序一变、某镜时长一改,绝对帧全错且**不报错**——只是声音和画面对不上,而这在抽帧自查里看不见。

**落点**:`门禁`(可量:检查 SFX 的 from 是不是字面量)

## S6. 轻音素材要预归一化,不能靠调 `volume` 救

**结论**:`volume` 是**乘法系数不是目标音量**。给到 1.0 也只是原样播放。

**做法**:库里 7 个峰值低于 -12dB 的样本已在 CATALOG 里标了 `quiet: true`。
它们会被 BGM(0.34 铺底约 -9.4dB)整个盖住。
处理办法按优先级:① 换素材 ② 预归一化 ③ 给 >1 的增益**并验峰**(别削顶)。

**落点**:`资产`(CATALOG.json 的 quiet 字段)

## 卡点(强节奏 BGM 的片子)

### 何时启用
用户**已经选好音乐**且音乐有明确鼓点时。没有 BGM 或 BGM 是氛围铺底的片子不要卡点——
那会让剪辑跟着一个观众听不见的节奏走。

### 1. 不要相信节拍检测返回的 tempo 标量

上游实测:检测器给出 129.2 BPM,真值是 131.97 —— **偏差 2%+**。
2% 的偏差在 30 秒的片子末尾会累出接近一拍的漂移,拼完就和原声对不上。

**做法**:检测器给出的**逐拍时刻序列本身是好的**,拿整个序列做**最小二乘等距网格拟合**
求真实 BPM 与相位:`t_i = t0 + i·T`。本项目的实现是 `node tools/beat-grid.mjs`
(纯 JS + ffmpeg 解 PCM,**不需要 Python/librosa**)。

### 2. 网格先验收,再分镜

拟合出的网格要按**瞬态覆盖率**验收:每个网格点附近有没有真实的能量突起。
覆盖率不达标说明这首歌不是等距节拍(有变速/自由段),那就不该卡点。
`beat-grid.mjs` 会直接报覆盖率并给出结论。

### 3. 时间线用拍号写,不用帧号写

分镜的切点写成 `beatF(n)` 而不是 `frame: 138`。
理由:BPM 一改,所有帧号全错;拍号不用动。
稀疏重音要**钉真实瞬态**,不要钉网格插值点——网格是均匀的,音乐不是。

### 4. 渲后回测(闭环,必做)

从**成片**里抽音轨,检测切点附近的瞬态,报每个切点的误差。
`node tools/verify-beat-sync.mjs <成片> <beats.json>`,**误差 ≤3 帧**才算过。
两种误差要分开报,别混为一谈:
- **网格误差**:拟合网格与真实瞬态的偏差(音乐本身的问题);
- **对齐误差**:画面切点与网格的偏差(我们的问题)。

### 5. 交付固定两版

配了 BGM 的片子终渲**固定出两版**:带 BGM 版 + 无 BGM 版(保留 SFX)。
靠同一条时间线的 `bgm` inputProp 切换。用户想自配音乐时不用返工。
