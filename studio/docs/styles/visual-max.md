# Profile:visual-max

用户 2026-10-12 已取消首尾帧最低墨量、最低材质种类、默认弹簧次数、固定语义节拍上限及计时/重试自动降质。密度与运动参数只描述本期设计，不作为默认必达额度；实际表达以批准方案和真实播放验收为准。60 分钟只作预算提示，不冻结范围、不自动判质量失败。

**默认 profile。** 目标是第一眼就把人按在屏幕上:满构图、多层空间、材质丰富、字体有态度。
不确定选哪个 profile 时选它——`docs/visual-first.md` 的评分表按这个密度标定。

它是 visual-first 的一种视觉语言,不是"最花的那档"。四个 profile 平级,区别在语言不在强度。

## 参数

| 项 | 值 |
|---|---|
| `density.target` | 8–9 / 10 |
| 占屏率(非底色像素) | 占屏率只描述版面，不以数值判完成或失败 |
| 空间层次 | 按表达需要设计，不设最低层数或材质种类 |
| 材质信号 | 可选手段，按构图与表达需要使用，不计最低种类 |
| 焦点 | 1 主 + 最多 2 次级锚点 |
| 语义节拍 | 随口播与理解负荷设计，不设固定数量额度 |

## 配色自由度

- 一个主色 + 最多两个辅助色;**强调面积 20%–35%**(整体默认区间是 10%–35%,本 profile 走上半段)。
- 允许辉光、Bloom、环境光斑、渐变映射的背景场——条件是主文字对比度仍达标(正文 ≥4.5,大字 ≥3.0)。
- 允许颜色表达能量、材质、空间,不必逐处解释它在编码什么信息。
- 明度阶梯仍是骨架:层与层 ≥0.04 L,否则堆再多元素也读成一片。
- 颜色在 `visual-contract.json` 的 `palette` 里声明一次,组件只消费 token。

## 排版偏好

- kit 首选 `impact`(得意黑 + Archivo),数据密集时 `tech-data`。
- 主标题 `hero` / `h1` 级起步,占宽 ≥70%,主动折行不缩字号。
- 三个主要语义层级 + 微型元数据(眉题、单位、时间码、署名)不计入。
- 允许第三个小范围角色:mono 做数据与时间码,decorative 做单个符号。
- 得意黑负字距 + 8° 斜切,容器补 `paddingLeft: '0.14em'`,否则首字左下出血被裁。

## 材质

背景不能是纯色板。至少给一层结构:网格、渐变场、噪点、模糊光斑、大尺度几何、或一张处理过的图。
主体元素要有表面:受光渐变 + inset 厚度 + 描边边界这一组是最省事的三件套(模板 `MetalCoin` 是先例)。
前景叠加负责"这是一个被拍下来的画面"而不是"这是一张网页截图":颗粒、暗角、局部景深、扫光。

## 运动性格

- 快而重:入场 10–16 帧,转场 18–26 帧。
- 弹簧为可选表达手段，不设次数或必用额度；实际播放复核焦点与读数。
- 背景允许持续低强度运动(缓慢漂移、光场呼吸、噪点流动),文字停留期间背景不必冻结。
- 镜头运动方向全片一致(统一向左或向上推进),转场要有空间逻辑:上一镜焦点位置决定下一镜起点。

## 什么时候不该用它

- **纯文字金句镜、悼念/严肃通告类内容**:满构图会显得吵,选 `editorial-luxe`。
- **多系列图表读数镜**:高强度背景和大面积强调色会压掉数据可读性,选 `data-cinematic`。
- **品牌方给了严格 VI 规范**(固定字体、固定色值、留白规定):选 `brand-energy` 并把规范写进合同。
- **画面主体是别人的截图或实拍**:前景材质叠加会盖掉真正要看的东西,减层,或改用 `data-cinematic`。
- 注意:"时间不够"**不是**换到更素画面的理由。记录预算变化，继续必要制作和修复，不自动降质。
