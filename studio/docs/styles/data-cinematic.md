# Profile:data-cinematic

用户 2026-10-12 已取消首尾帧最低墨量、最低材质种类、默认弹簧次数、固定语义节拍上限及计时/重试自动降质。密度与运动参数只描述本期设计，不作为默认必达额度；实际表达以批准方案和真实播放验收为准。60 分钟只作预算提示，不冻结范围、不自动判质量失败。

数据解释、财报、指标看板、系统架构、关系网络。**它不是"图表加动画"**——它是把界面和数据当作被拍摄的物体:
有空间、有材质、有镜头运动,同时读数一个不错。密度要求和 `visual-max` 一样高,只是密度由结构而不是特效提供。

## 参数

| 项 | 值 |
|---|---|
| `density.target` | 6–8 / 10 |
| 占屏率(非底色像素) | **50%–75%**。图表周围的坐标系、网格、图例、元数据轨都算,一条光秃秃的折线不算 |
| 空间层次 | 按表达需要设计，不设最低层数或材质种类 |
| 材质信号 | 可选手段，按构图与表达需要使用，不计最低种类 |
| 焦点 | 1 主(结论数字或结论线)+ 最多 2 次级锚点(对比项、时间轴) |
| 语义节拍 | 随口播与理解负荷设计，不设固定数量额度 |

## 配色自由度

- **两套颜色分开**:画面调性(底色/墨色/面板/网格)走 `palette`;图表分类系列走功能色 `theme.seriesDark/seriesLight`(已过 CVD 验证)。混用是本 profile 最常见的错误。
- 一个主色 + 最多两个辅助色;**强调面积 12%–25%**,强调留给结论项和当前焦点。
- 允许辉光和景深,**但不许打在数据元素上**:发光的折线在压缩后会糊,而且看不出精确值。光只打给背景和面板边缘。
- 系列色不当文字色用,状态色不当系列色用;数值、标签、图例文本一律用墨色。
- 系列超过 4 个:合并成"其他"或拆画面,不发明第 5 种颜色。
- 永不用彩虹渐变映射数值;渐变只做装饰性背景。

## 排版偏好

- kit 首选 `tech-data`(Noto Sans SC + JetBrains Mono + Archivo);偏产品/商业时用 `modern`。
- 数据用 `textStyle('data')` + `numeric(true)` 等宽对齐;单个主数字用比例数字。
- 三个主要语义层级 + 微型元数据豁免(单位、时间码、数据源、轴标)。本 profile 的元数据密度天然高,这是特征不是违规。
- 正负号、货币符号、百分号弱化一档,让数值抢视线。
- 标题直接写结论句("Q3 由入口业务驱动"),不写栏目名("Q3 收入构成")。

## 材质

面板是主要载体:`surface / surfaceRaised / line` 明度阶梯 + inset 厚度 + 一道边缘高光,就能把图表从"贴纸"变成"物体"。
背景给网格或渐变场,承担空间感。图表本身的材质来自结构:坐标系、面积填充、端点圆点带表面色描边环、
选择性数据标签、参考线。**一条 6px 的折线孤零零挂在空底上是本 profile 最典型的失败画面。**

## 运动性格

- 中速、精确:入场 12–18 帧,图表绘制 36–60 帧,数字滚动 24–45 帧。
- 弹簧为可选表达手段，不设次数或必用额度；实际播放复核焦点与读数。
- 数字滚动是主要的强调手段;多系列用 stagger 分批进入(间隔 2 帧左右),不同时轰炸。
- 镜头运动:缓慢推近到结论区域,焦点坐标走 `docs/locate-protocol.md` 拿,不许目测。
- 背景可保持低强度运动(网格缓移、光场呼吸);数据读取时刻图表本身必须静止,给足 1 秒/10 字。

## 什么时候不该用它

- **没有真实数据、只是"看起来像数据"的装饰画面**:那属于 `visual-max` 的 Digital Spectacle 语言,别在这里假装有数据(合同要写 `facts.mode: "illustrative"`)。
- **一句话金句镜、口号镜**:面板和网格会喧宾夺主,选 `brand-energy`。
- **人物、故事、文化类叙事**:选 `editorial-luxe`。
- **单个数字的冲击镜**:不需要坐标系和面板,大数字直接上,选 `brand-energy` 或 `visual-max`。
- 数据本身不可靠或还没核对完:先核对。事实正确是硬门槛,本 profile 里错一个数量级就等于全片作废。
