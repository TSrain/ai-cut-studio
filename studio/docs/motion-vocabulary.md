# 运动基元词汇表

用户 2026-10-12 已取消首尾帧最低墨量、最低材质种类、默认弹簧次数、固定语义节拍上限及计时/重试自动降质。密度与运动参数只描述本期设计，不作为默认必达额度；实际表达以批准方案和真实播放验收为准。60 分钟只作预算提示，不冻结范围、不自动判质量失败。


`storyboard.md` 的"动画行为"列**用这里的基元名写**,不要写自由散文。理由:分镜和实现之间需要一套共享词汇,否则"文字动感地出现"这种描述到了代码阶段等于没说,每次现场发挥,结果不可复现也不可评审。

写法:`基元名(参数)`,例如 `slide_up(24f) → hold(45f) → fade_out(12f)`。帧数按 30fps。

实现一律走 `src/lib/anim.ts` 的 `ENTER`/`EXIT`/`MOVE` 和 `progress()`;下表的"实现"列是配方,不是让你另起一套曲线。时长取值区间见 `docs/design-principles.md` §1。

## 入场

| 基元 | 实现(Remotion) | 适合的性格 | 默认时长 |
|---|---|---|---|
| `slide_up` / `slide_down` / `slide_left` / `slide_right` | `translateY/X` 从 ±(40–150)px 到 0,`opacity` 0→1,`ENTER` | 沉稳、有条理、专业 | 12–21f |
| `fade_in` | 仅 `opacity` 0→1,`ENTER` | 克制、次要元素 | 8–14f |
| `fade_blur` | `opacity` 0→1 + `filter: blur(14px→0)`,`ENTER` | 电影感、柔和揭示 | 14–21f |
| `scale_grow` | `scale` 0.9→1 + `opacity` 0→1,`ENTER` | 温和强调 | 12–18f |
| `scale_punch` | `scale` 0.6→1 + `opacity` 0→1,末端轻微过冲 | 冲击、有能量 | 10–16f |
| `word_reveal` | 逐词 `slide_up` + `staggerDelay(i, base, 2)` | 叙述、金句 | 每词错开 2f |
| `char_reveal` | 逐字同上,`gap=1–2` | 短标题(≤10 字)专用 | 每字错开 1–2f |
| `typewriter` | 按 `progress()` 截取字符数,或 `clip-path` 横向推进 | 技术、代码、终端 | 按字数算 |
| `draw_on` | SVG `strokeDasharray`/`strokeDashoffset` 随 `progress()` 归零 | 线条、路径、图表折线 | 36–60f |
| `count_up` | 数值随 `progress()` 插值,`tabular-nums`,末段减速后**静止** | 数字焦点 | 24–45f |
| `wipe_in` | `clip-path` 单向推进(`inset`),`MOVE` | 图片/图块/色带 | 18–30f |

## 强调(原地,不改变位置)

| 基元 | 实现 | 适合的性格 |
|---|---|---|
| `scale_pulse` | `scale` 1→1.06→1,`MOVE`,只做一次 | 节拍点、指向关键数字 |
| `color_shift` | 色值从次级墨色过渡到强调色 | 状态变化、结论落定 |
| `underline_sweep` | 下划线 `scaleX` 0→1,`transformOrigin: left`,`MOVE` | 关键词、标题收束 |
| `marker_band` | 关键词背景色带 L→R 长出,见 `KeywordHighlight` 组件 | 引文、金句、报道式高亮 |
| `weight_shift` | `fontWeight` 或 `fontVariationSettings` 跃迁 | 排版驱动的强调 |

## 出场

| 基元 | 实现 | 说明 |
|---|---|---|
| `fade_out` | `opacity` 1→0,`EXIT` | 默认出场 |
| `slide_out` | 位移离场 + `opacity` 1→0,`EXIT` | 有方向逻辑时用 |
| `wipe_out` | `clip-path` 反向收起,`EXIT` | 与 `wipe_in` 配对 |

**只有最后一镜需要显式出场。**镜与镜之间,转场本身就是上一镜的出场——再叠一层淡出是多余的。

## 保持

| 基元 | 说明 |
|---|---|
| `hold(Nf)` | **静止读取时刻**。文字出现后必须 hold 够读完(1 秒 / 10 字)。分镜里要显式写出来,不写就会被实现阶段挤掉。 |
| `breath` | 极轻微的 `scale` 1→1.012 缓慢往复,只用于长时间停留的画面避免死板。**一个画面最多一个元素做 breath。** |

## 运镜(整幅画面的相机动作,不是元素的入场)

**这一段和上面几段的粒度不同**:上面管「一个元素怎么进/怎么退」,这一段管「相机怎么动」。
一镜通常是「一个运镜 + 若干元素动作」,两者不冲突。

前四式是 `KenBurns` 一个组件的参数表达(平面裁窗推移);**后五式要 `DepthCam`**,
因为它们的说服力全来自「不同深度的东西动得不一样」——那是平面裁窗做不到的。

| 词 | 怎么实现 | 用在什么场合 | 时长参考 | 要分层素材吗 |
|---|---|---|---|---|
| `push` | `KenBurns` 焦点不动、`scale` 1.02→1.18 | 最安全的一式,不知道用哪个就用它 | 全镜 | ❌ |
| `pull` | `KenBurns` 从局部退到全景 | 先看细节,再交代这是哪儿 | 全镜 | ❌ |
| `pan` | `KenBurns` 焦点左右走、缩放几乎不变 | 顺着一条线读过去(时间轴、流程、长图) | 全镜 | ❌ |
| `diagonal` | `KenBurns` 边移边放大 | 最有摄影机在走的感觉;**一支片 ≤1 次** | 全镜 | ❌ |
| `crash_zoom` | `DepthCam` 6–11f 急推 + `shakeAt()` 撞停震屏 | 「点名」:把观众视线一把按到目标上 | 动作 <15f,前后各留 hold | ❌ |
| `dutch_roll` | `DepthCam` `roll` −8°→0 | 纠偏、落定的情绪 | 40–60f | ❌ |
| `multiplane` | `DepthCam` 三层 `parallax` 0.16/0.5/1.0 | 平面素材要「有厚度」 | 60–90f | ✅ |
| `dolly_zoom` | `DepthCam` 主体 `zoomGain` 0、背景 1.9 | 戏剧性蓄力;**一支片 ≤1 次** | 60–90f | ✅ |
| `orbit_freeze` | `DepthCam` 层带 `z` 偏移 + 扫 `yaw` | 给静止主体做特写巡视 | 60–90f | ✅ |

**标 ✅ 的三式需要真实前景层**:`swiftc -O tools/matte.swift -o /tmp/matte`,
然后 `matte <图> <前景.png> --trim --alpha-gamma 3.2 --width <显示宽>`。
**抠不出来就退回 `push`/`pull`**——拿两张平面图假装分层比不分层更难看,
观众能看出「该动的地方没动」。

三条参数下限(都是踩出来的,写死在组件的 `params` 里):
`crash_zoom` 动作超过 15 帧就不是撞是推;`dutch_roll` 起手超过 10° 读成失误不是风格;
`multiplane` 层间 `parallax` 差 >0.5 会读成「两张图各自在滑」。

九式都能在控制台「运镜」区看循环片,**指着说「要这个」比描述快得多**。

## 受限与禁用

这些在别处很常见,在本项目里受硬规则约束(`docs/design-principles.md` §2/§3/§8),分镜里写了也会被实现阶段驳回:

| 基元 | 状态 |
|---|---|
| `bounce_in` / 弹跳过冲 | **受限**——一个画面最多一个元素;商务/金融风格全程禁用。需要风格卡明确允许。 |
| `slam`(砸落 + 震屏) | **受限**——只在 `bold-shorts` 类风格卡下,且全片最多一次。 |
| `wave`(逐字波浪) | **禁用**——装饰性运动,答不出信息理由。 |
| 每元素异向飞入 | **禁用**——典型廉价模板感(§3)。相关元素同组同方向。 |
| 旋转入场的文字 | **禁用**(§8) |
| 线性位移 | **禁用**——线性只允许出现在匀速循环和进度条(§2)。 |
| 持续晃动/循环闪光/装饰粒子 | **禁用**(§8) |

## 用法约束

- **一次一个焦点**:任何时刻只有一个元素在"表演"(§3)。分镜里同一时间段出现两个入场基元 → 改成 stagger 或拆镜。
- 8 秒以内的短片,视觉事件不超过 4 个(§1)。一个基元 = 一个事件。
- 每个基元都要答得出"它帮观众理解了什么"。答不出就删——这条比上面所有表都优先。
