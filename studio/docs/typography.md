# 排版方法论

写任何有文字的画面之前读这份。默认值在 `design-principles.md` §6,这里是**怎么做到**。
代码实现在 `templates/remotion-base/src/lib/fonts.ts`,样张 `npx remotion still TypeSpecimen --frame=60`。

**字体套装(kit)是合同里的显式输入,不是库存里的可选项。** `visual-contract.json` 的
`typography.kit` 必须取以下六套之一,`textStyle()` 必须同时接收 kit 和 style role:

| kit | 中文 | 拉丁 / 数字 | 性格 | 常配 profile |
|---|---|---|---|---|
| `impact` | 得意黑 Smiley Sans | Archivo | 品牌冲击、大标题 | brand-energy / visual-max |
| `editorial` | 思源宋体 Noto Serif SC | Instrument Serif | 编辑、文化、权威 | editorial-luxe |
| `human` | 霞鹜文楷 LXGW WenKai | Inter | 人文、叙事、温度 | editorial-luxe |
| `modern` | 思源黑体 Noto Sans SC | Archivo / Inter | 科技、产品、现代商业 | brand-energy / data-cinematic |
| `tech-data` | 思源黑体 Noto Sans SC | JetBrains Mono / Archivo | 数据、代码、界面 | data-cinematic / visual-max |
| `minimal` | **霞鹜新晰黑 LXGW Neo XiHei** | Inter | 克制、留白、发布会大屏 | keynote-calm(口播 preset 默认) |

### `minimal` 的两条特殊规矩

1. **字重上限 500**(`TypographyContext.weightCap`)。新晰黑只有 400 一档,西文不压到同一档,
   一行字里就是"西文真粗 + 中文假细"——那正是"中文看着虚"的来源。
2. **全系统 `font-synthesis: none`**(2026-08-15 起,不只 minimal)。库里有四款单字重中文字
   (新晰黑 400 / 文楷 400 / 得意黑 400 / 思源宋 700),对它们请求更粗的字重时浏览器会把字形
   横向拉胖伪造一个粗体:笔锋糊掉、灰度变脏,**而且画面上不报错**,只是看着廉价。
   宁可渲出真实的 400,也不要一个假的 700。

**三张 Styleframe 至少用到两个不同的中文 kit**(品牌规范锁死字体时除外)——这是让用户真正看到字体差异的唯一办法。
`theme.font.family` 已删除;新代码不得把 `FONT.text` 当全局字体;可复用文字组件必须接收 typography context,
不许在组件内部暗选默认字体。**审查发现中文回退到默认字体时不得通过。**

## 0. 先诊断:"字看着 low"是哪三件事

用户说不出方法论,但每次都能一眼看出来。三个判据,命中一条就是 low:

1. **用了默认字体,或中文静默回退。** `system-ui` / `-apple-system` 在 macOS 上西文落到 Helvetica/SF、中文落到苹方。这是**全世界所有画面的默认值**,所以它自带"没做选择"的气味。同样糟的是**隐式回退**:代码里写了 `FONT.text` 当全局字体,七个字体文件都加载了,中文却全片都由思源黑体渲染——库存不产生输出差异就等于没有库存。
2. **字号是唯一的层级手段。** 只有大小变化、字重永远 400/700 两档来回切、字距行高从来没动过。这样的画面每一行都"正确",合起来像一份表格。
3. **中西文混排没有处理。** 一个 fontFamily 从头用到尾,西文和数字被中文字体里那套敷衍的西文字形渲染,或者中文被西文字体的回落字体渲染。这一条是中文项目最常翻车的地方。

三条对应下面 §1 §3 §4。

## 1. 字体角色制:两个主角色 + 小范围豁免

**一支片子两个主角色**(展示 + 正文),由合同的 `displayRole` / `bodyRole` 指定。
**小范围的 mono / decorative 角色豁免**,不计入两个名额:数据列与时间码用 mono(合同的 `dataRole`)、
单个符号或引号用 decorative。豁免的判据是**面积和频次**——只在几处小元素上出现,不承担正文或标题。

(旧规则是"最多两个角色,第三个要有真实理由"。改成豁免制是因为前者在实践中被执行成"数据也用正文字体",
表格数字跳来跳去。角色泛滥仍然是问题:两个主角色 + 两类豁免之外,不再加。)

| 角色 | 合同字段 | 中文 | 西文 | 用途 |
|---|---|---|---|---|
| 展示 | `typography.displayRole` | 按 kit 定(得意黑 / 思源宋体 / 霞鹜文楷 / 思源黑体) | Archivo / Instrument Serif / Inter | 大标题、金句、数字冲击 |
| 正文 | `typography.bodyRole` | 按 kit 定 | Inter / Archivo | 说明、标签、图表文字 |
| 数据 | `typography.dataRole` | — | JetBrains Mono / Archivo | 数据、时间码、单位、代码 |

**不要直接引 `FONT.display` / `FONT.text` 当全局字体**——先从合同拿 kit,再由 kit 解析出这三个角色。

字体文件在 `templates/remotion-base/public/fonts/`,母本在 `assets/library/fonts/`,全部 SIL OFL 1.1 / 免费商用(登记见 `assets/library/LIBRARY.md`)。

**各字体的性格**(选角色时按这个选,别按"好看"选):

- **得意黑**:中宫收紧、笔画硬朗、自带 8° 斜切。有态度、有速度感,竖版短视频标题的第一选择。**只在大字号用**(≥60px),小字会糊;单一字重,别指望调 weight。
- **思源黑体**:9 档可变字重,中性可靠。它是"正文的正确答案",不是"标题的答案"——拿它做大标题就会回到默认气味。**它也是最容易被隐式回退命中的字体**:全片中文都是它,通常意味着没人选过 kit。
- **霞鹜文楷**:楷体骨架、笔画有手写起收笔。人文、叙事、口述、文化类内容的第一选择,和 Inter 配得住;不要用在数据和 UI 上。
- **Archivo**:可变 wght + **wdth 宽度轴**。压缩到 wdth 75 做窄粗标题、拉到 112 做横幅字,这是真正的排版工具。
- **Inter**:西文正文与数字。x 高度大、字形开,和思源黑体的重心配得住。
- **Instrument Serif**:高对比展示衬线,一上来就是"编辑感/杂志感"。只用于展示尺寸。
- **JetBrains Mono**:数字辨识度高(0 带斜杠、1 有底衬),做时间码和数据列。

## 2. 字号从来不是一个数字

**永远用 `textStyle('h1')` 而不是 `fontSize: type.h1`。** 一个字号必须带着字重、字距、行高一起来,三者不配套就是那种"字号对了但还是很土"的画面。

字距规律(手写最容易漏的一条):

> 字号越大,字与字之间的视觉间隙越显宽 → **大字要负字距收紧**;
> 字号越小,间隙越挤 → **小字要正字距撑开**。

所以 `hero` 是 `-0.03em` 而 `caption` 是 `+0.06em`,不是随手填的。

| 预设 | 字号 | 字重 | 字距 | 行高 | 什么时候用 |
|---|---|---|---|---|---|
| `hero` | 224 | 800 | -0.03em | 1.02 | 强冲击标题、金句(展示体) |
| `heroQuiet` | 224 | 300 | -0.02em | 1.08 | 极简科技风:靠"大+细+松"拿高级感,不靠粗 |
| `h1` | 104 | 700 | -0.02em | 1.15 | 主标题 |
| `h2` | 68 | 600 | -0.01em | 1.30 | 次标题、结论句 |
| `body` | 44 | 400 | 0 | 1.62 | 正文 |
| `label` | 32 | 500 | +0.03em | 1.40 | 标签、轴标 |
| `caption` | 24 | 500 | +0.06em | 1.40 | 注释、署名、眉题 |
| `quote` | 104 | 700 | 0 | 1.45 | 引言(衬线) |
| `data` | 68 | 600 | -0.01em | 1.10 | 数据(等宽 + tabular) |

以上为 1080p 基准。**同一画面三个主要语义层级**(如:标题 / 结论句 / 说明),
**微型元数据豁免**——眉题、图注、单位、时间码、署名、轴标不计入这三级。

(旧规则是"同一画面最多 3 级字号"。照字面执行会逼掉所有元数据轨,而元数据轨恰恰是编辑感和信息密度的主要来源。
豁免的判据同样是面积和频次:`caption` 级、只占几处、不承担主要信息。)

层级只有三种合法手段:**字号、字重、明度**。三者组合足够拉出 5 层以上的差异。不合法的手段:给次要文字换颜色(颜色要承载意义,见 `color.md`)、给标题加描边/阴影/渐变。

## 3. 中西文混排(中文项目的必修课)

**① 栈顺序:西文字体写在中文字体前面。** 这一行就是"看着专业"和"看着像 PPT"的分界:

```ts
// 对:西文走 Inter,中文回落到思源黑体,各用各的长处
`'Inter', 'Noto Sans SC', sans-serif`
// 错:西文也由思源黑体渲染——它的西文是配角,窄、平、没细节
`'Noto Sans SC', 'Inter', sans-serif`
```

**② 行内西文/数字抬 6%。** 西文的 x 高度低于汉字的视觉高度,同字号排在一起西文显小。用 `latinInline` 包住西文 span(`fontSize: 1.06em`),**不要整行放大**——整行放大会把中文也带大,那不是这个问题的解法。

**③ 中文行高比西文松一档。** 方块字没有升降部帮忙分行,`1.6` 是中文正文行高的下限,纯西文可以到 `1.5`。

**④ 标点用全角,但**:句首不出现点号/收尾引号/收尾括号(避头尾);行末的全角标点会留出半个字的空档,窄栏排版时主动改断行位置而不是改标点。冒号引号一律沿用需求单原文,**一字不差**。

**⑤ 禁止伪粗体和伪斜体。** `fontWeight: 900` 在没有 900 字重的字体上会触发浏览器合成粗体(把笔画描粗),中文字会糊成一团。可变字体(思源黑体 100–900、Archivo 100–900)可以任意取值;得意黑、思源宋体是单字重,**不许调 weight**。同理不用 `fontStyle: italic` 伪斜中文。

**⑥ 不许用 `scaleX/scaleY` 拉字。** 拉伸会毁掉笔画的横竖粗细比例,这是最廉价的一种翻车。要窄要宽用 Archivo 的 `width(wdth)` 宽度轴。

## 4. 数字排版

- **数字列、要纵向对齐** → `numeric(true)` 等宽数字(`tabular-nums`)。表格、排行榜、逐帧滚动的计数器都属于这类:比例数字会让数字左右跳。
- **单个主数字**(一屏就这一个大数)→ `numeric(false)` 比例数字更好看,字形间距是设计过的。
- 正负号、货币符号、百分号**弱化一档**(降到次级墨色或小一号),让数值本身抢视线。
- 单位跟数字之间不留全角空格,用 0.15em 的间隙。

## 5. 视频特有的坑

- **缩略图测试**:关键帧缩到 320px 宽,主信息仍须可辨(硬规则)。竖版正文不小于 `body`(44)。
- **字体必须等加载完再渲染。** `fonts.ts` 用 `delayRender` 挡住首帧;少了这一步首帧会用回落字体渲出去,抽帧自查看到的和成片不一样,而且极难查。
- **动画期间不要改 letterSpacing / fontWeight。** 字距动画会让文字在读的过程中抖动;字重动画在可变字体上会重排整行。要动就动位置、透明度、裁切。
- **斜切展示体(得意黑)首字左侧会出血。** 负字距 + 8° 斜切,首字左下角会顶到容器外被裁掉——给容器补 `paddingLeft: '0.14em'`。这是渲帧才看得见的问题,`0.06em` 不够。
- **长标题先算宽度再定字号**(`nowrap` 的场合),窄竖版放大字号靠**主动折两行**(`whiteSpace: 'pre-line'`,不改一个字),不靠缩字号。

## 5.5 版式变形要映射内容,不是用来证明"设计过"

旋转、斜排、分屏、字符墙、偏置到角落 —— 这些都是**合法手段**,这一节不禁止任何一种。

它约束的是**理由**:变形必须映射内容里的动作、关系或情绪变化。判据只有一条 ——

> **观众不看任何解释,能不能从画面里感知到这个变形和文案的关系?**

两种**不算**证明:

- **同方向装饰不算。** 背景字符场也斜、装饰横规也斜、标题也斜 —— 形式上互相呼应,但那只说明它们朝一个方向,
  没说明这个方向在表达什么。呼应是内部一致性,不是语义。
- **代码注释不算。** 在源码里写「这里用熵表示信息过载、用秩序表示看懂」,画面上看不出来就是没做出来。
  设计说明只能帮复盘,不能替画面证明寓意。

**反事实删除测试**(评审时必做):把变形恢复成普通排版,再看一遍。
如果理解和情绪都不受损,**就删掉那个变形** —— 它没有在换取任何东西。

> **⚠️ 这个测试必须在成片上做,不能在静帧上做。**
> 2026-08-04 实测踩过:案例 04 的收尾句原本有一个落定动画,主 agent 只看静帧就判定"缩放是装饰、删掉不损失理解",
> 删掉之后用户的反馈是「**闪现出来了,没有任何过渡动效,感觉很突兀**」。
> 理解确实没受损,**但情绪受损了** —— 而情绪只在运动里存在,单帧上永远看不出来。
> 判据里的「情绪」两个字不是修辞,过渡、节奏、停顿都归它管。**动效类的删除决定,一律渲成片再判。**

**变形要有过程,不是把复杂堆在那儿。**
用户对同一版的另一句评价是「**不是越复杂越好**,它就是一个死板呆板的一堆文字堆在那儿,然后直接跳到想要说明的文字上」。
如果画面要表达"从混乱到清晰",**那个转变过程本身才是语义**;先摆一堵复杂的墙再硬切走,复杂度上去了,表达没上去。

**节奏要像人说话,不像打字机。** 逐字等间隔上屏是打字机节奏;口播节奏有词组的抱团、有停顿、有轻重。
同一版被指出「不是更多信息的节奏比较拖拉,不像口播的节奏,而像是打字的节奏」。

> 2026-08-03 round-01 案例 04 的教训:那一版斜排是有承接的(背景字符场、装饰横规、主标题都沿斜向),
> 但用户的原话是「看起来设计这么怪异,而且没有什么设计寓意」。
> **有承接不等于有寓意。** 这也是为什么这条判据定在"观众能否感知",而不是"画面里有没有同向元素"。
>
> 同时明确:**不存在"中文默认居中"这条规则,不要往这个方向补。**
> 用户对上述案例的原话是「我只是说这个 case 下有点故意设计的意思,不是说中文都要居中」。
> 这个项目在 2026-07-31 已经栽过一次同形状的跟头(把「≤4 个视觉事件」读成「≤4 个元素」,产出一批空画面),
> 「默认居中」会以完全相同的方式被读成「居中最安全」。

## 6. 反模板自查

出现即返工:

- [ ] 用了 `system-ui` / `-apple-system` / 裸 `sans-serif`
- [ ] 合同里没写 `typography.kit`,或代码没走 kit 直接引 `FONT.text` / `theme.font.family`
- [ ] 中文静默回退:成片里所有中文都是思源黑体,而合同选的不是 `modern` / `tech-data`
- [ ] 三张 Styleframe 用了同一个中文 kit(品牌规范锁死字体除外)
- [ ] `textStyle()` 只收了一个参数(没给 kit 或没给 style role)
- [ ] 全片只有一个 `fontFamily`
- [ ] 有 `fontSize` 但没有配套的 `letterSpacing` / `lineHeight`(即绕过了 `textStyle()`)
- [ ] 字重只有 400 和 700 两档
- [ ] 主要语义层级超过 3 个(微型元数据不计)
- [ ] 单字重字体上写了 `fontWeight`(伪粗体)
- [ ] 用 `scaleX` 拉窄/拉宽文字
- [ ] 用颜色区分主次文字(而不是字号/字重/明度)
- [ ] 标题加了描边、投影、渐变填充

## 7. Verification — 五套 kit 的实际渲染核对

样张:`templates/remotion-base/review/type-kits-60.png`(`npx remotion still TypeSpecimen --frame=60`)。
改了 `src/lib/fonts.ts` 的 kit 定义或角色映射之后**必须重渲并重新看图**,再回来更新本节结论。

**2026-08-01 首次核对(实施 visual-first 双引擎 Plan 1 时,主 agent 逐帧看图确认):**

- **所有中文字形正常渲染。** 五套 kit × 三行样例(含全角逗号「，」)全部出字,无豆腐块、无缺笔。
- **impact / editorial / human 的中文轮廓是三种骨架,不是三种字重。** impact 中宫收紧、笔画方硬带斜切,横向明显最窄;editorial 有横细竖粗和三角衬脚,拉丁行同步变成 Instrument Serif 的老式衬线数字;human 最轻最疏、同字号下占宽最大。三行并排时差异是压倒性的,不需要凑近看。
- **modern 与 tech-data 靠拉丁 / 数据角色区分。** 两者 display 同为 `'Archivo', 'Noto Sans SC'`,中文行本就一致(见 `TYPOGRAPHY_KITS`);差异出在 data 行:tech-data 是 JetBrains Mono,字距撑开、数字等宽,与 modern 的 Archivo 一眼可分。**这不是回退,是 kit 定义。**
- **没有任何一行的 display 塌回自己的 body。**

### 判断 human 有没有回退的方法(下次照做)

human 的 display 链是 `LXGW WenKai → Noto Serif SC → serif`。霞鹜文楷的楷体特征在小字号下并不张扬,容易让人怀疑"是不是没加载上"。不要靠肉眼分辨笔锋,用链条卡:**一旦 LXGW 没加载,画面必然是衬线**(链上后两位都是衬线)。所以只要 human 行明确不是衬线,渲的就一定是霞鹜文楷。这条逻辑比"看着像楷体"可靠得多。

### 已知短板(留给 A/B 迭代的单变量改进点)

**五套 kit 的中文骨架已经拉开,拉丁与数字侧没有。** impact / human / modern 三套的拉丁行都落在 Archivo / Inter 这类中性无衬线上,并排几乎无法区分。字体个性占视觉评分 15 分,这是现成的提分位置——但要改就单独改一轮并跑完整六类基准,不要和别的子系统一起动。
