# 配色方法论

定任何画面的颜色之前读这份。默认值在 `design-principles.md` §5,这里是**怎么做到**。
代码实现在 `templates/remotion-base/src/lib/color.ts`,样张 `npx remotion still TypeSpecimen --frame=60`。

**颜色在合同里声明一次。** 一个项目的调色在 `visual-contract.json` 的 `palette` 字段里定死
(`mode` / `dominant` / `support[]` / `accent[]` / `surfaces[]`),镜头组件只消费 token,不现场发明。
这一条替代了旧的"不许手写 hex":问题从来不是 hex 这种写法,而是**分散声明**——同一支片子里各镜各调各的,
明度不可控、色相会漂。合同里的值可以来自 `scenePalette()`、品牌规范、或从主视觉图吸的色,写进合同、跑过
`node tools/validate-contract.mjs` 就是合法的。

## 0. 先诊断:"配色看着 low"是哪三件事

1. **没有明度结构。** 整屏一个颜色、一个明度——所有元素同样深浅,读起来像一张贴纸而不是一个空间。**配色的骨架是明度阶梯,不是色相。**
2. **强调色的面积失控。** 太少(<10%)画面读起来没有能量,太多(>35%)它就不再强调任何东西,只剩下"这画面很红/很蓝"。
3. **分散声明。** 各镜各调各的,两个"看着一样深"的颜色实际差十几个感知明度点,拼在一起就是那种说不出哪儿不对的廉价感。

对应下面 §2 的三条构造律。

## 1. 色相从题材来

先定**一个主色相**(合同的 `palette.dominant`),需要时再加**最多两个辅助色相**(`palette.support`),来源按优先级:

1. 用户/品牌给定的色 → 直接换算成 hue 用
2. 题材固有的色(金融=冷蓝/绿红、纸媒=暖橙、医疗=青、能源=琥珀)
3. 素材本身的取色(有主视觉图时,从图里吸色,别拿通用色盖上去)

拿不准就用冷蓝 250°——它是本项目的默认值,**但默认值不是设计**:方案阶段要说出"为什么是这个色相"。

常用色相角:红 25 / 橙 55 / 黄 85 / 绿 145 / 青 195 / 蓝 250 / 紫 300 / 品红 350。

## 2. 三条构造律

### ① 中性色要染色,永不用纯灰/纯黑/纯白

底色、卡片、分隔线、次级文字都带 **4–10 点彩度**、色相跟着强调色走。这样画面读起来像"一整块被光照过的空间",而不是"灰底上贴了个色块"。

`#000000` 和 `#ffffff` 在视频里尤其糟:纯黑在暗部压缩后出块,纯白在手机屏上刺眼。用 `L 0.17` 和 `L 0.98` 代替。

### ② 明度阶梯在 OKLCH 里等差

OKLCH 的 `L` 是**感知明度**:L 相同 = 看着一样深,不论什么色相。HSL 做不到这件事(同 50% 亮度的黄和蓝差着两档)。所以阶梯在 OKLCH 里排,拉出来的层级永远够用,不会出现"两层看着一样深"。

一套深色场景的明度骨架(`scenePalette` 内置):

```
bg 0.17 → surface 0.22 → raised 0.27 → line 0.33 → muted 0.60 → second 0.78 → ink 0.97
```

**层与层之间至少 0.04 L**,否则观众读不出层级;相邻两层超过 0.15 L 会读成"两个不相干的区域"。

### ③ 一个主色相 + 最多两个辅助色相

主色定调,辅助色只做次级锚点(次要标记、状态、第二个视线落点),**辅助色不许和主色抢面积**。
剩下的对比全部用明度做:需要区分更多东西时,用明度分层、用位置分组、用形状区分,不是继续加色相。

(旧规则是"一个画面只能有一个强调色相"。放宽到两个辅助色,是因为单色相在多层空间的画面里
撑不出前后关系;但**四个以上色相同屏仍然是失控**,不是丰富。)

另有一处独立例外:分类系列色(图表里区分 2–4 个对象),那是**功能色**,不占色相名额,规则见 §5。

### 三条实战推论(都是渲帧才发现的)

**① 降低彩度 ≠ 变中性。** "把品牌色做成三档明度"听起来像在做层次,渲出来还是整屏一个色相。
主体(占大面积的那些元素)必须是**真中性**——彩度 ≤0.035;品牌色才配叫强调色。
判断法:眯眼看关键帧,如果整张图是一片同色,那就是没做层次。

**② 浅色画面需要一个深色锚点。** 浅色底上如果最深的东西只是文字,整张图会发飘。
让一部分主体做成"反白文字的深色块"(`L 0.32–0.42` 的中性),画面立刻有骨架,
强调色也才立得起来——强调色是靠周围的安静衬出来的,不是靠自己够艳。

**③ 浅色底上"越来越浅"只有一格余量。** 想用三档明度区分三类东西时,浅色模式下
最浅那档很容易撞到底色(实测 `L 0.978` 的填充对 `L 0.98` 的底色只有 **1.01** 对比度,
等于不存在)。层级要走**明度 + 形态**双重梯度:实心 / 描边 / 软填,形态承担主要区分。

## 3. 用法:`scenePalette()`

```ts
import {scenePalette} from './lib/theme';

const P = scenePalette(250, 'dark');           // 冷蓝、深色
const P = scenePalette(25, 'light', {          // 暖红、浅色、中性偏冷
  neutralHue: 250,
  accentChroma: 0.13,
});
```

拿到 11 个令牌:`bg` `surface` `surfaceRaised` `line` `ink` `inkSecondary` `inkMuted` `accent` `accentSoft` `onAccent`。

**新项目应该自己调一次,不要照抄模板默认值**(那是 demo 用的)。参数含义:

- `accentChroma` 默认 0.16。深色画面 0.14–0.19 最稳;**>0.22 在视频压缩后会糊成一坨色块**(H.264 的色度采样是 4:2:0,高彩度边缘最先烂)。
- `neutralChroma` 默认 0.008。>0.02 会让"灰"读成"有颜色",除非风格卡明确要那种调子。
- `neutralHue` 默认跟随强调色。想要"暖内容 + 冷环境"这种张力时才单独给。

其他工具:`ramp(hue, steps)` 造同色相明度阶梯(同类东西的强弱分档,**不是分类色**);`shift()` 调明度做压暗/提亮(比 `opacity` 干净,不会透出底下的东西);`alpha()` 只在必须半透明时用(叠在未知底片上的 chip);`contrast(a, b)` 校验对比度。

## 4. 面积律:10%–35% 区间

- **强调面积默认落在 10%–35%**,具体区间由 profile 定:
  `editorial-luxe` 10%–20% / `data-cinematic` 12%–25% / `visual-max` 20%–35% / `brand-energy` 25%–35%。
- 下界 10%:低于它画面读起来没有能量,这是旧的"≤10% 上限"把画面做素的直接后果。
- 上界 35%:超过它强调色就变成底色,不再强调任何东西。**上界仍然存在,只是抬高了。**
- 大面积需要"有颜色"但不想抢焦点时,用 `accentSoft`(同色相、低彩度、贴近底色),**不用于文字**。
- 参考分配:中性底色 45%–60% / 中性内容层 25%–35% / 强调 10%–35%。
- 品牌类画面里整块底色就是强调色的情况是允许的(`brand-energy`),此时靠明度和材质拉层级,不靠中性面积。

## 5. 功能色 vs 美学配色(别混用)

两套颜色在本项目里是**分开的**,混用是常见错误:

| | 美学配色 | 功能色 |
|---|---|---|
| 来源 | `scenePalette(hue, mode)` | `theme.seriesDark/seriesLight`、`theme.good` |
| 用途 | 画面调性:底色、层次、强调 | 图表分类系列、涨跌/状态 |
| 依据 | 色相来自题材,明度成阶梯 | 已通过色觉无障碍验证(CVD ΔE≥8) |
| 规则 | 一个主色相 + 最多两个辅助色相 | 固定顺序、不循环、不按排名重排 |

有图表的画面:**底色/文字/网格取美学配色,系列色取功能色**。系列色不当文字色用,状态色不当系列色用,反之亦然。

## 6. 对比度硬线

`contrast(fg, bg)` 校验(WCAG 比值):

- 正文、标签(< h2 尺寸):**≥ 4.5**
- 大字(≥ h2 尺寸):**≥ 3.0**
- 分隔线、装饰性图形:无硬线,但 < 1.3 等于没画

`scenePalette` 生成的令牌实测对 `bg` 的对比度(hue 250):

| | ink | inkSecondary | inkMuted | accent |
|---|---|---|---|---|
| dark | 17.5 | 9.5 | **4.8** | 7.7 |
| light | 16.4 | 7.4 | **4.6** | 4.6 |

`inkMuted` 是**贴着 4.5 线**设计的,**再往下压就不合格了**——想要"更弱的字"应该缩字号,不是继续降明度。
(浅色的 `inkMuted` 曾按 L 0.62 取,实测只有 3.44、不过线,已改成 0.55。这类问题肉眼看不出来,定完色跑一次 `contrast()`。)

### ⚠️ HyperFrames 镜头:CSS 里不要落 `oklch()` 字面量

**`npx hyperframes check` 的对比度审计遇到 `oklch()` 会把全部文字检查静默跳过,并且仍然打印「Check passed」。**

2026-08-01 实测(同一个文件、同一套配色,只换令牌的书写形式):

| `:root` 令牌写法 | check 的对比度结果 | 整体结论 |
|---|---|---|
| `--ink-0: #040b17;` | `40/40 text checks pass WCAG AA` | Check passed |
| `--ink-0: oklch(0.15 0.028 255);` | **`0/0 text checks pass WCAG AA`** | Check passed |

`0/0` 不是"全过",是"一条都没查"。而它报的仍然是通过,所以**这个门禁是静默失效的,不会有任何提示**。

**做法**:OKLCH 仍然是**定色的思维工具**(明度阶梯必须在 OKLCH 里等差,见 §2②),但落到 HyperFrames 的 CSS 里要写成 sRGB hex,把 OKLCH 原值留在同行注释里,例如:

```css
--ink-0: #040b17; /* oklch(0.15 0.028 255) */
```

这样既保留了明度阶梯的可读可改,又不会把对比度硬门槛关掉。Remotion 侧不受影响(`scenePalette()` 本来就输出 sRGB)。

- **别用彩虹渐变映射数值。** 渐变仅作装饰性背景,不承载数据含义。(这条仍是硬规则,防的是读错数。)
- **辉光 / Bloom / 光斑现在是允许的**(旧的全面禁令已取消),但有三条附加条件:
  ① 主文字对比度仍达标(正文 ≥4.5,大字 ≥3.0);② 不打在数据元素上——发光折线压缩后会糊,而且看不出精确值;
  ③ 强度写进合同的 `material` / `background`,不是每镜临时加。要层次仍然优先调明度阶梯,光是补充不是替代。
- **压缩友好**:高彩度 + 高频细节(细线、小字、噪点)在 H.264 下最先烂。大面积高彩度色块也会出带状。彩度上限 0.19 是实测线。
- **平台色偏**:手机端普遍偏冷偏艳。浅色底调到 `L 0.98` 而不是纯白,能避掉一部分刺眼。
- **一支片子里色相不许漂移。** 多镜项目所有镜头消费同一份合同的 `palette` token,不许每镜各调各的。这是合同存在的主要理由之一。

## 8. 反模板自查

出现即返工:

- [ ] 镜头代码里出现合同 `palette` token 之外的颜色(功能色令牌除外)
- [ ] 用了 `#000` `#fff` 或纯灰 `#888`
- [ ] 一个画面里出现 4 个以上色相(主 1 + 辅助 2 是上限,功能色不计)
- [ ] 强调面积 <10%(画面没能量)或 >35%(强调变底色)
- [ ] 明度阶梯里有两层差 < 0.04 L(层级读不出来)
- [ ] 图表元素上的某处上色说不出在编码什么信息(数据标度 / 分类区分 / 焦点强调,三者之一)
- [ ] 辉光/Bloom 把正文对比度压到 4.5 以下,或糊到数据元素上
- [ ] 多镜项目里各镜自己调色,没有共用合同 token
- [ ] 落进 `visual-language.md` §6 的三种 AI 默认审美:米白+陶土色、近黑+酸性绿、报纸式发丝线
