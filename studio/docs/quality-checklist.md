# 质量检查单

`/motion-review` 和交付前按此执行。**执行方式是看画面,不是看代码**:

```bash
# 渲染每个镜头的中点帧 + 首尾帧。--scale=0.4 是自查帧的默认值,不是交付物
npx remotion still <CompId> --frame=<N> --scale=0.4 review/frame-<N>.png

# 先让数字说话,再用眼睛看
node tools/frame-audit.mjs review/frame-*.png --contract projects/<name>/visual-contract.json
```

**顺序是先数字、后眼睛,两步都不许省。**

- `frame-audit.mjs` 能算的别用眼睛判:墨量、明度层数、构图偏压、安全区边缘硬边、
  离板颜色、强调色面积。数字报了就以数字为准,不许用「看着还行」推翻。
- 剩下的用 Read 逐张看,对照下表。眼睛负责的是数字判不了的事:焦点成不成立、
  和选中的 `sf-N.png` 像不像、有没有让人记住的东西。**没看过画面就交付,是本项目定义的失败。**
- **自查帧一律 `--scale=0.4`**(1080×1920 → 432×768)。下面「缩略图测试」这条要求的是
  320px 宽仍可读,432px 本来就在那条线之上;而全分辨率读一张图约 1844 tokens,0.4 约 442。
  `frame-audit.mjs` 内部统一缩到 270px 宽再量,**降采样不改变任何一项数字结论**。
  **只有三种情况读全分辨率**:选中的 `sf-N.png`、英雄帧、以及数字或眼睛已经起疑的那一帧
  (字形回退、伪粗体、字距这类判断需要全分辨率)。

任何"硬性"项不过 → 修复后重渲重查,循环到全过；时限或修复轮数耗尽不授权自动降质，无法继续交草稿、缺口与下一步，不称完成。

- [ ] 理想对象、关系、起始/变化/结束与口播锚点落实；模板选择比较六项表达条件及定制收益，文字槽位适配不单独构成命中。
- [ ] 实际连续播放全部交付镜，检查语义推进、揭示时点、停留、可读性与相邻衔接；review.md 记录文件与时间段依据，不能以分数/verified/技术 PASS 代替。
- [ ] overlay 查看真实口播合成，检查脸、手势和字幕干扰及 Alpha；只有抽帧、未播放或缺合成时明确未验收。
- [ ] verified 可免无变化模板的重复实现和数值审计，本次内容/节奏/合成检查仍执行；custom/draft 全量门禁保留。
- [ ] package/keyframes-only 只审真实关键帧及状态变化设计，动态尚未验收，不提前渲 MP4。

**验收基准是用户选中的那张 `styleframes/sf-N.png`,不是本文件里的任何一条旧规则。**
本文件与 `visual-contract.json` 冲突时,以合同为准(优先级链见 `docs/visual-first.md`)。

## Styleframe 保真度(硬性,新增)

选中的 Styleframe 是视觉验收基准。逐镜关键帧与它对照,以下五项对不上就**改画面**,不许引用旧规则自我辩护:

- [ ] **密度**:检查批准的留白、层级和合成后可读性，不以占屏率或首尾墨量判失败
- [ ] **层次**:真实渲染中主次关系清晰，不设材质种类或默认空间层数额度
- [ ] **材质**:`sf-N.png` 里出现的材质信号(受光渐变 / 厚度 / 描边 / 玻璃金属 / 颗粒 / 景深)在成片里也在
- [ ] **字体**:成片实际中文字形与 `sf-N.png` 一致;**中文回退到默认字体一律不通过**
- [ ] **色彩关系**:主色 / 辅助色 / 强调面积与合同 `palette` 一致,跨镜不漂移
- [ ] 每镜至少检查首、中、尾三帧;英雄帧主观评分 ≥8/10

## 结构化视觉评审(硬性,新增)

散文 review.md 继续写,但**门禁读的是 JSON**——「整体不错,可以交付」拦不住任何东西。

```bash
node tools/validate-review.mjs projects/<name>/review.json   # 不过 → exit 1
```

- [ ] `node tools/validate-review.mjs` 通过。四条门禁**彼此独立**,任一不过即不通过:
      **总分 ≥80** / **任一维度 ≥6** / **英雄帧 ≥8** / **`technical` 五项全 `true`(缺项 ≠ 通过)**
- [ ] 七个维度都打了分:`composition` 20 / `typography` 15 / `density` 15 / `motion` 15 /
      `distinctiveness` 15 / `clarity` 10 / `continuity` 10(格式与打分标定见 `docs/visual-scorecard.md`)
- [ ] 评审是**看实际像素**给的:每个分数指得到某一帧的某个位置;`mismatches` ≥3 条具体不符(带帧文件名+位置)
- [ ] `repairs` ≤5 条且按分数影响降序;逐镜评审角色合同见 `docs/subagents/visual-reviewer.md`
- [ ] 多镜项目有 `continuity.json`,六项边界检查全过;失败边界的修复**只涉及该边界两侧那两镜**
      (`docs/subagents/continuity-reviewer.md`)

## 合同有效性(硬性,新增)

```bash
node tools/validate-contract.mjs projects/<name>/visual-contract.json
```

- [ ] `node tools/validate-contract.mjs` 通过(缺字体套装、镜头引擎、画布或连续锚点时**不得派发 shot worker**)
- [ ] 三份候选合同 `styleframes/sf-{1,2,3}.contract.json` 也各自通过校验
- [ ] `shots[]` 覆盖全部镜头,每项有 `engine` / `objective` / `startAnchor` / `endAnchor`
- [ ] 相邻镜头的 `endAnchor` 与下一镜的 `startAnchor` 对得上(`continuity.json`)
- [ ] `facts.mode` 与实际内容相符:用了虚构数字就必须是 `illustrative`,不得让演示数字伪装成真实结论
- [ ] **`exact` 不等于"把审计信息都上屏"**:它只约束数据不被篡改/乱算/用虚构中间值。
      **不要求**显示样本量(`n=5`)、数据来源、完整量纲说明或轴起点注释 —— 口播插片里这些会挤掉结论。
      但两条底线必须守:**单位至少完整出现一次**;**Y 轴非零起必须有可感知的断轴符号,或改用零基线**。
      截断轴而不标记属于误导,比脚注冗余严重得多。
- [ ] 镜头代码没有绕过合同自行声明颜色 / 字体 / 密度

## 内容(硬性)

- [ ] 观众在规定时长内能理解核心结论(自测:只看画面 1 遍,说得出结论吗)
- [ ] 每个动画都有信息理由,删掉它会损失理解
- [ ] 信息层级清晰:**一个主焦点 + 最多两个次级锚点**(合同 `focus`)
- [ ] 文字停留时间 ≥ 阅读所需时间(1 秒 / 10 字)
- [ ] 事实正确:已声明为事实的数据和文案与原始来源逐项对得上

## 设计(硬性)

- [ ] 字体、颜色、间距全片统一,均来自合同声明的 token
- [ ] **字体**:无 `system-ui`/裸 `sans-serif`;合同写死 `typography.kit`;`textStyle()` 同时收 kit 和 style role;两个主角色(小范围 mono/decorative 豁免);无伪粗体、无 `scaleX` 拉字(`docs/typography.md` §6)
- [ ] **配色**:镜头代码只消费合同 `palette` token;一个主色 + 最多两个辅助色;**强调面积 10%–35%**;明度阶梯层间 ≥0.04 L;无 `#000`/`#fff`(`docs/color.md` §8)
- [ ] 同一画面**三个主要语义层级**(微型元数据:眉题/图注/单位/时间码/署名,不计入)
- [ ] 缓动全部使用标准曲线,无线性位移;弹簧按表达需要选择，检查是否干扰焦点
- [ ] **图表元素上的颜色承载意义**(数据标度 / 分类区分 / 主体强调);图表之外允许用颜色表达品牌、情绪、能量、材质、空间
- [ ] 辉光 / Bloom / 光斑**允许**,但没有把正文对比度压到 4.5 以下、大字压到 3.0 以下,也没糊在数据元素上
- [ ] 动画结束后文字有足够的阅读停留;**背景允许保持低强度运动**(不再要求全静止)
- [ ] 无 `design-principles.md` §8 剩余清单里的违规项
- [ ] 转场有空间/逻辑关联
- [ ] 缩略图测试:关键帧缩到 320px 宽仍可读,且能认出主焦点
- [ ] 竖版:关键信息在安全区内

## 密度与材质(下限,硬性)

> **为什么单开一节**:上面所有条目、`validate-output.sh`、`design-principles.md` §8 克制清单——
> **全都是「不许出现 X」,没有一条是「必须达到 Y」**。所以一个几乎全空的画面能 100% 通过全部检查。
> 2026-07-31 的 auto-motion 同题对比就是这么翻的车:那一版全部 PASS,
> 末帧墨量只有 **5.1%**(94.9% 的像素是空的),首帧墨量 **0.6%**;对照组末帧 47.0%。
> 这两条命令就是补上「下限」的:

```bash
tools/check-density.sh <文件> --contract projects/<name>/visual-contract.json   # 帧密度:阈值按合同/profile 取
node tools/lint-shot.mjs <shots 目录> --contract projects/<name>/visual-contract.json  # 源码:该用而没用
node tools/frame-audit.mjs <关键帧...> --contract projects/<name>/visual-contract.json # 单帧:上面两条的逐帧版
```

- [ ] `node tools/frame-audit.mjs --contract` 与 `tools/check-density.sh --contract` 成功解码并记录指标；墨量与明度层数不设下限，入场、退场和叠层需真实播放及合成检查。
- [ ] `node tools/lint-shot.mjs --contract` 无技术 error。字体、配色令牌、确定性和本地资源要求保留；不计最低材质种类或必用弹簧。
- [ ] 语义节拍按口播关系和理解负荷检查，不设固定数量上限。
- [ ] **先立一个强主视觉,再谈补充。** 顺序是「渲帧 → 看主焦点立没立住 → 立住了再问缺什么」,
      不是「看哪里空就补什么」。
- [ ] **每个新增元素必须承担新的信息、新的空间层次或新的情绪**——三者都不占的,是填充物,不要加。
      **重复已经在画面上的信息不算新增信息**:同一个数值、同一个词、同一组标签在同一帧里出现第二次,
      涨的是墨量不是密度。
- [ ] **英雄帧定下来之后必须做一次删除检查**:逐个问「拿掉它,观众少懂了什么?」——
      答不出来就拿掉。这一步不是可选的收尾,是硬性项。

> **为什么把原来那条删了。** 这里原本写的是「加法在减法之前:至少三轮渲帧补东西之后才允许做减法检查」。
> 2026-08-03 的 round-01 盲评证明它有害:案例 03 把五个数值印了两遍、差值印了三遍、
> 又加上 `Y 轴自 15 起 / 单位小时 / n=5` 的学术脚注,「三轮加法」全部做满,
> 结果是观众更难一眼读到结论,该案例排名第 3(输给改造前的自己和竞品)。
> 用户原话:「信息过于冗余……本项目是口播场景,表现力为主完全没必要这么严谨。」
> 这条规则诞生于 2026-07-31 的空画面事故,方向是对的,但它把「不要空」执行成了「不停加」。
> **防空屏交给 `check-density.sh` 的下限就够了,不需要再用一条流程规则去催加法。**
- [ ] 低于阈值时**可以**是正当例外(纯文字金句镜),但必须在 `review.md` 写明理由,
      而且理由必须来自**选中的 Styleframe 就是这样**。
      注意「`editorial-luxe` 的版面留白」已经**不再是例外理由**——它现在直接体现在阈值里(13.3/6.7)。
      换 profile 是改合同的动作,不是评审时口头豁免的动作;
      profile 没换却说「这个风格就该素」,等于既不改画面也不改标准。
      **"时间不够所以做简单点"不是正当例外**——极简是需要被选中的视觉方向,不是超时降级路径。
      时间不够按 `docs/visual-first.md` 的预算检查点记录草稿与缺口；实现调整须保留批准表达，不自动降低复杂度、密度或质量。

## 技术(硬性)

前四项由脚本客观校验,**跑它,不要肉眼核对**:

```bash
tools/validate-output.sh <文件> --size 1080x1920 --fps 30 --duration <brief 时长> --audio none
```

- [ ] `tools/validate-output.sh` 全过(文件非空 / 尺寸 / **宽高均为偶数** / 帧率 / 时长 / 音轨)
- [ ] 渲染无报错(Remotion 镜跑 `npx remotion render`,HyperFrames 镜跑对应 CLI)
- [ ] **多引擎输出已规范化**:所有镜同为合同指定的偶数宽高、30fps、H.264 High、`yuv420p`、无音轨(除非合同声明)、timebase/SAR/色彩标记一致
- [ ] 无素材缺失/路径错误(渲染日志无 404/ENOENT)
- [ ] **确定性**:代码里没有 `Date.now()`、未播种 `Math.random()`、渲染期网络请求——一切从 `useCurrentFrame()` 推导。有随机感需求时用固定种子的伪随机。
- [ ] **选中素材已本地缓存**:`assets/` 里有实际文件,渲染引的是本地路径,没有远程 URL
- [ ] 文字无溢出、无互相遮挡(逐帧图上看)
- [ ] 多镜项目:各镜时长之和与合同总时长一致(逐镜相接、无缝无重叠、误差 ≤0.1s);SRT 项目还要覆盖完整字幕跨度

> 宽或高为奇数会让 libx264/yuv420p 编码失败或画面变形,而报错信息通常指不到这里——所以把它做成自动检查项。

## 软性(记录进 review.md,不阻塞)

- 节奏是否有拖沓段(>1.5 秒无视觉变化且非阅读时刻)
- 是否有模板感、廉价感(说不出为什么但看着俗 → 记下来,复盘时归因)
- 音效/音乐时机(若有)
- **画面内署名**:用到真实地图底图、第三方影像、要求署名的开源素材时,建议把署名烧进画面(角落小字,与素材同时在场)
- 记录活跃时间与预算变化；超出60分钟参考预算只提示成本，不自动判失败
