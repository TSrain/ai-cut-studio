# 视觉语言:反模板审美方法论

提炼自官方 `frontend-design` skill(claude-plugins-official),已翻译并适配为**动画/动效**语境。与 `design-principles.md`(硬规则)互补:那边管"不能错",这边管"要有味道"。每次进入方案设计(阶段 A)和实现前读一遍。

## 1. 从题材本身长出设计

方案不确定视觉方向时,先钉死:**具体题材是什么、观众是谁、这支片子的唯一任务是什么**,并明说选择。独特的视觉选择来自题材自己的世界——它的材料、器物、仪式、行话。(例:婚礼片的"表盘→婚戒"来自"吉时"与"戒指"这两个题材固有物,而不是通用的粒子模板。)用户记忆和过往项目偏好(memory/taste.md)是线索,优先采纳。

## 2. 签名元素(Signature)

每支片子必须有**一个**让人记住的独特元素,它本身要能体现 brief 的核心。把大胆花在这一处,其余一切保持安静、克制、服务于它。**不冒任何险本身就是风险**——三个方案里至少一个要有真正的 aesthetic risk 并能说出理由。

**一个可直接套用的具名手法:实物几何即图表(asset fusion)。**不要"放一张图 + 旁边配一个图表",而是让题材里那个真实物体的几何形态**本身成为**图表:吸管的长度成为量表刻度、杯中液面成为饼图、楼梯的踏面成为柱状图、包装盒的展开成为分解视图。做法:

1. 判断数据类型(时间序列 / 数量 / 占比 / 空间)。
2. 读这个物体的**几何可供性**——线性 → 时间轴或量表;体积/液面 → 占比;高度差 → 柱状;容器 → 分解视图。
3. 用 `docs/locate-protocol.md` 拿到锚点坐标(中心、范围、可放置区、需避让区)。**不许目测坐标**,目测的圈注会落在目标外面。
4. 配色从素材本身取色,不要用通用的白/黑/品牌色盖上去。
5. 两层结构:素材铺底(全出血),数据图形叠在其几何之上,用连接线/引线把数据和物体实体地绑在一起;**素材全程保持可见**。

这是 §1"从题材本身长出设计"最具操作性的一种形态,也是最不容易做出模板感的一种。

## 3. 排版承载个性

字体处理是画面性格的主要来源:刻意设定层级、字重、字距(letterSpacing)、留白,让文字排布本身成为记忆点,而不是信息的中性容器。同一画面 ≤3 级字号的硬规则不变,个性来自比例与节奏,不是来自更多字体。

**具体怎么做见 `docs/typography.md`**——字体角色制(最多两个角色)、`textStyle()` 的字号/字重/字距/行高配套阶梯、中西文混排五条。这里只强调一件事:**默认字体没有性格**,而没有性格在成片里直接读作廉价,所以 `system-ui` 是硬性禁止项。

## 4. 结构即信息

编号、分隔线、眉题、刻度等结构装置必须**编码内容里真实存在的结构**(真实的顺序、真实的时刻、真实的分组),不为装饰而放。例:钟面刻度之所以成立,是因为内容就是时间线;若内容无顺序,就不该用 01/02/03。

## 5. 动效要"编排",不要"散落"

一个精心编排的高潮时刻(orchestrated moment)胜过满屏零散小动画。想清楚动效为题材服务的位置:入场序列、揭示、强调、收束。**有时更少就是更多——过量动画正是"AI 生成感"的来源之一。**动画结束必须有静止读取时刻(与 design-principles §8 一致)。

## 6. 警惕三种"AI 默认审美"

当前 AI 生成设计高度聚集在三种样子,除非 brief 明确要求,否则不要把自由度花在它们身上:

1. 米白底(≈#F4F1EA)+ 高对比衬线大标题 + 陶土色强调
2. 近黑底 + 单一酸性绿/朱红强调色
3. 报纸式:发丝线、零圆角、密排多栏

判断法:换一个类似的 brief 推演一遍,如果会得出同样的设计,说明那是默认而不是选择——改掉,并说明改了什么、为什么。

## 7. 两遍法:先方案后执行

动手写代码前先出**紧凑的令牌方案**,四项各一行写进 `proposals.md` 或 `storyboard.md`:

1. **配色**:一句 `scenePalette(hue, mode, opts)` 调用 + 为什么是这个色相(来自题材/品牌/素材取色,见 `docs/color.md` §1)
2. **字体角色**:展示用哪个、正文用哪个(最多两个,见 `docs/typography.md` §1),以及展示体为什么配这支片子的调性
3. **布局概念**:一句话 + 必要时 ASCII 草图
4. **签名元素**:一个,见 §2

对照 brief 自评一遍"哪部分像通用默认",修掉,然后严格按修订后的方案实现,每个颜色与字号决定都从方案推导。

## 8. 边做边照镜子

实现中持续自我批评:**渲帧看画面**(一图胜千 token,本项目的核心质检手段)。收尾前做"香奈儿检查":出门前照镜子,摘掉一件配饰——找出画面里最可有可无的一个装饰,删掉它。把试过的方向记进 review.md,避免下轮重复。

**次序不能反。** 香奈儿检查的前提是画面**已经足够丰富**——她说的是"穿戴完再摘一件",不是"少穿一件出门"。
所以流程是:渲帧 → 数字门禁(`check-density.sh` / `frame-audit.mjs`)与眼睛都过就**停**;
不够丰富才补,缺什么补什么(通常一两轮),密度站住了最后才摘一件。
在画面本来就素的时候做减法,是 2026-07-31 那次做出空画面的直接原因之一;
但反过来,**固定的「至少三轮加法」也已废除**——2026-08-03 盲评证明它催生冗余堆料
(数值印两遍、差值印三遍),排名反而落后。防空屏交给密度下限,不靠多跑轮数。
同理:**画面迭代要排在过程文档之前**。brief/storyboard 先写骨架够用,review.md 收尾时补全,
省下的预算全投进渲帧循环——那次真正花在画面上的迭代只有对照组的五分之一。

## 9. 文案是设计材料

画面里的每个字都为"让人更快理解"存在,不是装饰。从观众那一侧命名事物(说人话,不说系统话);主动语态;具体永远胜过俏皮;同一事物全片同一叫法;每个元素只做一件事——标签就是标签,示例就是示例。空状态/收尾画面是引导行动的机会,不是抒情位。

## 10. 质量地板(不声张地做到)

动画语境下的对应项:安全区合规、缩略图测试可读、色觉无障碍配色(theme 已内置)、片尾静止、导出规格与 brief 一致。这些不是卖点,是地板。
