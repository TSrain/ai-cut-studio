# 口播镜头风格 v2：可见推拉，全景为主

状态：2026-09-10 用户已批准，取代0904小幅慢推及每分钟2次默认。旧版仅见 [历史记录](aroll-camera-style-0904-history.md)，不得反向覆盖新默认。数值均为本账号试片起点，不是行业标准。

## 资料及适用边界

- StudioBinder：Zoom Shot，https://www.studiobinder.com/camera-shots/camera-movements/zoom-shot/ 。推近集中注意、强化主体与情绪，拉远扩大观看范围；速度改变表达效果。电影语言可借鉴其目的，不把戏剧化范例直接套进口播。
- Descript：How to Make Good Video Content From Home，https://www.descript.com/blog/article/create-professional-video-content-from-home 。口播剪接可用相关 B-roll 或人物裁切变化处理，4K 有更多裁切余量。数字缩放不改变真实机位透视，也不能保证断点消失。
- Adobe：Morph Cut overview，https://helpx.adobe.com/premiere/desktop/add-video-effects/apply-video-transitions/morph-cut-overview.html 。Morph Cut 面向访谈删减造成的跳切处理；不作为日常推拉效果或所有断点的通用修复。

上述资料不支持每分钟固定次数、统一倍率或全景占比标准。以下数值是结合用户偏好的试片起点，须用真实素材验证，不包装成行业标准。

## 主原则

1. 基础构图 A=1.00，指原片最完整的可用构图，不要求全身入画，也不能从近拍视频虚构更广视野。
2. 次数由内容决定：删除滚动60秒最多2次的阻断。不规定最低次数、不按固定秒数切换。
3. 每次变化标明：触发原话、叙事目的、运动开始、到位、保持结束、回程、构图安全。近景不能无理由一直保持到片尾。
4. 普通解释、背景交代、并列步骤、操作说明默认 A。强调是短时离开 A，意思完成后回归 A。
5. 基础全景建议占人物口播可见时间75%–85%；推进+近景停留+拉回合计约15%–25%。这是初始审美目标，不是为了凑比例删除有效表达的硬门槛。低于75%提示复核，半数及以下与“大部分全景”的偏好冲突，须返工或有明确本期例外。
6. 同时报告整片 A/近景/运动/B-roll 遮挡时间，分别列明分母。B-roll 不冒充人物镜头变化，不能用其遮挡时长抵消长时间近景问题。独立镜头视频也报告完整轨道构图占比。

## 动作选择

|场景|首选动作|回程判断|
|---|---|---|
|关键答案、纠正常见误解、短而明确的判断|快推|重点说完，开始普通解释时回A|
|完整因果逐渐展开、个人体会加深、关键结论形成|慢推|到结论处停住，意思完成后回A|
|自嘲、反高潮、否定夸张承诺、张力突然释放|快拉|到A即停，让反差落地|
|从个人感受回到整体解释、重点结束、恢复手势空间|慢拉或自然速度回程|回A后稳定讲述|
|进入章节|通常保持A；若此前近景且语义重启，可回A|不因章节标签而自动制造一组推拉|
|真实剪接断点、明确时间跳跃、极少数需要突断的反转|有理由的硬切，先考虑相关证据画面/另一机位|检查眼位、动作、音频连续性；没有需要可全片零硬切|
|界面、数据、操作、真实结果|优先证据画面|由B-roll流程处理，禁止用人物推拉冒充证据|

笑点若来自脸上的反应，保持或推近；若来自荒诞处境或自我降格，考虑快拉。不是遇到否定词必拉远。

## 可见性与试片参数

- 默认试片比较 A=1.00 与 B=1.10–1.15；特别强调可试 C=1.15–1.20。不要求每片三档，不要求大幅裁切。原片构图太近时减幅或取消该动作，记录原因，不能裁掉手势来达到数值。
- 快推/快拉：先试0.25–0.50秒，短加减速或linear，到位即停，不弹跳、不震动、不长拖尾。
- 慢推/慢拉：先试1.5–3秒，按完整短句可延长至约4秒。慢不等于微弱；正常速度下应看得出从A到B的构图变化。
- 近景停留：先试重点句剩余部分或约1–3秒，完整意思优先；强判断尚未结束可延长，但不要无理由占据后续普通解释。
- 推与拉无需同速：慢推接快拉用于反高潮；快推接较缓回程用于强调后的解释。
- 手机常见播放尺寸、正常速度、不显示运动标记、不靠前后截图切换，能辨认动作起止，才算可见性通过。若看不清，先检查时长和幅度的组合及人物自然移动干扰。
- 源为4K但交付仍为4K时，裁切放大仍会重采样；仅4K到1080才有更明确的像素余量，不承诺无损。保护头顶、眼位、肩部、关键手势，保留固定画布和亚像素防抖。

## 本期可试的叙事处理（非最终时间轴）

- “不是因为AI现在已经全能一键出片”：若没有B-roll主强调，可短快推，边界讲完回全景。
- “全部堆给AI”到“最后结果很尴尬”：可慢推建立期待，在“尴尬”处快拉；若同处已安排黑箱动画，则由动画承担主强调，人物保持A。
- “但最终……还是由我自己来决定”：可快推落在决定权，完整意思结束后回A。
- “第一步/第二步/第三步”：以全景、导航及真实录屏承担结构，不逐步循环推拉。
- “创作的辅助系统，而不是一个一键出片的工具”：可完整短句慢推，结论讲完回A，后续邀请与告别保持全景。

实际选点须听原声、看动作并对齐已批准的B-roll时段；以上不构成所有点都必须做的配额。


## 运行与审查合同

- `shot-plan.json` 保持 version=2；`slow` 是历史协议名，表示所有连续运动，0.25秒快推也使用 slow + linear/ramped，不增造不兼容的 fast 类型。
- 默认试片 A/B/C=1.00/1.12/1.18；实际可按构图减幅或只用两档。显式旧计划的 levels 保持原值，不静默放大历史产物。
- 每个近景段写清触发原话、开始、到位、保持结束、回程和构图依据；回程必须在真实 events 中体现。无回程的结尾近景单独说明理由。
- check 不再按滚动频率、连续运动10%差值或运动覆盖20%阻断。保留1.35倍率技术上界、至少0.2秒连续运动、真实原话与理由、有效锚点、无重叠、时长/音轨一致和防抖实现。
- check 报告完整镜头轨的基础全景、近景保持、运动占比。全景低于75%须复核；不超过50%须返工或记录用户明确的本期例外。不是技术通过就可交付，REVIEW REQUIRED 项必须在 review/REVIEW.md 逐项写处理结果，不能留空或以 PASS 替代。
- 全景占比高于85%不因此强加动作。资料/操作段优先证据，无法确认B-roll实际遮挡时只报告完整镜头轨，不伪造可见口播占比。
- 硬切和短时反复往返须说明特定目的；可全片零硬切。实际B-roll可见时段已知时，另算人物可见段占比及整片各类型时长，明示分母，不把插片混为人物运镜。
- 首次使用新默认先做20–30秒代表试片，真实查看正常速度、手机尺寸的快慢动作；通过后才扩展全片。不能凭参数、静态前后图或测试通过宣称观感达标。
- 复用固定画布、眼位锚点和亚像素 buildCameraFilter；不叠加横移、追脸、摇摆、弹跳；抽查头顶、肩部、关键手势及实际连续帧。
- 原片、原声、时长不变，输出新文件。交付独立镜头视频与透明字幕；字幕为屏幕层。工作台只调用，不拥有任何镜头生产规则。
