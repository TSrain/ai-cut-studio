# text-mask · 字形遮罩开场

> principle: atoms are sacred · slots are the only freedom · timing is frozen

```yaml
version: 1
name: 字形遮罩开场
role: 把品牌词/口号和产品画面压成同一个东西——字形当窗口,画面在笔画里流动;末段字形胀开,画面接管全屏
duration_seconds: [3.5, 6]
source: video-shotcraft 的 text-as-mask 移植(2026-08-26);配方卡 docs/catalog/recipes-external/opening/text-as-mask.md
colors: 全部来自皮肤;骨架流另在 OKLCH 里起一整套明度阶梯,**方向随 P.mode 翻转**(暗皮肤 页 L0.46 / 卡 L0.74 + 深字条;亮皮肤 页 L0.30 / 卡 L0.40 + 浅字条)——门里门外必须拉开明度才读得出"门里有世界",禁直接写 hex
typography: title=遮罩字,Archivo VF + 思源黑 VF 真 900 字重(不跟皮肤 kit,遮罩要的是最大墨量),460 起缩至 180;caption=label(40 缩至 26)
geometry: 画布 1080×1920;词带中心 (540,920);遮罩字最大宽 940;caption 顶边 1660
mask: 行内 <svg> 的 <mask><text>(**不是** CSS mask-image + data-URI,那条路拿不到 FontFace 字体);放大写在 mask 子树,内容层不做反向补偿
motion:
  - {phase: enter, seconds: 0.00, action: 第 0 帧即在场(字+门+内容);caption 0.25s 起上浮淡入 0.4s, easing: ENTER}
  - {phase: hold,  seconds: 0.55, action: 字与门建立,内容静止}
  - {phase: hold,  seconds: elastic, action: 字内漂移 3.0px/帧匀速(线性,刻意不加缓动),轴取 cover 后余量大的那根}
  - {phase: exit,  seconds: 1.00, action: "takeover=full:遮罩 S=7^endT 放大 + 描边 0→0.55em 吞字腔 + 内容归位 + 全屏层淡入接管", easing: "bezier(0.4,0,0.2,1)"}
  - {phase: exit,  seconds: 0.90, action: "takeover=hold(二选一):漂移减速停住,caption 留场", easing: outCubic}
  - {phase: hold,  seconds: 0.80, action: 末段真静止 24 帧(full 定格在全屏标准构图 / hold 定格在字内)}
slots:
  title: 当遮罩的那个词(必填,中文 2–4 字最稳)
  image: 字里透出的画面(**可省,preset 样例就省着**;裸文件名补 screens/,含 / 视为 public 完整相对路径。给图前先过「选图硬判据」三条)
  imgW / imgH: 源图真实像素(填了 image 才需要)
  caption: 底部小注,可省
variants:
  takeover: full(默认,末段接管全屏,当章节转场) | hold(全程留在字内,当独立开场卡)
spring_accents: 0
```

## 用法

```json
{"id": "shot-001", "preset": {"id": "text-mask", "version": 1},
 "presetProps": {"durationSeconds": 5, "variant": {"takeover": "full"},
   "slots": {"title": "出片", "image": "app-dashboard.png", "imgW": 1200, "imgH": 2600,
             "caption": "字是门,产品在门里。"}}}
```

> 给 `image` 之前先过下面的「选图硬判据」三条。`sample-page-tall.jpg`(Remotion 落地页长截图)是**反例**:
> 漂移窗口正好压在一条留白带上,「出片」读成纯白色的字。

没有截图时把 `image/imgW/imgH` 整组省掉,门里流的是从皮肤令牌派生的产品界面骨架流(**preset 自带样例走的就是这一档**——见下面「选图硬判据」:单张真实截图能不能成立取决于漂移窗口正好压在哪条带上,样例是控制台里这个模板的门面,不能靠运气):

```json
{"id": "shot-001", "preset": {"id": "text-mask", "version": 1},
 "presetProps": {"durationSeconds": 6, "variant": {"takeover": "hold"},
   "slots": {"title": "新叙事", "caption": "一支片子,一个词。"}}}
```

## 什么时候用它

口播的**第一镜**,或一段讲完要换章的**转场镜**,而且这一镜同时要交代两件事:一个词(品牌名/栏目名/本段主题)和一个画面(产品界面/网页/某张图)。
先字后画太慢、画上压字太挤,这一式让两者同体——观众在读词的同时已经在看画面了。
`takeover: full` 时末帧就是全屏产品画面,**下一镜可以直接接画面**(比如接 `screen-push` 的同一张截图),中间不需要转场;`takeover: hold` 是独立开场卡,末帧仍在字内。

## 什么时候不用它

- **`brand-open`**(同为开场字标):它管的是**字标本身怎么出场**——字标显形、静置,画面里只有字。
  当这一镜只需要"念出这个名字",用 brand-open;只有当**字里必须有东西**(产品画面是这一镜的第二个信息)才用 text-mask。
  拿 text-mask 去做纯字标开场,等于花一个大动作说了一件小事。
- **`title-reveal`**(同为标题入场):它给的是**标题的入场动效**(逐词浮出 / 记号笔 / 括号拉幕),标题是**要读的文字**,可以有副标题、可以两三行。
  text-mask 的 title **不是拿来读长句的**:它是视口,2–4 字,再多笔画就细到看不见里面。有副标题、有完整句子 → title-reveal。
- **`screen-push`**(同为展示截图):它的主角是**截图内容本身**——完整在场、推近、把某一处勾出来,观众要**看清那一处**。
  text-mask 里的画面是**质感与氛围**,被笔画切碎、只露局部,谁也读不清细节。要观众读截图上的字或数据 → screen-push;要观众感到"这个词背后有东西" → text-mask。
  两者衔接得很好:text-mask(full)末帧交出全屏截图,下一镜 screen-push 接着指给他看。
- **同片不与 `transition-travel` C 式(字腔穿越)并用**(配方卡 P4):两者都是"字里长出世界",一个是相机钻进字腔、一个是字自己胀开,观众会读成同一招使了两次。一支片子里只留一个。
- **手上那张图过不了下面「选图硬判据」三条**时别用它——不是"效果差一点",是**这一式直接不成立**(字读成纯色的字,或者字整个消失)。
  这时候要么省掉 `image` 走骨架流,要么换 `screen-push`(那一式是让人看清截图的,不是拿截图当质感的)。

## 选图硬判据(给 `image` 之前必读)

这一式对素材挑食,失败方式还是**静默的**:工程照跑、渲染不报错,画面直接不成立。三条都得过:

1. **门里必须和门外拉开明度。** 暗皮肤(`P.bg` L0.17)下门里内容的明度要**明显高于** `P.bg`;亮皮肤(L0.98)下要明显更暗。
   **暗色截图 + 暗皮肤 = 字直接消失**——实测 `sample-screen.png`(暗底绿色纽结)和 `catalog/ui-dashboard.svg`(暗色线框仪表盘),笔画里比背景还暗,「片」整个不见了。
2. **笔画里必须有结构**(边、条、卡、色块),不能是一块平色。460px 字号下笔画宽约 40–60px,图元节距得落在这个量级。
   大片留白、大片纯色、纯渐变在笔画里一律退化成"有颜色的字"——实测 `sample-page-tall.jpg`(Remotion 落地页长截图),漂移窗口正好压在一条留白带上,「出片」读成**纯白色的字**,笔画里只剩一面国旗、一个 emoji 和半行灰字,窗口感为零。
3. **要看的是那一条带,不是整张图。** 漂移窗口只覆盖源图的**一条窄带**(1080×1920 + `CONTENT_ZOOM=1.5`,5s 档实测整支片子累计只透出约 400px 高的一段),页面别处再好看也进不了画面。
   **给图之前先量一下那条带上是什么。** 长页截图尤其容易踩:好看的部分往往在首屏,而首屏根本不在窗口里。

低分辨率截图还会在笔画里糊成一片(配方卡的已知坑)——这一式的画面全程被特写盯着。

## 坑

- **遮罩字用不上我们加载的字体——如果你把它写回 data-URI 的话。** demo 的
  `mask-image: url("data:image/svg+xml,<svg><text>…")` 在本项目**会静默失败**:SVG 作为图片被引用时在独立文档里栅格化,
  拿不到 `lib/fonts.ts` 用 `FontFace` 注册的字体,中文回退成系统字体甚至豆腐块,**而且不报错**。
  所以整块是行内 `<svg>`:`<image>` 走图片、`<mask><text>` 走遮罩,同一棵树、同一个文档。**别"顺手优化"回 data-URI。**
  验证方法:渲两帧,一帧默认字族、一帧 `tune.font: "smiley"`,两张字形应当明显不同(得意黑是 8° 斜切)。都一样 = 双双回退了。
- **遮罩字族不跟皮肤 kit,这是故意的。** 当前皮肤 abyss 用 minimal kit(中文霞鹜新晰黑,只有 400 一档,`weightCap` 500)。
  460px 下它的笔画宽约 25px —— 那不是门,是门缝。遮罩槽的功能要求就是最大墨量,所以固定走 Archivo VF + 思源黑 VF 的**真** 900。
  `tune.font` 仍可覆盖,但覆盖成单字重字族(smiley / wenkai / noto-serif)会明显变细,`fontSynthesis: 'none'` 会老实渲 400 而不是伪造粗体——**那是取舍不是 bug**。
- **放大原点不许再手推。** demo 把 `transform-origin` 推到字母 L 的竖笔 61.5%,配方卡自己写明"换词换字体必失效";
  中文一个字一个样,手推的百分比换文案后必错,而错的后果是**放大后铺满全屏的是底色不是画面**。
  本 preset 的策略是:原点取词包围盒中心(与文案无关),放大的同时给字加 0→0.55em 描边,**让字腔和字间缝被自己的笔画吞掉**,
  原点因此必然落在实心里。0.55em 是按字腔最大的那批字(口/回/日/田)倒算的,**别调小它去"保住字形"**——保字形的旋钮是放大曲线,不是这一条。
- **`DILATE_WINDOW` 两头都掉坑,改之前先拿「回口田」重渲。** 太早(试过 0.05)→ 字形在 endT 0.35 就糊成一坨、整块提前铺满,接管段后 2/3 是死时间;
  太晚(试过 0.50)→ 字腔在 endT≈0.5 长到约 670px,画面正中挂一块深色方块,就是配方卡说的"透出底色"。
  验证文案必须是**大字腔且正中那个字腔压在原点上**的,两个字的短词看不出问题(它的包围盒中心通常落在很窄的字间缝上)。
- **放大是几何插值 `S = 7^endT`,不是线性 1→N。** 线性插值在 endT=0.08 就已经 3 倍,"字形胀开"观众只看得到前 8%;
  几何插值缩放速率恒定,字形能被读到 endT≈0.35(默认档第 103 帧仍是完整字形)。
- **mask 的放大 transform 必须待在 `<mask>` 子树里。** 挪到 `<g mask="…">` 上就等于把 demo 的坑搬了回来:
  内容会跟着字一起胀成 N 倍废片,那时才需要 1/S 反向补偿。SVG 路线下遮罩几何与内容几何天生解耦,**别去"统一"它们**。
- **接管保险层不许省。** 纯 mask 放大在字缝处会留深底残余,所以另叠一个共享同一内容变换的无遮罩全屏层在 endT 0.50–0.90 淡入。
  两层内容变换完全相同,交叉淡入看不出接缝。
- **SVG `<image>` 不是 Remotion 的 `<Img>`,渲染器不会替你等它加载。** 组件里用 `delayRender` 手工预载;
  删掉那个 hook 会得到"偶尔首帧没图"的幽灵 bug。
- **骨架流不是"骨架屏",是一个产品界面。** 判据只有一条:**渲 f60,笔画里要同时看得到 ≥3 种图元**(面板底 + 分隔线/分栏 + 强调色柱或芯片),
  让人读作"门里是一个界面",而不是"字是蓝的"。第一版是稀疏的大卡片墙,笔画里只截得到一块平色——机制全对,但看不出是哪一式。
  **图元尺度按笔画宽度标定,不按"版面好不好看"标定**:`CONTENT_ZOOM=1.5` 时 1 骨架 px = 1.5 屏幕 px,笔画宽 ~50 屏幕 px ≈ 33 骨架 px,
  所以节距必须落在 26–74 骨架 px(表格行 54 / 图表柱 36 / 迷你柱 29 / 右栏行 74)。再大退化成平色,再小视频压缩后糊成噪点。
- **骨架流的两套明度阶梯是整体翻转的,不是"越亮越好"。** 暗皮肤门里是**亮色 UI**(卡片 L0.74 + 深色文字条),
  亮皮肤门里必须是**暗色 UI**(卡片 L0.40 + 浅色文字条)。第一版亮皮肤照抄了暗皮肤(卡片 L0.985 vs paper 纸底 L0.98),
  字形直接化在纸上,只剩几根散落的柱子。**加皮肤时先看 `P.mode`,再决定这一栏往哪个方向走。**
- **骨架流上半带不能留白。** 只放柱状图的话柱顶以上是一片平色,f0 的笔画里就只有一块灰;英雄面板里的 KPI 条(骨架 y 1418–1494)
  和趋势折线(1500–1630)就是补这一段的。**整支片子的漂移窗口累计只覆盖骨架 y 1403–1801、x 180–900**(5s 档实测),
  密度必须整页均匀,不能只在某一处堆一块好版面。
- **骨架流的英雄面板摆在页面纵向正中**——接管完成帧是 cover 居中裁切(骨架 y 690–2610),正中放什么末帧就落在什么上;
  摆在中间,末帧才是一块像样的产品版面,不是一墙一模一样的卡片。
- **`takeover: 'hold'` 不是"把末段砍掉"**,它有自己的收束:漂移 outCubic 减速 0.9s 停住 + caption 留场 + 末段真静止 24 帧。
  两档的动作性格必须一致(同样的 hold 时长、同样的漂移速度),只是结尾去处不同。

## 设计取舍记录

- **26 倍 → 7 倍。** demo 的 26 是 1920×1080 + 拉丁字母的值。竖版里字半高 230、原点到画幅底边 1000,盖满只需 ≈4.4 倍;
  7 倍是留足"字边残影彻底出画"余量后的取值。再大只是把爆发浪费在观众已经看不见的地方。
- **横漂 → 轴自适应。** demo 是 16:9 仪表盘横漂 ~2.75px/f。竖版的典型素材是长页截图:横向没余量、纵向余量巨大,
  所以按 cover 之后哪根轴富余多就漂哪根(配方卡"漂移方向选画面信息密的轴"在竖版里就是这个意思),长页读作"页面在字里滚"。
- **字内取景 1.15 → 1.50。** demo 的 1.15 是 1920 宽仪表盘的值;竖版里 1200 宽的长页在 0.9 倍下元素太小,笔画里读不出是什么。
  1.50 让门里看得清是什么,接管时归位到 1.00 顺带做成一次"拉开看全貌"。
- **不做内容层 1/S 反向补偿。** 那是 CSS mask 绑元素 transform 才需要的补丁。走 SVG `<mask>` 之后,
  配方卡守的那条命门(产品不许跟着字胀成 N 倍)从"靠一个反向 transform 撑着"变成**结构性成立**。少一个能被改坏的地方。
- **词带中心 920 而不是几何中心 960。** 竖版里几何居中永远看着偏低;920 让字块视觉居中,底部 1660 留给 caption。
- **`title` 的 `fontSize` 从骨架的 360 提到 460。** 940 的宽度上限下,2 字正好吃满(906px);
  360 会白白浪费掉四分之一的门洞——而门洞大小就是这一式的信息量。3 字自动缩到 ≈319,4 字 ≈240,6 字直接报错。
- **左右墨量不平衡是文案属性,不是版式 bug。** 样例「出片」的 `frame-audit` 报"左半边占墨 79%":
  出的笔画密度天然远高于片。词是居中的(实测包围盒中心 = 画幅中心),这条告警在换文案后会自己变。
