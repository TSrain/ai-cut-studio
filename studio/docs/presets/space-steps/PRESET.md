# space-steps · 空间步进

> principle: atoms are sacred · slots are the only freedom · timing is frozen

```yaml
version: 1
name: 空间步进
role: 把「几步讲述」拍成在同一片空间里的一次旅行——每一步不只换内容,还换一个空间姿态;末段拉远一眼看全
duration_seconds: [5, 10]
source: video-shotcraft 的 basic-3d-scene 移植(2026-08-26,合成 ScBasic3DScene 逐帧对照)
colors: 站点色 = oklch(0.38/0.21, C, accentHue+{0,+28,−28,+56}°);结论板 = 皮肤 slab 渐变 + slab.ink;禁 hex
typography: 站名=h1(72 缩至 36)、小注=body(站名字号×0.46,≤2 行)、序号=caption 30、结论板=h1 88(缩至 48)、caption=body(44 缩至 32)
spacing: 卡 640×580、卡内文字块宽 512;站位 x=0/±340、y 每站 +700、z 每站 −260;结论板挂末站下方 540
geometry: perspective 1600(persp : max|z| ≈ 2:1)、世界锚点 (540, 900)、总览 3 站 s=1.80 / 4 站 s=2.32
motion:
  - {phase: enter, seconds: 0.00, action: 第 1 站正视,第 0 帧即在场;世界自 z+80 落位 0.7s(轻推入,不是入场), easing: CALM}
  - {phase: hold,  seconds: 1.05, action: 飞第 2 站 0.85s(右移+下行+后退+ry−38°), easing: MOVE}
  - {phase: hold,  seconds: 1.90, action: 停留 0.95s 读卡;离焦站 0.28 底 + 5px 模糊,始终在场}
  - {phase: hold,  seconds: 2.75, action: 飞第 3 站 0.85s(左移+下行+后退+rz90°:画框侧躺,相机把它转正), easing: MOVE}
  - {phase: hold,  seconds: 3.70, action: 停留 0.95s;结论板从画面底部露出一角(预告)}
  - {phase: hold,  seconds: 4.65, action: 飞 OVERVIEW 1.10s(相机退到站前 z+180 并 1/1.8 拉远,全员点亮,幽灵序号淡出), easing: MOVE}
  - {phase: hold,  seconds: elastic, action: 总览定格(英雄帧);伸缩先落这里,再压 hold,最后才压飞行,末段真静止 ≥0.85s}
variants:
  spin: on(第 3 站 rz90° 画框侧躺,记忆点,一支片只用一次) / off(只用位移与 ry,给信息密的文案让路)
slots:
  steps: 每一站,3–4 条,写成「站名 | 一句话」(必填)
  overview: 总览结论板上的那句话 —— 这一镜的英雄帧,可省(不填用第一站站名)
  caption: 画面底部的结论句,可省
spring_accents: 0
```

## 用法

```json
{"id": "shot-004", "preset": {"id": "space-steps", "version": 1},
 "presetProps": {"durationSeconds": 7, "variant": {"spin": "on"},
   "slots": {
     "steps": ["先把话说顺 | 画面的事一个字都别想",
               "一句话一个画面 | 配不出来的那句多半是废话",
               "八成套模板 | 剩下两成才值得设计"],
     "overview": "三步,一支片子",
     "caption": "不是翻页,是在想法的空间里走一趟。"}}}
```

## 什么时候用它

口播说**「这件事分几步 / 有几个环节 / 我是这么一路走过来的」**,而且你希望观众记住的不只是几条内容,还有**它们之间的空间关系**——第二步是"往那边去了",第三步是"整个视角翻过来了",最后是"退一步,它们本来是一整片"。

它的独有叙事收益就一条:**转场本身携带语义**。别的多步 preset 是"下一条内容替换上一条",这一式是"你被带到了另一个位置" —— 因此末段拉远时会有一个别处拿不到的收束:观众看到自己刚才走过的路,三张卡同时在场。

3 站是甜区,4 站要给到 ≥8s(否则每站读卡时间会被压到 0.7s 以下,赶)。

## 什么时候不用它

- **和 `cube-nav` 的分界:那几块是不是同一个物体?** cube-nav 的面是**同一个立方体的几个面**(一个系统的几个部分,静态并列,转是为了看它的另一面);space-steps 的站是**一条路径上的几个位置**(有先后,有方向,camera 一直在往前走,不返程)。说「这个工作台有五个区」用 cube-nav,说「我是这么三步做出来的」用 space-steps。用反了观众会误读关系:把并列读成流程,或者把流程读成拼盘。
- **和 `step-flow` 的分界:观众要不要同时看见全流程?** step-flow 是平面脊线,**所有步骤始终同框**,当前步高亮 —— 它服务"这条流水线长这样,我们现在在第 2 环";space-steps **一次只给一站**,别的站在空间深处虚化,最后才合并成一张全景 —— 它服务"跟我走一趟,走完你回头看"。要**对照几步之间的关系**(谁在谁前面、哪一步最长)用 step-flow;要**逐站沉浸 + 末段恍然**用 space-steps。另外 step-flow 吃 2–6 步、这一式只吃 3–4 站:少于 3 站没有"旅行",多于 4 站在竖版里排不下且每站都被压得读不完。
- **换一条内容还成立吗?** 站名超过 14 个字、或者小注需要两行以上才说得清,就不成立 —— 卡在空间里飞,不是给人细读的版面,文案没法提炼到一行就改用 `bullet-run` 或 `recede`。
- 只有两条内容用 `contrast-pair`;要强调"数字变化"用 `number-beat`;要强调"时间推进"用 `timeline-travel`(它的横移刻度轴本身表达时间,这一式的空间位移不表达任何量纲)。

## 坑

- **本体是一行:`camera = stepTransform.inverse()`。** 每站只写卡片自己的 pose,相机严格取逆 `scale(1/s) rotateZ(−rz) rotateY(−ry) rotateX(−rx) translate3d(−x,−y,−z)`,**顺序反着正变换**。乱序在单轴旋转时看不出来,第 4 站(rx+ry 复合)会歪。加站只改 `stepPose` 表,两处 transform 字符串别动。
- **`scale(1/s)` 是 2D scale:它只缩 x/y 不缩 z**,所以透视放大率 `mag = P/(P−z_rel)` 与 s 无关。总览取景的算式(组件里 `OVERVIEW` 常量上方那两行不等式)和结论板的 `k = OVER_S/mag` 都建立在这一点上,换成 `scale3d` 会全崩。
- **每站至少换一个新的变换维度**(2 站 ry、3 站 rz、4 站 rx),只挪 x/y 就是把幻灯片摆到了 3D 里。
- **有旋转的飞行段不许快于 0.7s**。观众需要时间理解"世界在转";压时长时先压 hold(最多压到一半)再压飞行,组件里已经是这个顺序。
- **离焦底值 0.28、模糊峰值 5px,底别再压低**。离焦卡要"在场";压到纯黑就丢了空间感,末段"原来它们一直都在"的收束也就没了。5px 是 demo 3.5px@480 坐标的保守换算(等效值 7.9px 会把竖版大卡糊成色块)。
- **rz90 站的文字在末段反向旋转,不是淡掉 —— 别"顺手"删掉这个反向旋转**。相机 rz 从 −90 归 0 的同时文字走 0→−90,屏幕上净旋转恒为 0(`−90(1−u) + 90 + (−90u) ≡ 0`),文字全程稳住、卡片绕着它转;删掉它总览里那张卡的字就是躺倒的。注意这**不是** `cube-nav` 顶/底面那种情况:那里法线朝上、两个姿态差 180° 面内旋转,数学上无解只能淡掉;这里 rz 是面内旋转,精确可解。**进站方向的"转正瞬间"照旧保留**,被稳住的只有出站。
- **卡内文字块必须是 `top:50% + translateY(−50%)` 居中**,不能顶对齐:反向旋转绕块中心,顶对齐会把文字甩出卡外。块宽 512 ≤ 卡高 580、块高 ≈300 ≤ 卡宽 640,所以 90° 转过去仍在 `overflow:hidden` 里。
- **总览之后无返程**,这一式作段落收尾用。要循环回第 1 站得在末尾补一段 fly back(cam 再 lerp 回 `poses[0]`)。
- **perspective : max|z| ≈ 2:1**。z 再深(加站)要同步加大 perspective,否则最近的一站会被拉成鱼眼。

## 设计取舍记录

1. **横版散点 → 竖版下行纵队。** demo 的四站散在横向平面(x 最大 520、y 最大 300)。竖版画幅高是宽的 1.78 倍,横向散点在总览时被宽度卡死、上下留出大片空。改成左右交替的下行纵队后,总览是一列自上而下的瀑布,天然吃满竖画幅;读序也从"到处找下一张"变成"顺着往下读"。这是移植真正的工作量,不是把横版塞进竖版。
2. **OVERVIEW 从"空间里一张巨卡"改成"纵队末端的结论板",且板内一切按屏幕像素授权。** demo 的总览卡 s=3.1、内容预除 2.2,压在别的卡上(原片定格里标题被 STEP01 挡掉半行)。竖版的英雄帧必须字大且不许被挡,所以把板挂在末站下方 540px、z=0 最前层,世界缩放取 `k = OVER_S / mag(z=0)` —— 于是不论 3 站还是 4 站,板在总览里恒为 800px 宽、标题恒为 88px。副作用是好的:槽位 `fit` 可以直接用屏幕像素口径写,填表的人看到的 88 就是渲出来的 88。
3. **rz90 站末段反向旋转而不是淡掉**(理由见上「坑」)。取舍是:牺牲"侧躺的字"这半个记忆点,换总览里全员可读;卡片本身仍然是横躺的(640×580 转 90° 后比例明显不同),记忆点没丢。
4. **灰阶骨架条全删,换成真实中文文案。** demo 卡内是两根灰条占位,在真文案面前只是噪音;保留的是一根 68×5 的 accent 细规,它是版式锚点不是装饰。
5. **每站背后加一枚 400px 幽灵序号,总览时淡出。** 对齐单站时画面只有一张卡 + 底,墨量与层次都偏薄(实测首版 46%、质心偏压 0.37);幽灵序号补层次又补身份,而且是方向中性的图元(rz90 站转过去也不别扭)。总览时三张卡自己撑满画幅,序号必须让位 —— 否则一屏三个 400px 数字。序号左右交替(奇数站在右),顺带把构图偏压拉回 0.41–0.46。
6. **砍掉了一条竖排进度轨。** 首版在右边缘做了一条带圆点的竖轨表示"走到第几站"。反事实删除测试没过:卡上本来就有 `01/02/03`、身后还有 400px 幽灵序号,进度信息已经有两处,轨道只是第三处 —— 而且在 320px 缩略图里它读作边缘的一道杂线。删掉了。
7. **结论板与末站的距离定在 540(不是 660)。** 660 时末站停留帧四周空无一物;540 时结论板正好从画面底部露出一角,末站那一拍有了"下面还有东西"的预告,拉远时也就不是凭空冒出来一块板。
