# bullet-run · 列点推进

> principle: atoms are sacred · slots are the only freedom · timing is frozen

```yaml
version: 2
name: 列点推进
role: 口播说「有三个原因 / 四个特征 / 五件事」时的画面。b-roll 里最高频的一种,也是最容易做成 PPT 的一种
duration_seconds: [4, 12]
colors: 全部来自皮肤;当前条 = 满亮 + 一根 4px accent 竖条,其余 = 同一颜色压到 0.38。**没有底板、没有描边、没有分隔线**
typography: 题目 h1(96 起,自动缩字)、条目 h2(3 条时 84)、小注 body(条目的 0.42)。字重上限 500(minimal kit)
layout: >
  题目在 420;列表块在 700–1520 之间**垂直居中**(不是铺满);行距 = 字号 × 2.15;
  左边距 100,竖条占着它,文字从 144 起。上下各留一大片空,那是设计的一部分
motion:
  - {phase: enter, seconds: 0, action: 全员在场(0.16 亮度),整块 0.9s 内亮到 1 并抬 10px, easing: CALM}
  - {phase: enter, seconds: 18%–62%, action: 光逐条走过去,当前条亮起 + 竖条长出,讲过的退回 0.38。元素不位移, easing: CALM}
  - {phase: hold, seconds: elastic, action: 完全静止,约占全片 38%}
slots:
  items: 要列的几条(2–6)。一行一条;每条可用 ` | ` 隔出小注(默认别填)
  title: 可选,题目句
  eyebrow: 可选,顶部眉题(默认别填——见下)
variants:
  flow: walk 光走过去(讲过的退暗) / stack 亮了就不灭
  marker: none 不加标记(默认) / number 01·02·03 / check 对勾 / dot 短横
```

## 用法

```json
{"id": "shot-002", "preset": {"id": "bullet-run", "version": 2},
 "presetProps": {"durationSeconds": 7, "variant": {"flow": "walk", "marker": "none"},
   "slots": {"title": "为什么现在动手",
     "items": ["工具已经够用了", "内容比工具稀缺", "早做早有素材库"]}}}
```

控制台「做片子」里 `items` 是一个多行文本框:**一行一条**,空行忽略。

## v2 为什么把 v1 拆了重做

v1 是"信息面板"路线:眉题 + 题目 + 补充句 + 右上角 `01/03` 计数 + 三块卡片底板 +
序号 + 主句 + 小注 + 分隔横线。**每一件都能说出用处,合起来是一屏九种元素。**

用户 2026-08-15 的原话:「元素太多…口播就要设计的和乔布斯的 ppt 一样,简单直接高级;
字体不好看;画框占比太大留白过少;动画过于着急」。

v2 只留三件事:**题目、几条内容、光走到哪条**。

| 删掉的 | 它当时的理由 | 为什么还是删 |
|---|---|---|
| 右上角 `01 / 03` | 观众知道进度 | 竖条已经标了当前条,进度是同一件事说两遍 |
| 补充句 kicker | 给题目加一句注解 | 题目自己说不清楚就该改题目 |
| 卡片底板 | 平衡右侧构图 | 三个框占了半屏,"画框比内容大" |
| 分隔横线 | 表格结构感 | 行距够大就不需要线来分 |
| 大号序号 | 数得清有几条 | 三行字本来就数得清 |
| 眉题「三件事 · CHECKLIST」 | 说明这是个清单 | 观众看一眼就知道。**自证性标签是最该删的一类** |

构图失衡也就跟着解决了:v1 用底板往右铺材质来对冲"左对齐列表左压"(实测左半占墨 72%),
v2 索性接受左对齐 + 大片右留白——那不是失衡,那是版式。

## 三条不能退的规矩(改这个模板前先读)

1. **不许飞进来。** 所有条目第 0 帧就在场,动的只有"光"。元素位移只剩 10px 的抬升。
   会飞的列表读作动画演示,不会飞的列表读作有人在讲话。
2. **一拍 0.9 秒(`BEAT`),缓动用 `CALM` 不用 `ENTER`。** ENTER 前 30% 就跑完 80% 的距离,
   放在 84px 的大字上就是"甩"。慢到能看清它怎么停下来,才叫稳。
3. **留白是内容。** 列表块在 BAND 里**居中**而不是铺满,行距是字号的 2.15 倍。
   有人想往空白处再加点东西时,先回来读这一行。

## 踩过的坑

1. **所有条目必须同一个字号。** 逐条各自 shrink-to-fit 会出现第 2 条比第 1 条大一号,
   列表立刻读作"排版坏了"。取所有主句 fit 结果的**最小值**统一用。
2. **条目多就降字号,不许压行距。** `BASE_SIZE()` 按条数分档(2 条 92 / 3 条 84 / 4 条 70 / 5+ 58),
   `PITCH_RATIO()` 同步降。靠压行距硬塞进去的列表看着就窒息。
3. **最后一条没有"下一拍",别拿 `Infinity` 去喂 `interpolate`** —— 它只收有限数,
   会直接抛 `inputRange must contain only finite numbers`,而且报错指向的是上一个 JSX 节点,很难查。
4. **`splitOn` 是给估宽用的。** 一条 item 带小注时,整串按主句字号量会把排得下的文案误判成超宽。
   `preset.json` 里声明 `splitOn: "|"` + `noteRatio`,校验器才会分段各量。
