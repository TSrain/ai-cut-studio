# timeline-travel · 时间轴横移

> principle: atoms are sacred · slots are the only freedom · timing is frozen

```yaml
version: 1
name: 时间轴横移
role: 把版本史 / 里程碑 / 发展段落拍成一次沿时间轴的旅行——速度本身在讲"发展快",急停在讲"现在最重要"
duration_seconds: [4, 8]
source: video-shotcraft 的 timeline-travel 移植(2026-08-26);配方卡 docs/catalog/recipes-external/data/timeline-travel.md
colors: 卡片 = oklch(0.245→0.30 / 0.185→0.22, C, accentHue) 按站序走明度阶梯;走过的轨道 = P.accent 向尾端淡出;末刻度线与刻度名到站转 accent;禁 hex
typography: 刻度名=h1(88 缩至 40,轴下方)、卡内正文=body(52 缩至 30,最多 2 行)、眉题=label(42 缩至 28)、结论句=body(44 缩至 32)
geometry: 轴 y=1080;刻度间距 880(0.81 屏宽);卡 680×(178+行数×75),底边离轴 54;推近原点钉在轴上 (50%, 56.25%)
motion:
  - {phase: enter, seconds: 0.00, action: 轴/次刻度/全部刻度名第 0 帧即在;首站卡从轨道上弹起立住, easing: spring(damping 11)}
  - {phase: enter, seconds: 0.47, action: 相机横移——前 15% 时间走 5.5% 距离(缓起)/ 中段 73% 时间吃掉 84.5% 距离(冲刺)/ 末 12% 时间只剩 10% 距离(急刹), easing: 断点 [0,0.15,0.88,1]→[0,0.055,0.9,1] 段内 inOut(quad)}
  - {phase: enter, seconds: 每站到达前 6f, action: 那站的卡从平躺以底边为轴弹立(明显过冲)+ accent 立杆长出 + 刻度名点亮, easing: spring(11/160/0.9, 26f)}
  - {phase: enter, seconds: 3.92, action: 急停推近末刻度 1→1.28(10f);末刻度线与刻度名转 accent, easing: out(cubic)}
  - {phase: enter, seconds: 4.02, action: 结论句底部上浮 22px 淡入 0.45s, easing: CALM}
  - {phase: hold,  seconds: elastic, action: 完全静止读结论(默认 5.5s 下 37 帧,≥ 配方卡的 30 帧)}
slots:
  stops: 每个刻度(必填,3–5 个),写成「刻度名 | 一句话」
  title: 顶部眉题,可省
  caption: 急停后淡入的结论句,可省
spring_accents: 1
```

## 用法

```json
{"id": "shot-004", "preset": {"id": "timeline-travel", "version": 1},
 "presetProps": {"durationSeconds": 5.5,
   "slots": {
     "title": "一年半,四个版本",
     "stops": ["v1.0 | 只能套三个模板", "v2.0 | 会自己分镜了", "v3.0 | 字幕能改了", "今天 | 一句话出片"],
     "caption": "一直在发货。"
   }}}
```

刻度名(竖线前)印在轴下方 88px,是这一式的节奏;那一句话(竖线后)印在卡里 52px,是内容。
**竖线后半段不写的站只有刻度和名字,不渲空卡**——半空的卡读作"这里本来该有东西"。

## 什么时候用它

口播讲「我们一直在发货」「这三年是怎么走过来的」「从 v1 到今天」时。
判据是**把顺序打乱画面还成立吗**:不成立,而且顺序本身有时间语义,才该用它。
它独有的叙事收益是**速度**:观众感觉到"这一段发展得很快",然后急停告诉他"但重点是现在这一站"。
这个感受在任何一种逐条列出的画面里都拿不到。

## 什么时候不用

- **`step-flow`(流程推进)**:同样是多步推进,但它讲的是**因果**——第二步是第一步的结果,
  打乱顺序不成立是因为"做不了",不是因为"时间不对"。它的载体是纵向脊线逐段画出去,
  重点在"现在走到哪一步";没有速度、没有急停。**讲机制用 step-flow,讲历史用 timeline-travel。**
  一个判据:如果每一站换成"里程碑日期"读起来很别扭,那就不是时间轴。
- **`bullet-run`(列点推进)**:打乱顺序**画面照样成立**(三个理由谁先谁后无所谓)。
  一旦顺序是可交换的,横移就成了纯粹的运镜表演——观众会问"为什么要跑这一趟"。
  时间轴的独有收益(速度感、走了多远、还剩几站)在无序内容上全部失效,退回 bullet-run。
- **`trend-chart`(趋势图)**:同样有时间维度,但它讲的是**一个量随时间怎么变**,
  必须遵守坐标比例诚信那一套(`docs/chart-rules.md`)。timeline-travel 的刻度之间
  **没有等比时间语义**——v1.0 到 v2.0 和 v2.0 到 v3.0 在画面上是同样的 880px,
  实际可能一个隔三个月一个隔一年。**有数值就用 trend-chart,只有事件就用 timeline-travel;
  拿等距刻度去暗示等距时间是在骗人。**

另外:刻度只有 1–2 个的别用(没有"旅行"),超过 5 个也别用(每站分到的时间不够读,
掠过速度会把中间几张卡冲糊)——那种情况该拆成两镜或改用 bullet-run。

## 设计取舍记录

- **变速曲线是这一式的命门,不是可调参数。** 输入断点 `[0,0.15,0.88,1]` → 输出 `[0,0.055,0.9,1]`,
  段内 `inOut(quad)`。全程匀速就是廉价 PPT;中段拉慢就没有旅行感;末段不急刹就只是"停了",
  推近才是"到了"。三段各自的比例都是 demo 逐帧调校过的,改一个断点就要重新验收全片。
- **横版 → 竖版不是等比缩。** demo 刻度间距 1400px 是 0.73 屏宽;竖版屏宽只有 1080,
  照 0.73 取会让相邻的 680 宽卡片几乎贴在一起,掠过时糊成一条。竖版取 880px = 0.81 屏宽,
  换算的守恒量是**每帧走过的屏宽比例**(≈2.8%/帧),不是像素数。
- **卡高是算出来的。** `178 + 正文行数 × 行高`,行数由 `estimateTextWidth` 确定性地算出来,
  全表统一。写死高度配上一句短文案就是一张半空的卡。
- **刻度名 88 / 正文 52 = 1.69 的字号比。** 刻度名是节奏(v1.0 → v2.0 → 今天),正文是内容;
  两者都要能读,所以不能靠"一个大一个小到看不见"拉开,靠的是**字族 + 位置 + 色**:
  刻度名走 display 家族、印在轴下方、到站转 accent;正文走 body 家族、印在卡里、始终 P.ink。
- **未到站的卡平躺在轨道上。** demo 里卡是凭空出现的;竖版一屏只装得下一张多卡,
  掠过两站之间会有约 20 帧右半屏是空的。让下一张卡先躺在轴上补住那段空,顺带交代"还有几站"
  (`step-flow` 的「脊线未走段不能省」同一条道理)。它仍然是从刻度线上立起来的,语义没变。
- **平躺→立起必须是一条连续曲线。** scaleY 从 13% 长到 1,不是 `up ? 立起 : 平躺` 两个分支——
  写成两个分支会在起弹那一帧闪断成「13% → 0% → 重新长起来」,像卡片被删掉又重画。
- **卡面内容是卡 div 的子元素**,跟着一起被压扁再回弹。单独放一层只跟 scaleX 的话,
  弹立中段能看到文字和 accent 条悬在压扁的卡外面,像两个不相干的东西。
- **走过的轨道向尾端淡出。** 不淡出的话它会把整个左半屏刷成实心强调色,构图直接偏压
  (`frame-audit` 的左右平衡实测 leftShare 71%)。淡出同时也在说"越久远越淡"。
- **末段静止预算前置。** 先扣掉 1.05s(31 帧)静止再把剩下的给行程;时长不够 nominal 时
  **压缩行程不压缩静止**。demo 首版就是因为把静止排在最后,只剩 25 帧不达标。
- **不叠 CameraMotionBlur。** 配方卡说"快到卡片糊时可叠",但竖版的硬约束是"至少末两张卡能读",
  而速度已经按 demo 的屏宽/帧标定过,并不糊。这时候叠方向模糊只是拿可读性换一个没人要求的效果。
- **弹簧只有一个名额**(卡片弹立,damping 11 明显过冲)。刻度名点亮、accent 立杆长出
  都由同一根弹簧驱动——一个名额,多处消费。
