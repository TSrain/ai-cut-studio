# step-flow · 流程推进

> principle: atoms are sacred · slots are the only freedom · timing is frozen

```yaml
version: 1
name: 流程推进
role: 口播讲「先 A,再 B,最后 C」「输入进去,中间发生了什么,输出出来」时的画面。讲工作流、讲机制、讲这东西怎么运作
duration_seconds: [5, 16]
colors: 全部来自皮肤;已走脊线段与当前节点 = accent,未走脊线 = line 0.5,步骤名靠不透明度分三档(当前 1 / 走过 0.45 / 未到 0.2)
typography: 题目 h2(62,压到 0.62 亮度)、当前步 h2(4 步时 64)、其余步 0.56 倍、说明句 body(当前步的 0.56)、步骤号等宽数字
layout: >
  题目 400;脊线 x=196,纵贯 620–1580;步骤号右对齐收在 152;步骤名 292 起(宽 688)。
  说明句挂在当前步名字下方,**只有当前步有**
motion:
  - {phase: enter, seconds: 0, action: 骨架全在——题目 + 完整脊线 + 全部节点与步骤名(压暗), easing: CALM}
  - {phase: enter, seconds: 16%–70%, action: 脊线逐段画到下一节点 → 节点点亮放大 → 步骤名放大 → 说明句展开, easing: CALM}
  - {phase: hold, seconds: elastic, action: 完全静止,约占全片 30%}
slots:
  steps: 几个步骤(2–6)。一行一步;每步可用 ` | ` 隔出说明句
  title: 可选,这是什么流程
  eyebrow: 可选,顶部眉题(默认别填)
variants:
  emphasis: focus 当前步明显更大 / even 全部同大只靠亮度
  marker: number 01·02·03 / dot 只留节点
```

## 用法

```json
{"id": "shot-003", "preset": {"id": "step-flow", "version": 1},
 "presetProps": {"durationSeconds": 9, "variant": {"emphasis": "focus", "marker": "number"},
   "slots": {"title": "一支口播片子是怎么出来的",
     "steps": [
       "写稿 | 先把话说顺,画面的事一个字都别想",
       "拆分镜 | 一句话配一个画面,配不出来的那句多半是废话",
       "套模板 | 八成的画面已经有模板,剩下两成才值得设计",
       "拼成片 | 时间轴对齐口播,末段留静止"
     ]}}}
```

## 什么时候**不**该用它 —— 和 bullet-run 的分界

这两个模板长得像。选错的代价是画面在暗示一个不存在的因果关系。

**判据只有一句:把步骤顺序打乱,画面还成立吗?**

| | 成立 | 不成立 |
|---|---|---|
| 例子 | 「现在动手的三个理由」 | 「写稿 → 拆分镜 → 套模板 → 拼成片」 |
| 该用 | `bullet-run` 列点推进 | `step-flow` 流程推进 |

用 step-flow 去讲一组无序的理由,脊线会让观众以为"第二个理由是第一个理由造成的"。
反过来用 bullet-run 讲流程,则丢掉了唯一重要的那条信息:**它们是接着来的**。

## 有向性靠三处一起承载,少一处就退化成列表

1. **脊线逐段画出来。** 线走到哪,进度就在哪——这是"上一步的产物流到下一步"的视觉载体。
   第 0 帧未走段就全在(浅色),观众要先知道"一共几步、还有多远";从零长出来的流程图,
   观众不知道自己在哪。
2. **当前步是大的,不只是亮的。** 字号从 0.56 倍放到 1 倍。尺寸差比亮度差更能说"现在在这里"——
   `emphasis: 'even'` 关掉这一条,只在步骤名很短、要一眼看全流程时才用。
3. **一次只有一句说明在屏上。** 只有当前步展开它的说明句,其余收成一行名字。
   四句说明同时在屏 = 四个焦点 = 没有焦点。

## 规格是从哪来的

不是现编的。SC-0025 的 Shot5/Shot6 手搓过两次漏斗流水线,当时在 `memory/taste.md` 里写下的
可复用结论是:**「多阶段流水线用『每阶段一个顶部标签 + 焦点逐段转移』承载,规避单镜多焦点的混乱」**。

这个模板就是那句话的固化。唯一的改动:竖版里"顶部标签"会和题目打架,所以把它换成了
**脊线上的当前节点**——承担的职责一样(锚定"现在在哪一步"),但不占顶部。

## 踩过的坑

1. **槽位间距必须按最大的那个块算,不能按平均。** 当前步是"名字 + 说明句"两行,其余步只有一行;
   按一行的高度排间距,当前步一展开就撞到下一条。
2. **说明句是会折行的,估宽必须按折行算。** `preset.json` 里 `splitOn: "|"` + `noteRatio` + `noteMaxLines`,
   校验器才会分段各量、并按 2 行预算量小注。少了 `noteMaxLines`,任何超过一行的说明句都会被误判成"太长"。
3. **所有步骤名统一字号**(取 fit 结果的最小值)。逐条各自 shrink-to-fit 会大小不一,流程图立刻读作排版坏了。
