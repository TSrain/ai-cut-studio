# 动效设计原则

写任何动画代码之前读这份文件。

**本文件在优先级链的位置(见 `docs/visual-first.md`):**

- §9(确定性与输出规格)、§7(安全区与可读性)、§4 的数据正确性条款是**技术硬门槛**,任何合同都不能覆盖。
- 其余条款(时序、缓动、编排、配色、排版的克制部分)是 **profile 默认值**:
  `visual-contract.json` 或选中的 profile(`docs/styles/`)显式声明了不同值时,**以合同为准**,不必再回来辩护。
- 顺序永远是:选中的 Styleframe / VisualContract > 技术硬门槛 > profile > 本文件的默认值 > 旧项目经验。

下面每一条被放宽的规则都直接标了新的默认值,不要再照旧值执行。

## 1. 时序(30fps 换算)

| 场景 | 时长 | 帧数 |
|---|---|---|
| 微交互 / 状态反馈 | 150–250ms | 5–8 |
| 元素入场 | 400–700ms | 12–21 |
| 场景转场 | 600–1000ms | 18–30 |
| 数字滚动 | 800–1500ms | 24–45 |
| 图表绘制 | 1200–2000ms | 36–60 |

- 观众读一行中文标题约需 1 秒 / 10 字;文字出现后必须停留够读完的时间再动下一步。**(硬门槛:可读性)**
- 语义节拍由口播与理解负荷设计，不设固定数量上限；从属元素与焦点运动按实际播放复核。
- **「语义节拍」= 观众要依次看懂的几件事,不是画面上的元素个数。** 一张由 30 个元素构成的图表(坐标系+面积+折线+端点+标注)一次画出来,是 **1 拍**。
  这条规则限制的是"观众要在多短的时间里理解几件事",不是"画面上能放几个东西"。
  把它读成"元素要少"会直接做出空画面——2026-07-31 的 auto-motion 对比就栽在这里:
  对方 144 个 DOM 元素只有 5 个信息节拍,完全合规,而我们 50 个元素做成了明显更素的画面。
  判断法:数一数"观众需要依次看懂几件事",不是数图层。

## 2. 缓动

模板 `src/lib/anim.ts` 里定义了三条标准曲线,直接用:

- **ENTER** `cubic-bezier(0.16, 1, 0.3, 1)` — 入场:快到慢,末端几乎静止
- **EXIT** `cubic-bezier(0.7, 0, 0.84, 0)` — 出场:慢到快,离场干脆
- **MOVE** `cubic-bezier(0.65, 0, 0.35, 1)` — 同屏移动:两端缓

规则:
- 位移**永不使用线性缓动**。线性只允许出现在匀速循环(背景流动)和进度条上。
- 弹跳(spring/overshoot)是可选强调手段；可以全片不使用，也可以按表达需要多次使用。
  不设默认次数或必用名额，`motion.springAccents` 记录本期设计意图。检查真实播放是否干扰读数或焦点，不用次数代替判断。

## 3. 编排

- **一个主焦点 + 最多两个次级锚点。** 任何时刻画面里有一个元素在"表演",另外最多两处可以承担次级视线落点
  (对比项、时间轴、图注、状态条);其余静止或做极轻微的陪衬运动。次级锚点的数量写进合同的 `focus.secondary`。
  (旧规则"每时刻仅一个焦点"已放宽——单焦点会把画面做空,但**主焦点仍然只有一个**,三个平级焦点等于没有焦点。)
- 列表/组元素交错入场,间隔 40–80ms(30fps 下 2 帧左右),用 `staggerDelay`。
- 相关元素同组同方向运动;"每个元素从不同方向飞入"是典型的廉价模板感,禁止。
- 转场要有空间逻辑:上一场的焦点位置决定下一场从哪里开始,不做无关联的硬切+特效。

## 4. 图表(数据动画硬规则)

- **单轴。** 永不做双 Y 轴图;两个量纲不同的指标 → 两张图或指数化到同一基准。
- 分类系列色**固定顺序、不循环、不按排名重排**;筛选变化后幸存系列不换色。
- ≥2 个系列必须有图例,≤4 个系列同时做**直接标签**(标注在线端/柱旁);单系列不放图例,标题即名称。
- 数据标签是**选择性**的:只标结论需要的那几个点,不在每个数据点上都放数字。
- 文字(数值、标签、图例文本)用墨色,不用系列色;旁边的色块/色点承载系列身份。
- 线宽 6px、端点圆点 r≥12px 且带表面色描边环、网格线用发丝级灰(以上均为 1080p 尺度,模板组件已内置)。
- 先出结论还是先出过程?默认**结论先行**(主数字/结论句 → 展开证据),纪录片/叙事风格才用过程先行。

## 5. 配色

**方法论见 `docs/color.md`(怎么定色);本节是默认值,合同可覆盖。**

- **颜色在 `visual-contract.json` 的 `palette` 里声明一次,组件只消费 token。** 镜头代码里不再现场发明颜色——
  这不是因为 hex 本身有罪,而是因为分散声明的颜色明度不可控、跨镜会漂。合同里的值可以来自 `scenePalette()`、
  品牌规范、或从主视觉图吸的色;写进合同、跑过校验就是合法的。
- **配色的骨架是明度阶梯,不是色相。** 层与层之间至少 0.04 感知明度(OKLCH L)。
- **一个主色 + 最多两个辅助色;强调面积默认 10%–35%**(profile 给具体区间)。
  (旧规则「单一强调色相 + 面积上限 10%」已放宽——那条 10% 上限是把画面做素的主要原因之一。
  面积上界仍然存在:超过 35% 它就变成底色,不再强调任何东西。)
- **颜色不必只编码信息。** 除了数据标度、分类区分、焦点强调,颜色也可以表达品牌、情绪、能量、材质和空间。
  (旧规则"说不出这个颜色在编码什么信息就拿掉"已取消。)
- 中性色带 4–10 点彩度、色相跟随主色;**永不用 `#000` / `#fff` / 纯灰**(视频里纯黑出块、纯白刺眼,这是技术原因,不是审美)。
- 文字对比度仍是硬门槛:正文 ≥4.5,大字 ≥3.0。

功能色(与美学配色分开,不混用)——模板 `src/lib/theme.ts` 内置了一套**通过色觉无障碍验证**的配色(相邻系列色 CVD ΔE≥8、正常视觉 ΔE≥15,OKLab×100),直接用,不要现场发明颜色:

| 角色 | 深色画面 | 浅色画面 |
|---|---|---|
| 画面底色 | `#1a1a19` | `#fcfcfb` |
| 主墨色 | `#ffffff` | `#0b0b0b` |
| 次级墨色 | `#c3c2b7` | `#52514e` |
| 弱化/轴标签 | `#898781` | `#898781` |
| 网格线 | `#2c2c2a` | `#e1e0d9` |
| 系列 1 蓝 | `#3987e5` | `#2a78d6` |
| 系列 2 绿 | `#008300` | `#008300` |
| 系列 3 洋红 | `#d55181` | `#e87ba4` |
| 系列 4 黄 | `#c98500` | `#eda100` |
| 正向状态 | `#0ca30c` | `#006300` |

- 系列色超过 4 个:合并为"其他"、拆分画面,不发明第 5 种颜色。
- 状态色(涨/跌/警告)不当系列色用,反之亦然。
- 用户给品牌色时:品牌色替换系列 1 和强调位,墨色/网格体系保留;替换后需自查相邻色可辨性(色弱模拟),达不到就配二次编码(直接标签/纹理)。
- 永不使用彩虹渐变映射数值;渐变仅作装饰性背景,不承载数据含义。**(这条仍是硬规则:它防的是读错数,不是审美。)**
- **图表元素上的颜色仍必须承载意义**:数据标度、分类区分、或标记主体。图表之外的画面(背景、面板、材质、氛围)不受此限。

## 6. 排版

**方法论见 `docs/typography.md`(怎么排)。前三条是硬门槛,其余是可覆盖的默认值。**

- **禁止 `system-ui` / `-apple-system` / 裸 `sans-serif`,禁止中文静默回退到默认字体。(硬门槛)**
  字体套装是合同里的显式输入:`typography.kit` 取 `impact` / `editorial` / `human` / `modern` / `tech-data` 之一,
  `textStyle()` 必须同时接收 kit 和 style role。**不许把 `FONT.text` 当全局字体**(`theme.font.family` 已删除)——
  那正是中文长期落回 Noto Sans SC、七个字体文件不产生任何输出差异的根因。
- **字号必须走 `textStyle()`,不许只写 `fontSize`。(硬门槛)** 一个字号带着字重、字距、行高一起来:大字负字距收紧、小字正字距撑开,不配套就是"字号对了但还是很土"。
- **一支片子两个主字体角色**(展示 + 正文);**小范围 mono / decorative 豁免**(数据列、时间码、单个符号)。
  (旧规则"最多两个字体角色"里的"最多"改为"两个主角色 + 豁免"。)
- **同一画面三个主要语义层级**;**微型元数据豁免**(眉题、图注、单位、时间码、署名不计入)。
  (旧规则"最多 3 级字号"照字面执行会逼掉所有元数据轨,那是编辑感的主要来源。)
- 层级只用字号/字重/明度三种手段,不用颜色区分主次文字。
- **中西文混排:西文字体写在中文字体前面**(`'Inter', 'Noto Sans SC'`),行内西文用 `latinInline` 抬 6%,中文正文行高 ≥1.6。
- **禁止伪粗体/伪斜体**(单字重字体上调 `fontWeight`)和 `scaleX/scaleY` 拉字;要窄要宽用 Archivo 的 `width(wdth)` 宽度轴。
- 需要纵向对齐的数字列用 `numeric(true)`(模板 NumberTicker 已内置);独立主数字用比例数字。
- 间距取 `theme.space`(24px)的整数倍。

## 7. 安全区与可读性

- 竖版 1080x1920:上 220 / 下 320 / 左右 96 内不放关键信息(平台 UI 遮挡区,`theme.safeVertical`)。
- 横版:四边 5% 内不放关键文字。
- **缩略图测试**:把关键帧缩到 320px 宽看,主信息仍须可辨;不可辨说明字号或对比不够。

## 8. 仍然出现即返工的清单

> 这份清单**大幅收缩过**。原来它禁掉了辉光、Bloom、光斑和多弹簧,结果是画面平到没有层次
> (2026-07-31 的实际教训)。现在只剩下真正会伤害理解的那几条,其余交给合同和 profile。
> 渐变做表面受光、投影做前后关系、描边做边界、inset 阴影做厚度,一律允许并且鼓励——
> 模板的 `MetalCoin` 就是 `radial-gradient` + `inset boxShadow`,它是明确的先例。

- **无目的的运动**:每个元素都在动、动得没有理由。运动 = 一次连续的镜头移动 + 若干目的明确、可重叠的元素揭示。
- 全屏飞入、**每元素异向入场**、旋转入场的文字——这是最典型的廉价模板感。
- 弹跳造成读数误解或焦点干扰时，按实际播放结果调整。
- 彩虹渐变映射数值、五颜六色的图表、系列色当文字色。
- 文字入场后停留时间不够读完就被换掉(§1)。
- **文字被氛围效果压掉可读性**:辉光/Bloom/景深糊到正文对比度不足 4.5、大字不足 3.0。

**已从本清单移除**(现在允许,由合同和 profile 控制强度):

| 曾经禁止 | 现在 |
|---|---|
| 背景光斑、环境辉光、镜头光晕、Bloom | 允许,条件是不损害文字对比和主焦点 |
| 一个画面 >1 个弹跳元素 | 按表达需要选择弹簧，次数不限且不要求使用 |
| 动画结束后画面仍在动 | 文字要有阅读停留,但**背景可保持低强度运动**(漂移、呼吸、颗粒流动) |
| 装饰性上色 | 图表元素之外允许用颜色表达品牌、情绪、能量、材质、空间 |

## 9. 确定性与输出规格(硬门槛,合同不能覆盖)

- **一切从 `useCurrentFrame()` 推导。**代码里不许出现 `Date.now()`、未播种 `Math.random()`、渲染期网络请求——任意一帧都必须能独立计算出来,否则重渲结果不一致、抽帧自查也失去意义。需要随机感时用固定种子的伪随机函数,种子写死在代码里。
- **输出宽高必须都是偶数。**奇数宽或高会让 libx264/yuv420p 编码失败或画面变形,而错误信息通常指不到这里。
- 素材一律引用**项目内的本地文件**,不引远程 URL;**选中的远程素材立刻下载进 `assets/` 再用**。这是确定性要求,与版权无关——素材来源是非阻塞元数据(`docs/visual-first.md` 的 Assets 一节)。
- 多引擎输出在拼接前统一规范化:合同指定的偶数宽高、30fps、H.264 High Profile、`yuv420p`、无音轨(除非合同声明)、timebase/SAR/色彩标记一致、文件名 `shot-<NNN>.mp4`。
- 交付前跑 `tools/validate-output.sh` 客观校验尺寸/帧率/时长/音轨,跑 `node tools/validate-contract.mjs` 校验合同(见 `docs/quality-checklist.md`)。
- **事实正确**:已声明为事实的数据和文案不得被篡改。演示界面可以用虚构数字,但合同必须写 `facts.mode: "illustrative"`。
- 用到要求署名的素材、且**已经决定要署名**时,署名烧进画面(角落小字,与素材同时在场)——署名义务是对观众的。但**署名状态不阻塞交付**,缺署名不构成硬性不通过。
