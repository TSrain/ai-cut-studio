# Styleframe 决策协议

用户在整个流程里只做一次决策:**看三张真实的画面,选一张(或指名混哪些特征)。**
这份协议规定这三张图怎么产生、长什么样、选完之后发生什么。总纲见 `docs/visual-first.md`。

为什么是图不是文字:文字提案里"视觉冲击型"和"信息清晰型"读起来都对,选完才发现不是想要的东西。
一张按真实文案、真实字体、真实比例渲出来的帧,用户 2 秒就能判断,而且它同时就是后面所有镜头的验收基准。

## 1. 三张图必须是什么

| 是 | 不是 |
|---|---|
| 目标画布尺寸的 PNG(默认 1080×1920) | moodboard、参考图拼贴 |
| 项目的**真实文案**(brief 里的标题、数字、结论句) | Lorem ipsum、"标题文字"占位 |
| 合同指定 kit 的**真实中文字体**,字形渲出来 | 系统默认字体、只有西文的示意 |
| 已下载到 `assets/` 的**真实素材**(logo / 截图 / 图片) | 灰色占位矩形、线框 |
| 一个真实镜头的代表帧(通常是英雄帧) | 色卡、字体样张、组件拼盘 |

三张之间必须在**构图、字体、材质、运动设想**四项上同时拉开。只换配色、只换字号的三张图不算三个方向,重做。
三张至少用到**两个不同的中文 typography kit**(品牌规范锁死字体时例外)。

**而且必须用本镜的真实中文句子把 display face 渲出来** —— 不是列一行字体名、不是拿"中文示例"占位、
不是只在小字号的正文里体现。**观众第一眼看到的那句中文,要以它在成片里的实际字号出现在 Styleframe 上。**

理由:字体选择的质量保证不能靠写理由,只能靠比较实际像素。2026-08-03 的 round-01 案例 03 就是反例 ——
合同选了五套里最中性的 `tech-data`,整条中文口播句落在等宽字体上,成片读起来像仪表盘;
而这个选择在流程里从未被任何环节质疑过,因为没有人把两套 face 的真实句子并排看过。
等宽字体只负责数字、时间和短标签,**不负责完整中文结论**。

默认三向(可按内容替换,替换要在 `proposals.md` 写理由):

1. **Brand Impact** —— 大字、品牌资产、强色块、高对比、明显的英雄构图。
2. **Editorial Cinematic** —— 摄影、拼贴、衬线或人文字体、编辑式版面、镜头运动。
3. **Digital Spectacle** —— UI、数据、网格、玻璃、3D、Shader、Kinetic Typography。

## 2. 文件名(精确,不许变体)

```text
projects/<name>/styleframes/
├── sf-1.png            方向 1 的真实渲染帧
├── sf-1.contract.json  方向 1 的候选合同
├── sf-2.png
├── sf-2.contract.json
├── sf-3.png
└── sf-3.contract.json
```

候选合同 `sf-N.contract.json` 与最终 `visual-contract.json` 用同一个 schema(`docs/visual-contract.schema.json`),
在候选阶段 `shots[]` 可以只放这一镜。三份候选合同必须都能通过
`node tools/validate-contract.mjs projects/<name>/styleframes/sf-N.contract.json`——渲图之前先过校验,
避免三个 worker 各自渲出好看但字段不合法的图。

## 3. 三个独立 worker

- 三个 `styleframe-worker` **并行**,每个只写自己的 `sf-N.png` 和 `sf-N.contract.json`,互不读取对方目录。
- 视觉导演给每个 worker 的 dispatch 必须包含:方向名、候选合同(kit / palette / density / material / motion)、
  要渲的那一镜的真实文案与素材路径、画布、以及"这张图要证明什么"。
- **dispatch 必须显式要求走两遍法**:`docs/visual-language.md`(签名元素、反模板)+ 调用 `frontend-design` skill
  (令牌方案:字号阶梯、间距节奏、层次对比)。这两条**不走 `route-knowledge.mjs` 的 token 预算**——
  预算是给镜头 worker 的,Styleframe 阶段还没有 dispatch manifest,审美层在这里是必读不是候选。
  worker 交付时要回一行 `two-pass:` 说明这两遍各定了什么,写不出就退回重做。
- worker 可以自选引擎(Remotion 或 HyperFrames)把这一帧做出来,选择写进候选合同的 `shots[0].engine`。
- 完成标准是**文件存在 + 校验通过 + 导演用 Read 看过图**,不是 worker 口头声称完成。
- 时间盒:活跃时间第 6–15 分钟。第 15 分钟仍没有三张合格图 → 熔断,用匹配度最高的已验证 preset / Registry block 补齐,
  并在 `review.md` 记这次降级。

## 4. 呈现与选择

呈现给用户的内容,只有三样:

1. 三张图(图本身,不是路径描述);
2. 每张一行的**隐藏设计摘要**(kit / 主色 / 密度 / 材质 / 运动性格,各一个词);
3. 一句推荐及理由。

**不呈现**逐镜文字计划、不呈现代码方案、不呈现风险清单——那些落进 `proposals.md` 留档即可。

用户可以:选一张;或说"用 2 的构图 + 3 的字体"这类混合。混合时由导演合成一份新的合同,
并把合成结果的来源写进 `proposals.md`(哪些字段来自哪张)。

**这是流程里唯一的常规停点。** 选定之后不再新增任何用户确认点;
付费外部生成的费用确认是既有授权规则,不算新增确认点。

## 5. 选定之后

1. 把选中(或混合出的)候选合同提升为 `projects/<name>/visual-contract.json`,补齐全部镜头的
   `id / durationSeconds / engine / objective / startAnchor / endAnchor`。
2. 跑 `node tools/validate-contract.mjs projects/<name>/visual-contract.json`,**不过不许派发 shot worker**。
3. 在 `proposals.md` 记录:三张图路径、各自设计摘要、用户选了哪张、混了什么、选择时间。
4. 合同冻结。子 agent 不得自行修改;需要改动时回报导演,由导演改并重新校验。
5. 选中的那张 `sf-N.png` 成为**视觉验收基准**:后续每镜的关键帧要和它对得上密度、层数、材质、字体和色彩关系。
   对不上就改画面,不许引用旧规则辩护。

之后的反馈循环里,只有"整体方向不对"这一类反馈才允许重新进入 Styleframe 阶段(重跑一轮三图);
"这里字太小""这个镜头节奏慢"属于直接改画面,不回到本协议。

## 6. 非交互与继承

先按内容设计最佳效果，再比较可满足的模板并推荐；模板同等最好可推荐复用。模板候选不等于已选路线，不能只因有候选免除设计；模板预览与定制候选可以同批展示，不增加审批轮。

| 场景 | 怎么走 |
|---|---|
| `$motion` 直接交互任务 | 完整三图 + 一次选择 |
| `$motion-srt` | 对**整片**做一轮代表性三图选择;选定后每镜继承同一份合同,不逐镜询问 |
| `$motion-broll` **已选原生 verified preset 的镜** | **不出三图**(版式/字体/材质/运动已被 preset 冻结,三向探索无处可探)。无有效已批准预览时，用本次真实文案渲一张 Preset Preview(时长 0.4 处)→ 整批拼成接触印张 → `preview-manifest.json` v2 记录 Remotion still 命令与 props/route/signals/still SHA 绑定 → **一次确认** → `validate-contract --require-preset-artifacts` 通过后才渲视频。两个 preset 一样合适就各渲一张让用户二选一。工具:`node tools/preset-preview.mjs <项目>` / `--confirm "<用户原话>"` |
| `$motion-broll` 被外部管线带合同调用 | 直接继承传入合同的设计、已选实现路线与视觉选择，不暂停、不重跑三图；不能重新匹配模板覆盖已批准 custom。已有有效 SHA 绑定预览回执时只校验并复用，跳过 expand-presets、预览重渲与重新确认；内容/props/preset 版本改变才重建并沿原有变更审批确认新版。纯搬迁且 SHA 不变仅更新路径引用/映射、保留证据后重验，不重复询问 |
| `$motion-broll` 直接交互批次、无合同、**有视觉未定的 custom 镜** | 无论是否有模板候选，为这些定制镜跑一轮三图,按代表镜出图,选定后这些镜继承;三图与接触印张**在同一条消息里一次贴出**,一批只打扰用户一次 |
| **上游预生产候选调用**(派发方注明「只出候选,不做决定」) | **渲候选图 + 候选合同就返回,到此为止。** 不打分、不自动选、**不冻结 `visual-contract.json`**、不渲逐镜关键帧。返回每张 PNG 绝对路径 + 一行设计摘要 + 一句推荐。选择由派发方那一层的真人做,选完会带着结果再派一次 |
| `$motion-broll` 非交互批次、无合同 | 视觉导演按 `docs/visual-first.md` 的评分表给三张候选打分,**自动选最高分那张**,并把三张图路径、各自得分、选择理由写进 `review.md` |
| 续做已有项目 | `visual-contract.json` 存在且校验通过 → 直接继承,不重跑;只有 `styleframes/` 没有合同 → 从第 4 节继续 |

自动选择不是"跳过 Styleframe":三张图照渲、照落盘、照记录,少的只是那次人工点击。
理由是外部管线没有可交互的人,不是因为这一步可以省。
(preset 镜同理:免掉的是三向探索,不是给用户看的东西——真实文案的预览照渲、照落盘、照确认,并保留 v2 绑定回执。
非交互批次用 `preset-preview.mjs --confirm "非交互批次自动确认:<依据>"` 盖章并写进 `review.md`。)

⚠️ **判"有没有人"要看整条链,不是看自己这一层。** 子代理内部永远没有人,照这个判法就永远自动选——
但真人可能就在派发方那一层等着看图。**上游预生产调用属于有人**,`/broll` 那种录完音批量跑的才是真的没人。
派发方在 dispatch 里注明「只出候选,不做决定」时,自动选择条款一律不适用,把选择权交回去。
(2026-08-10:`/package` 的调用一直被误判成非交互,用户因此从未见过三张候选,只看到已冻结合同渲出的关键帧。)
