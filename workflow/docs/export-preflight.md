# 导出前核对（2026-10-21 用户要求）

用户未指定降低分辨率时，默认保留主原片的显示分辨率。工程默认画布、代理尺寸和上一轮导出尺寸不是用户的输出要求；明确的目标画幅、裁切或交付规格优先。

1. 读取真实原片元数据（含旋转、像素宽高比、帧率）、最新保存工程和本次导出快照。对照原片显示尺寸、工程画布、输出尺寸及帧率，记录差异及依据。不要仅检查横竖比例；16:9 的 1080p 与 4K 仍有清晰度差别。
2. 没有明确降分辨率要求而工程低于原片时，先校正输出目标再导出。保持现有构图、字幕相对字号与位置、镜头曲线和手动删改；优先使用独立导出配置或可恢复副本，不能为升分辨率直接改坏当前工程。无法保持画面时说明具体限制，不静默降为 1080p。
3. 预览代理仅用于预览。正式成片读取原始媒体；不能把已有低分辨率成片放大后当作恢复原生画质。
4. 开始前用一句话告知实际输出尺寸、帧率和范围。有明确规格或合理默认值时直接执行，不增加例行确认。分辨率匹配不等于编码质量一致，另核对编码、码率或质量参数、色彩/HDR与透明需求。
5. 导出后核对实际宽高、帧率、帧数/时长、音轨、交付文件与渲染文件一致性及全片解码。实际结果与目标不符则不交付为完成。记录技术验收、画面抽查和真实连续观看/听审的各自范围。
6. 优化性能先查本次实际引擎、快路径拒绝原因、缓存命中及分阶段耗时。不能靠未经要求的降分辨率、降帧率、删字幕、删配乐或删镜头来宣称提速；短样本和历史工程的加速比不冒充当前全片实测。

回归案例：MVI_7521 原片为 3840×2160，而工程默认画布为 1920×1080，2026-10-21 导出沿用画布而未保留原片分辨率。此次失误必须在导出前发现，不能等用户查看成片后指出。
