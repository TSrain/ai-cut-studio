# 动画表达需求与模板应用标准（2026-10-13）

## 短视频的人物保留与阅读负担（用户 2026-10-16 纠正，优先）

适用于原生模板、定制动画及用户手动委托的 Claude；Codex 经用户明确授权临时代行外部动画角色时同样执行。这是创作与验收方法，不新增审批停点。

1. **先看真实底片。** 每一处拟配动画至少抽看对应口播的开头、中间、结尾，并记录源文件、实际秒点、截图和观察。手势、实物、机位或画面切换处加抽；必要时连续看该段。检查当前工程的剪切/变速/镜头推拉和已有叠层，不能只读 SRT、凭印象或统一版式决定构图。抽帧用于设计判断，不替代交付清单定位，也不冒充连续观看。
2. **先选真人关系，再选动画形式。** 明确选择纯真人、真人上轻量叠加、或复杂场景主导。简单概念、价格、关键词、个人体验默认保留真人；无需辅助就留白。实物操作、表情、手势及已拍证据不能因为能做动画就被盖掉。不是要求全部透明，也不是所有动画全屏。
3. **要么简洁有效，要么复杂且值得占屏。** 简单关系在真人旁用少量对象演示；复杂段落必须以具体对象、连续行为、空间或因果变化增加理解与观看收益。禁止简单图标铺满全屏，配标题、说明、进出场冒充演示动画。复杂场景占主要画面时，保留该时刻同步播放的真实人物圆角小窗，保留原色和口型；不使用静态头像代替，不遮挡演示重点和字幕。不得为了展示技术给简单内容硬做复杂场景。
4. **先说清关系，再用动作表达。** 先写一句观众要看懂的关系，再写起始状态、关键变化、结果。快慢要让同类任务的完成先后可见；远近让距离发生变化；因果让原因先发生、结果随后改变。图标加箭头只表示连接或方向，不自动表示效率、强弱或因果。不虚构速度倍数、精度、声学比例等实测结论；事实边界留记录。
5. **动画切入点围绕有效变化。** 铺垫时留真人，关键变化开始时再切入，切入即推进理解；结果看清后退出。不把整个字幕段时长当动画时长，不提前展示静态起始画面等口播三四秒。必要的短暂阅读停留可以保留，但不靠无意义漂浮、闪烁、循环填时长。记录切入锚点、首个有效变化、退出理由，并以实际播放节奏检查空等和信息过载。

   片头明确要加强吸引力时，先结合真实底片评估一次0.25–0.50秒的快速推近，让开头立即出现可感知的画面变化；需要时同步一声短促扫风/嗖声。保护首句人声、头顶、手势和实物，给近景安排合理回程；不是把整段口播加速，也不机械给所有视频套同一片头。
6. **限制额外阅读。** 观众同时听口播、看人、读字幕。辅助画面一次只增加一个重点，比较仅保留必要对象。删除导航、章节号、页眉、装饰分隔线、重复标题、副标题、无关解释。禁止“我更愿意直接说出来”一类擅改口播含义的标题。不添加为了安全显得周全的免责声明或解释性脚注；事实归属依靠原口播与真实素材，设计记录保留事实边界，不能靠小字补救误导的画面。
7. **看实际合成与运动。** 每段检查开始、变化、结果及退场，并以手机观看尺寸检查；叠层必须和实际底片、当前镜头和字幕合成。检查脸、手、设备、证据与字幕遮挡。问：不读说明能否看懂变化？是否必须占这么大？有没有提前进场静等？原视频是否更有价值？技术通过、代表帧目检、动态抽看、连续观看、听审、用户采用分别记录。

8. **审美单独验收。** 缩小、透明和少字不自动等于好设计。配色必须与本期实拍协调，不沿用上一版色板凑数；文字的基线、光学居中、内边距与视觉重心要实际检查，比较对象保持清楚的数字层级与对齐。真人、设备等可识别对象优先用真实素材；若用图形，比例、结构和轮廓必须可信，不能把临时手画路径当完成品。先检查手机尺寸下的真实合成，再判断能否交付；技术通过不抵消明显审美缺陷。

用户参考方向：能演示事情怎样发生的动画，而非带进出场的 PPT。复杂程度不是目标；有效表达与真人真实感共同决定是否值得制作。

## 竖屏素材、人物与字幕版式（用户 2026-10-20 纠正）

- 设计前使用现有 `design-md`、`frontend-design` 的层级、比例、对齐原则，并读 `hyperframes-creative` 的 `references/video-composition.md`；把视频画面与网页留白分开判断。需要参考时主动查找并实际查看相关案例或官方制作资料，记录来源与采用的具体手法，不能只列链接就称已经参考。
- 先确定本段真正的视觉主体。手机演示要让设备和关键 UI 在手机观看尺寸下可辨认；采访要看清人物。依实际源片裁切周边冗余，保留关键操作、脸和手，不用同一缩小窗口机械套遍横竖素材。
- 人物小窗和字幕须形成清楚的组合与阅读顺序。可根据素材用并排、叠放或其他适合的关系，不把素材、头像、字幕各自放一排后留下无用途的大空区。留白要能说明其作用：分组、呼吸、避免遮挡或平台安全区；不能用“高级感”解释无意义空洞，也不能加无关文字或装饰补洞。
- 已有定制背景是承托主体的品牌元素，不是缩小所有有效内容的理由。保留用户指定背景，但以真实内容占比、重心与可读性决定布局。
- 应用前先渲真实合成帧，覆盖本期不同素材比例、人物镜头和长字幕，在手机显示尺寸下目检；发现问题直接改版式。关键帧确认无明显缺陷后再导出整片，并检查入退场和相邻衔接。静帧、技术通过和连续观看分别记录，不新增用户审批停点。

## 完整 package 总入口

新 package/handoff 默认执行 `docs/complete-package-contract.md` 的 fullPackageVersion=1。本文件只限制动画语义和定制动画；Codex仍须具体设计并执行脚本审阅、节奏留白、镜头推拉、字幕、封面标题、声音和独立真实素材，不能在模板+Claude提示词后终止整期。各项带本轮设计、文件与工程回读；旧结果存在不算本轮执行，有理由留白/保留手调必须留报告，blocked为partial。完整worker在本任务内执行content-footage业务支线，独立子manifest发布父ResultStore并等宿主CAS回读，再完整汇总；此模式覆盖下文“完成后另派素材worker”历史机制。Codex不定制动画、不自动Claude、不新增审批；非动画可以自主设计并保留用户版本。

独立真实素材不属于本文件的动画限制：新 package/broll 的当前结果保存后由宿主默认派发独立 `$content-footage` 子任务，遵循 `docs/real-footage-contract.md`；worker 只交自身 manifest，不递归调用 footage 或混入其结果，历史任务不自动补跑。素材子任务全文逐段审、实际获取并推荐独立入轨；动画分支结束不跳过它。素材报告在 package Claude 提示词之前，素材与动画状态分别记录。

适用新 package、broll、handoff 的 semantic-template-v1 分支；它们完整执行下述规则后结束，不继续旧的理想画面/定制方案设计、动画内容审批、模板审批、Styleframe/接触印张与关键帧确认。设计依据为 `docs/superpowers/specs/2026-10-12-codex-claude-animation-workflow-design.md`。旧批准作品不自动重做，明确续作旧合同才使用文件后半历史分支。

1. Codex 先按完整口播意义单元分析动画必要性、表达目标、信息与关系、理解困难和事实边界，保留不需动画的真人段。此步骤不具体设计画面、场景、构图、状态变化、运动、二维/三维或预设动画秒数，不先以模板限制表达需求。
2. 分析后现读本地 MENU、preset 定义、详细说明和必要组件，建立可核查路径/SHA或版本的模板能力索引。匹配不仅看文字能否放下，还看模板真实表达能力、槽位容量、原生参数、运动行为、画幅/Alpha和时间限制。direct 直接应用；partial 有实际价值则作为可删除备选应用并明确差距；none 写缺口。状态 verified、源码或截图阅读不等于本期动态看过。
3. Codex 仅使用已有模板原生参数，不新增动画动作、改组件或结构；额外动画写成 Claude 提示词，由用户手动运行，不自动派发或等待 Claude。用户无需提供参考片，具体动画视觉由 Claude 自主设计。
4. package 通过 animation_package.py finalize 校验语义合同并生成总结，工程 worker 先合计划再追加原生模板，经 CAS 保存/回读；可用模板在当前工程时间轴和预览实际存在才算应用。无 SRT/真实时间只交有序计划、可预览信息及缺口，不伪造准确区间。原生模板不强制先渲视频；不把模板候选或任务提交说成已应用。
5. package 总结末尾唯一“给 Claude 的动画提示词”：公共说明含真实脚本/SRT/主视频/素材和当前规则的绝对路径，缺项说明；逐段有可整体删除边界，只交语义目标、上下文及事实约束。Claude 自读完整 SRT 决定设计、跨段拆合镜及时间，不以 Codex 模板区间约束，不默认附模板候选。Claude 交付真实媒体及 `animation-delivery.json`（`schemaVersion: 1`、`timeBase: "project"`；当前工程时间轴零点），每项包含 `file`、`startSeconds`、`durationSeconds`、布尔 `transparent`。文件可相对清单目录或为绝对路径；`projectId`、`sourceVideoSha256` 可选。起点、时长和跨段合镜由 Claude 自定，不必绑定原 shotId；相关段 ID 只作信息关联。详见 `docs/animation-delivery-manifest.md`。本期不沉淀公共模板，用户满意后另开任务。
6. broll 使用当前需求和共享真实时间轴执行模板、素材及其他授权支线，不另建提示词、不定制、不等待 Claude。有交付清单时以清单秒点为唯一定位依据，经不可变快照及文件、时长、工程边界等技术校验后，直接追加独立实例和最上方独立动画轨道；不重新按 SRT/模型/抽帧匹配，不检查是否符合原分镜或旧视觉形式，不为塞旧模板区间拉伸、循环、定格或裁剪。清单错误明确报技术错误，不静默退回识别猜位置。`transparent: false` 按完整画面覆盖人物画面并保留工程原声，允许视频自带人物；旧 overlay 要求不再强制其 Alpha。`transparent: true` 可核验实际 Alpha 并透明叠加，属于技术检查。仅无清单时走原探测、解码、抽帧和当前计划内容匹配；不能凭文件名或编号猜定位。保留全部旧模板、素材、手调、锁定和显隐，独立轨道供用户开关删除，不标最终采用。重复导入幂等，已删除/忽略不恢复，新版本独立追加，并发时重读并 CAS 保存。控制台制作计划可输入交付 JSON 绝对路径；CLI 使用 `--delivery-manifest`。直接导入媒体路径时，先在原媒体同目录发现 `animation-delivery.json` 再归档，避免相对文件引用丢失。清单导入不强制补 SRT、独立 ASR 或模型核验，也不新增动画审批。
7. 画幅来自实际主口播显示比例或明确目标，不默认 9:16；叠层保留人物主导，检查脸/手/字幕与可读性，无清单的 overlay 媒体实际 Alpha 并检查真人合成；清单媒体按 transparent 声明检查技术条件，不以旧分镜形式判定接入资格。来源真实性、时长、内容边界、共享转写与技术门禁保持。模板仅技术通过不代表实际观看或最终采用；连续播放、听审和全期验收分别报告。非动画必要输入确认继续。
8. 所有可独立任务连续做到完成；结果给控制台和总结入口。只将实际应用、提示词就绪、待外部媒体与具体技术/输入缺口分类报告，不用动画 waiting_approval/waiting_selection 当交付停点。

## 历史最佳效果设计合同（仅明确旧合同续作）

# 动画设计与质量目标

用户 2026-10-11 再次确认：package、broll 优先奔着效果最好做；在最佳效果设计的基础上，模板能满足就同时给模板方案。未来题材不限，不要求用户提供参考片，以行业标杆为创作目标。

本文件适用于 package、broll 及其 visualization 派发。它覆盖旧的“先匹配槽位再想画面”“槽位装得下就必须用模板”“verified 无须检查本次动态效果”以及超时或修复次数耗尽后自动降质交付的规则。既有内容审批、真实时间轴、素材真实性、画幅、冻结合同与技术门禁继续执行；已批准作品不因本规则自动重做。

## 1. 先设计表达，再决定实现

每镜先回答：观众需要理解什么？画面用什么具体对象和关系表达？注意力怎样随口播移动？

先独立设计本段效果最好的表达：写出具体主体、关系、视觉焦点、**起始状态 → 关键变化 → 结束状态**，说明画面如何跟着口播推进，再读实时模板菜单寻找实现路径。不能从现有槽位倒推创意，也不能为了省事将机制演示缩成标签轮播。动作必须推进理解，例如拆层解释组成、局部展开解释因果、元素沿路径移动解释流程、同一对象变形解释变化。

方案选择先比较理解效率、视觉表现力、语义节奏、可读性、真人关系与本期一致性，再在效果相当的方案间考虑实现成本和复用。效果更好的定制是正常首选，不必等模板失败；模板同样达到最佳效果时可推荐模板，不为“定制”而增加动作或复杂度。已有明确预算/期限时说明它对效果的真实影响，不能静默降低目标。

复杂不等于优秀：简单强调可以用文字，复杂关系才用空间、镜头或多阶段变化；按内容选择真实素材、二维图形、排版、示意图、数据图、2.5D 或 3D，不把某个博主的霓虹、黑底、透视复制为所有话题的固定风格。统一的是本期视觉语言，变化的是具体表达。

## 2. 在原分镜审批中说清模板与定制

对需要动画的镜头，在 plan.md 中提供以下信息，并把已选结论及理由带进 keyframe brief、冻结合同和后续 motion brief：

| 项目 | 必须说明 |
| --- | --- |
| 最佳效果主方案 | 具体对象、起始状态、关键变化、结束状态及对应口播锚点；说明为何适合本段，而非只写“高级/科技感” |
| 可行模板方案 | 现读菜单得到的真实 preset ID；对照主方案说清语义、动作、构图、节奏和风格能保留什么；没有合适模板就明确写无 |
| 定制方案 | 需要新做的场景、对象运动或镜头变化；相对模板的具体收益和制作负担 |
| 推荐 | 选模板、复用组件定制或完全定制，并解释理由；无收益的定制可写不建议 |
| 关键风险 | 尚缺的素材、未验证能力、影响交付的实现条件 |

先展示最佳效果主方案，再并列展示可行模板方案；可以在同一次分镜提交中给出，不必先排除模板才能提定制，也不必先批准主方案才展示模板。模板与主方案相同就明确写“同效果，可直接复用”，不虚构第二套。仅部分满足的模板只能标为有明确损失的备选，不能称等效。候选存在、状态 verified、技术展开通过，都不等于本期已选择它。

两条方案是供判断的实现比较，不自动制作两套视频，不增加逐镜确认轮次。模板/定制与动画/真实素材是两种不同选择，沿用原分镜审批整批呈现。用户选一套就生产一套；明确两套都做才分别生产并标识版本。简单且完整适配的镜头可简写，核心解释镜头必须写具体差别。内容批准后的视觉候选也按已批准范围同批展示，不偷偷把定制换为模板。

模板匹配必须同时满足 **语义关系、对象结构、构图、运动过程、口播节奏、视觉风格**。文字槽放得下仅是技术条件。需要的拆解、变形、连续镜头或材质表达超出模板时，即使文字能装下也不能判为完整命中。

继续填写现有 presetCandidates、selectedPreset、matchReason、unmatchedReason；理由覆盖上述差异。`presetCandidates`/`templateOptions` 记录比较，`selectedPreset` 只记录当前批准方案实际采用的原生模板。定制时为 null，`unmatchedReason` 说明本次未选模板的效果理由，不必谎称目录里完全没有可用模板。需要修改组件或增加动作的镜头按 custom 路径制作和验收，可复用现有组件，不冒充原 verified preset。无需定制时可选择合适模板。

冻结后 broll 执行已批准设计、对象变化和实现路线，现读目录用于检查能力与依赖，不能重选路线。新模板更省事、工期紧、渲染失败均不构成改回模板的授权。实质变更效果或路线回到原方案变更审批；保持批准表达的实现修复直接继续。

用户在同批并列方案中明确选模板或定制，就已授权对应路线；按这次选择保存所选分镜、设计摘要与批准记录，不复用另一套路线的旧摘要，也不再为同一选择重复询问。未选方案仍作为备选留存，不混进正式合同。

## 3. 用户无需提供参考片

Codex 负责提出视觉概念和设计依据，先从内容中的因果、比较、时间、空间、层级或操作关系出发。核心镜头内部至少比较两种不同表达，择优推荐；不能只比较同一排卡片的不同颜色。

需要陌生题材的视觉知识或声称对标具体作品时，由 Codex 主动查找并实际查看相关公开作品或专业资料，记录来源和可迁移的手法。不得把“请给参考片”作为普通开工条件，不读取仓库 benchmark 资产充当生产输入。无法查看的参考明确记未核验，不能声称已对标。

参考服务于表达：可以吸收构图、节奏或空间手法，但独立设计本期内容；不要求每个镜头找一条参考，不照抄无关装饰，也不虚构截图、数据或证据。

## 4. 质量靠实际画面验收

“行业标杆”是持续追求的目标，不是自动授予的验收标签。评分、模板 verified 状态和文件校验都不能证明本片的艺术质量。

package 检查真实渲染的关键帧及设计的状态变化；核心多阶段镜头至少查看起始、关键变化、结束的实际画面，不能只靠最漂亮的一张代表帧。明确动态尚未验收；保持 keyframes-only，不为检查提前渲最终 MP4。broll 按真实录音执行，验收全部交付镜头的连续播放；叠层看真实口播合成，整段看相邻镜衔接。verified 模板可复用技术验证，但本次内容的节奏、可读性和合成效果仍需实际查看。

关键动作按批准的语义锚点落到真实时间轴，记录秒点来源与核对状态。长句按字数插值仅为初排，不是逐字对齐；音画时间原点有偏移先核验，不能用“文件时长相近”代替。动态播放、原声/音效听审、手机尺寸可读性分别记录；工具只能返回间隔截图或无法听到声音时对应项保持待验，不能把播放器结束或技术 PASS 写成完整质量通过。

逐镜给出有画面依据的结论，至少检查：

- 表达：不用重复念屏幕文字，是否也能看懂核心关系；动作是否增加理解。
- 设计：焦点、字号、留白、色彩、材质、层次是否协调，人物与字幕是否被干扰。
- 动作：加减速、错峰、停留和镜头运动是否有目的；能否连续看清，是否存在突兀跳变。
- 节奏：揭示时点是否绑定口播，是否留足理解时间，前后镜是否流畅。
- 一致性与真实度：整期视觉语言一致，证据和素材准确，复杂程度符合内容。

发现缺点必须关联具体帧、动作或时间段，修复后重看。未能播放、只有抽帧或缺少合成预览时写清未验收范围。时限和修复轮数用于暴露进度与成本，不授权将未达标作品宣称完成；无法继续时交当前草稿、缺口和下一步，不静默降低已批准的表达。

## 5. 跨仓库执行

package 的 keyframe brief 与 broll 的 motion brief 均附本文件绝对路径，要求 visualization 读取；保留每镜理想过程、模板差距、所选路线和质量风险。visualization 负责具体视觉实现与验收，上游负责检查回执是否保留批准设计。文字规则更新不等于渲染能力提升，不能据此声称现有作品已经达到目标。

## 6. 创作限制取消（用户 2026-10-12 明确授权）

不再用 hybrid 三镜/full 半数限制动效，不再要求金句只能定格或减法，不再限制意象只能一次，不再要求按固定素材来源顺位逐项排除。按每镜表达价值、整片节奏、读懂时间与真人关系设计。先独立设计最佳效果，再比较满足目标的模板/定制和真实素材方案；不能以取消限制为由自动堆动画。

证据真实性、实际画幅、同步、可读性、full 无真人定义、本期内容审批及真实播放验收继续执行。批准本批限制移除不等于批准任何本期分镜或实际成片。
