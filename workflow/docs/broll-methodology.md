# 口播视频 B-roll 方法论

> 2026-10-08 运行边界：produce 只写口播，所有开头与逐镜画面由 package 设计。动画与真实素材按 `docs/broll-parallel-options.md` 并列选择，后文旧的“动效优先”或固定路线排名示例不能覆盖该用户新约定。实际画幅以根 AGENTS 和 §13 的主视频探测为准，竖屏安全区只适用于竖屏。

> 只写当前生效的判据。改判据直接改这里，不留修订史。
> 冲突时以影视／广播教材和同行评议研究为准；横屏长视频博主的风格主张（Schiffer / Hillier-Smith / Abdaal）不得用来推翻教材。标「经验值」的条目未经验证，可被实测推翻。
> 写稿与分镜的必读范围是 §1–§2；其余按需查。

---

## §0 核心认知

**不是"根据文案找画面"，是"根据这句话在叙事中的功能，决定观众此刻该看什么、理解什么、感受什么"。**

所有 B-roll 错误——泛用空镜、素材库感、画面很贵但信息为空、每句都配图——根因都是跳过"这镜为什么存在"，直接跳到"这镜怎么做"。

不存在"每三秒切一次"这种公式。控制的是信息节奏、视觉功能、注意力变化，切镜频率只是结果。

## §1 十种功能：这镜为什么存在

任何要配画面的点，先回答它属于下面哪一种。**答不上来的，不配画面。**

| 功能 | 判据 | 典型配法 |
|---|---|---|
| `解释` | 把仅靠语言难懂的内容变成可见结构 | 流程图、时间线、对比图、步骤逐个叠加 |
| `证据` | 为事实性陈述提供可验证的实物 | 文档原文截图并高亮、产品录屏、数据表、官方公告、终端日志 |
| `具象` | 把抽象说法落到一个可被指认的场景 | 真实截图 > 实拍 > 库存视频 |
| `隐喻` | 用一个物理关系映射一个抽象关系 | AI 生成最适合承担的就是这一类 |
| `情绪` | 不增加信息，只改变观众情绪状态 | 必须和音乐、环境音、明暗共同工作，单靠画面无效 |
| `重置` | pattern interrupt：换一次视觉模式 | 半身切特写、画面静止、字号骤变、抽掉一秒音乐 |
| `定场` | 先给全貌再给局部，观众得先知道在看什么 | 先完整文档页 0.5–1 秒，再推到高亮那行 |
| `对位` | 画面与话语相反或有张力，让观众自己得出第三层意思 | 口播"每家公司都说在用 AI 提效"→ 一屏没人看的 AI 周报 |
| `遮盖` | 这镜存在的理由就是盖住剪辑点（口误、重录、变速） | 从当前场景已有的东西里挑，不为它找新素材 |
| `节奏` | 这镜存在的理由就是节奏需要一次变化，无新增信息 | 优先零素材成本手段：换景别、静止、字号变化 |

**功能的硬约束：**

1. **证据位必须能说出来源**（哪份文档、哪个页面、什么时候）。
2. **AI 生成画面、库存视频、无出处网图，禁止进入证据位。** 这不是排最后，是禁止——AI 生成在功能上等同于重演，用它举证就是拿假东西当真东西。
3. **重演／演示性画面必须让观众看得出是演示**，不能伪装成实录。检验问题：如果观众知道这段画面是怎么来的，他们会怎么说？
4. **证据画面不中立**：你截哪一帧、高亮哪一行本身就是论证，选材要经得起"你为什么截这一段"的追问。
5. **`重置` 有上限**：核心结论、情绪转折、反常识判断、结尾 CTA 这几类句子上禁止使用 `重置`——不许为了防划走在情绪高点上做视觉打断。同一种打断手法在一条片子里第三次以后基本失效（定向反应会习惯化），手段要轮换。
6. **`对位` 慎用**：一条片子最多 1–2 次，且必须让观众不看解释就能感知到那层反讽；感知不到就只是画面跑题。
7. **竖屏的 `定场` 不是广角**：9:16 里广角失效（横向视野被裁、既看不清主体也交代不清空间）。竖屏定场是"先给完整对象，再给局部"——完整界面／完整图表／完整文档。

## §1.5 十二个动作：这几秒画面上做什么

功能回答"这镜为什么存在"，动作回答"这几秒画面上发生什么"。**两格都要填**，缺了动作会稳定退化成文学意象——句子很美，但观众看到画面那一秒画面本身什么也没说，得靠口播解释才成立。

有效的镜长这样：*两个一样的 `$2,000`，一个买下十项数学突破，一个只够养一个博士生一个月，中间落一个等号*。差别不在审美，在它有一个动作，不需要解释就能看懂。

| 动作 | 画面上发生什么 | 典型承载 |
|---|---|---|
| `对比` | 两个东西并置，观众自己看出差别（分屏／并置／等号） | 数据、判断、两条路线 |
| `数字` | 一个数出现、滚动、放大定格，成为画面主体 | 成本、比例、规模 |
| `前后` | 同一位置的状态被替换（before → after） | 改动效果、演进 |
| `清单` | 多项逐个入场或逐个点亮 | 枚举、维度、条目 |
| `流程` | 按因果顺序一步步推进 | 机制、步骤、循环 |
| `时间线` | 沿一条轴移动或标点 | 历史、节奏、里程碑 |
| `增长` | 量的累积或坍缩（柱子长高、曲线上扬、进度条） | 趋势、规模变化 |
| `偏离` | 一条路径或预期走向错误方向 | 风险、失控、反直觉 |
| `圈注` | 在一张真实画面上指出某一处（高亮／圈红／推近） | 截图、录屏、文档取证 |
| `定格` | 画面停住、清屏、只留一个东西（减法） | 金句、结论、情绪落点 |
| `实录` | 让观众看一段真实发生的事，不加额外动作 | 录屏、实拍、公开影像 |
| `意象` | 靠联想成立的隐喻或氛围画面 | 语言解释不动的抽象关系 |

**动作的硬约束：**

1. **`意象` 不设数量上限。** 每镜说明其隐喻关系及理解价值，不能用无关氛围填时间。
2. **`证据` 功能不得配 `意象` 动作。** 靠联想成立的画面举不了证。
3. **`圈注` 收益最大，优先用。** 把观众视线引到画面正确位置（signaling，对低先验知识观众效应最强），实现是 visualization 的 `tools/locate.mjs`。凡是证据类截图、录屏、文档，**默认配 `圈注` 而不是 `实录`**。

动作和功能是两个独立维度，不互相推导：同一个 `证据` 可以走 `圈注`（指出哪一行）、`数字`（把关键数放大）或 `实录`（让操作自己跑一遍），选哪个取决于观众此刻该看清什么。

## §2 五个必须避免的错误

### 错误一：逐句配图，把名词翻译成画面

说到"数据"就配数据可视化空镜，说到"团队"就配开会画面。**这类画面信息量为零，禁止。**

口播插片也不要变成逐句贴文字：一镜先提炼一个核心命题，再用图形关系、局部强调或氛围表达。常规只保留一个短标题和至多三个关键词；确有必要的枚举另论。能用节点网络表现整体与局部，就不要再塞目录和文档正文。用户的真实产品结果优先使用真实录屏。

一级章节导航与其下的具体案例必须使用有明显区分的视觉结构，不能只换文案继续套同一个模板。核心总结适合用退让式强调提炼关键词。默认不加全画幅边框、底部装饰色块，也不为满足强调色面积或占屏指标填充无意义元素；已确认的视觉方向优先。

**每镜先选呈现方式，再选动画。** 短标题、关键词、简单工作类别卡片、图标说明优先做 `overlay`，保留口播人物；复杂空间关系、需要观看的证据或有意的章节重置才做 `immersive`。导航不是必须全屏，按当下叙事选择。brief 写明 `presentationMode` 和理由，叠层尺寸来自真实口播视频，不照搬旧 B-roll 画幅。

`overlay` 是真正透明背景上的清晰图文，必要时用局部半透明深色承托和柔和阴影，不是把整张全屏页面降低透明度。必须在真实口播上检查人脸、手势和现有字幕，不用全屏墨量门槛逼迫辅助图文变大。

**开场强调文字不得预埋。** 逐镜检查首帧和对应口播开始点，文字按语义锚点淡入/轻移/遮罩展开；不能只在第 0 秒播放一个装饰动作，却把结论提前放在那里。后文才说到的结论必须等到对应句子。工作类别用直白短标签就能理解时，不强行发明需要观众猜的模拟或隐喻。

泛用空镜的问题是它是一次**不相关切换**：观众被迫为一个不带新增信息的画面重建视觉表征，花了认知成本什么也没换回来。实验证据是不相关切换**降低**记忆，而相关切换（同一场景内换景别／角度）**提高**记忆。问题从来不是"切得多"，是"切到了和当前叙事无关的东西上"。

第二条理由：与目标无关的画面会挤占理解带宽（coherence principle，加入"诱人细节"后成绩下降）。注意边界——这类研究测的是理解，不是完播。

全覆盖模式不是本条的例外：全覆盖要求画面无空档，不是每句一镜，见 §11。

### 错误二：照搬广告式 B-roll 质感

镜头运动＋匹配转场＋声音设计那一套是为产品、食物、商业短片设计的。我们的内容是 AI、商业、认知、方法论，直接照搬的结果是：画面高级、信息为空、每个镜头都很重、注意力从观点转移到画面、内容显得像课程广告。

**素材投资优先级：信息理解 > 观点可信度 > 节奏 > 情绪 > 画面精致度。**

这条链只管"时间／预算只够做好一件事时先做哪件"，即这一镜投多少成本、做成什么素材。**它不是切点判据**——那一刀该不该落在这一帧，用下面错误四的 Rule of Six（那里情绪排第 1）。

### 错误三：脚本本身每句话权重一样

根因往往不在剪辑，在文案：句子太书面、缺具体案例、没有结论或冲突。脚本每句权重一样时，AI 只能用更多画面制造假节奏。**这时该改的是脚本，不是加画面。**

### ⚠️ 两个目标别混用规则

| | 追求什么 | 怎么衡量 | 观众状态 |
|---|---|---|---|
| **让人听懂** | 理解、记住 | 事后能复述、能应用 | 想学 |
| **让人不划走** | 完播、留存 | 留存曲线、完播率 | 随时可能走 |

这两个目标会冲突：加入生动但与主题无关的细节会同时**提高兴趣评分、降低学习成绩**，而抖音要的更接近兴趣评分。由此两条纪律：

1. 多媒体学习／认知负荷那套理论只能解释"为什么这个画面让人看不懂"，**不能**解释"为什么这个画面让人不划走"（它的因变量全是测验分数，且明确排除动机变量）。
2. **一个设计在买哪个目标要说清楚，不许两个都声称**（典型见 §5 开头 0–5 秒）。

### 错误四：按固定时间插 B-roll

"每三秒切一次"只能当粗略节奏提醒。合理切点来自五类变化，**按意义单元切，不按秒数切**：

1. **观众此刻应该处于什么状态发生了变化**（排第一）
2. 观点发生变化
3. 句子出现关键词重音
4. 因果关系进入下一步
5. 当前画面已完成信息使命

依据是 Murch 的 blink theory（人在一个完整思绪／情绪结束时会眨眼，剪辑点应落在观众"思绪换挡"处）与 Rule of Six 的取舍序：

| 序 | 判据 | 权重 |
|---|---|---:|
| 1 | **Emotion**（观众此刻该有什么感受／状态） | **51%** |
| 2 | Story（是否推进叙事） | 23% |
| 3 | Rhythm（时间上对不对） | 10% |
| 4–6 | 视线连续 / 平面连续 / 空间连续 | 7 / 5 / 4% |

emotion **不是煽情**，是"观众此刻应该处于什么状态"：困惑被解开、意识到自己错了、被反常识击中，都算。**Rule of Six 是取舍序不是六选一**，大多数情况六条能同时满足，权重只在冲突时裁决。

### 错误五：镜头时长与它承载的信息量不匹配

**判据一句话：镜头时长 = 观众读完它所需要的时间。**

- 一个画面 1 秒就读完却留 3 秒 → 浪费，观众开始等。
- 高密度截图／图表只给 1.5 秒 → 必然读不完，等于没配。
- 一个画面**持续在提供新信息**（元素逐项入场、数据逐个点亮、镜头缓推、结构逐层展开）→ **可以任意长**（§11.1 的 bed shot 就靠这条成立）。

另有一条执行层约束（只约束 AI 生成素材，不约束录屏、截图、自制动画）：AI 生成视频超过数秒容易结构崩坏、动作重复、细节漂移，参数见 §10.3。

### 错误五之二：切到"和当前叙事无关的东西"上

有害的不是切得多，是切到哪儿：

| | 效果 |
|---|---|
| **相关切换**（同一场景内换景别、换角度、推近拉远） | **提高**对内容的记忆 |
| **不相关切换**（切到一个新场景／新对象） | 引发定向反应、要求重建心理表征，**降低**记忆 |

所以"只换景别就是一次完整的视觉变化"（§4）是对的：它是相关切换，还零素材成本。`遮盖` 和 `节奏` 这两个功能本来就不承载新信息，**必须优先用换景别**，用不相关切换是纯亏。

执行细节：换景别要**至少差两级**（全景→特写，不是全景→中全景），否则是同轴跳切，看起来像穿帮。竖屏里更刺眼，因为主体几乎总在画面中心。

## §3 五层分层系统（不要统一叫"B-roll"）

| 层 | 内容 | 作用 | 使用原则 |
|---|---|---|---|
| **A 人物口播** | 正脸出镜 | 建立信任、传递态度、承载最重要判断 | 核心结论 / 反常识观点 / 直接反驳 / 价值判断 / 情绪转折 / 最终总结——**这些句子不能被画面全覆盖**，否则观众只记住画面，不记得是谁说的 |
| **B 证据素材** | 产品截图、文档、数据、新闻标题、官方声明、软件操作、代码与 Agent 日志 | 解决可信度 | **最该增加的一层**：讲 AI 与商业认知，观众第一质疑是"这是不是你瞎总结的" |
| **C 解释动画** | 流程图、时间线、对比图、结构拆解、数字变化 | 降低理解成本 | 只有真正需要整屏演示的机制才做全屏；单点数字／对比做成**画中画贴纸** |
| **D 具象补充** | 实拍、素材库、库存视频 | 让抽象落地 | 必须能说出它图解的是哪句话的哪个概念 |
| **E 隐喻／氛围** | AI 生成的概念画面 | 处理抽象关系与情绪 | 按隐喻适配与表达效果决定，不设固定用量或来源排名 |

全覆盖模式下 A 层不存在，替代方案见 §11.2。

## §4 节奏的四个可变量

节奏不等于切镜频率，来自四类变化的组合：

1. **信息密度**——每个意义单元给出一个新增信息点。
2. **意义单元切点**——见 §2 错误四的五类触发。
3. **视觉变量**（不必每次换整个画面）：人物景别 · B-roll · 截图 · 动画 · 大字 · 构图 · 明暗 · 运动方向。
   > 只换景别（半身↔特写）就是一次完整的视觉变化，零素材成本。**这是最被低估的手段。**
4. **声音节奏**——常比视觉更能制造速度：关键词 hit / 滑动声 / UI click / 转折 riser / 短暂抽掉 BGM / 环境声进入 / 低频冲击 / 音乐段落变化。声音不是最后补上去的装饰，是连接动作和转场的结构。

## §5 密度建议（本账号内容类型，经验值）

> **这些是观察到的结果范围，不是要凑的目标。不许为了够次数硬切。** 切点由 §2 错误四决定，密度只是那些判据作用之后的产物。未做过 A/B 验证，可被实测推翻。

### 开头 0–5 秒

目标：**让观众不划走**（不是"让观众马上理解冲突"）。

- 视觉变化 3–6 次，每个画面 0.5–1.5 秒
- 优先用：人物特写、结果画面、反常识大字、强对比证据
- ❌ 不先铺氛围；❌ 不先展示慢动作键盘、办公室空镜、城市空镜

> 例：口播"Skill 装得越多，AI 可能反而越笨。"
> 画面：① 人物正脸说"装得越多" → ② 屏幕上技能列表高速增长 → ③ 系统响应变慢的真实录屏 → ④ 大字"越装越笨"

**开头这几秒的画面必须在写稿阶段定下来**，不能留给 `/package`：开头的话和开头的画面是同一个决定。同样讲那十项数学难题，画面定成「`$2,000` 砸出来 + 切近景」，第一句话就得写成能接这个动作的话；等到分镜阶段才想画面，话已经录完了，只能往话上贴画面。所以写稿契约对前 3 秒是硬要求（见 writing-scripts skill），而不是"需要才写"。

**这套参数在买什么**：快节奏叠加高唤醒内容会**降低**观众对具体内容的记忆。这不必然是错的——开头目标只是留人，牺牲内容记忆是划算的交换；但要认清这笔交换，**理解发生在主体段落，不在这里**。

### 主体段落

- 每个意义单元一次视觉变化
- 核心结论句保持人物出镜
- 证据类画面给足够看清的时间（截图类可略长于隐喻类）

### 结尾

- 行动号召／总结**回到人脸**，不被 B-roll 盖住

全覆盖模式下"保持人物出镜""回到人脸"无法执行，替代做法见 §11.2；密度数字同样是结果范围不是硬参数。

## §6 分镜表标准格式

| 时间 | 口播原文 | 是否配画面 | 功能 | 素材类型 | 画面描述 | 时长 | 切法 | 声音 | 禁止项 |
|---|---|---|---|---|---|---|---|---|---|
| 00:00–00:02.1 | Skill 装得越多，AI 反而越笨 | 否 | — | 人物特写 | 正脸，字幕大字"越装越笨" | 2.1s | — | glitch | 不出现机器人 |
| 00:02.1–00:04.0 | 因为每个 Skill 都在增加约束 | 是 | 解释 | UI 动画 | 规则模块逐个叠加，模型可行动空间缩小 | 1.9s | 匹配切 | click×3 | 不用锁链隐喻 |
| 00:04.0–00:06.5 | 就像把赛车发动机装到拖拉机上 | 是 | 隐喻 | AI 视频 | 赛车发动机安装进老式拖拉机，拖拉机缓慢行驶 | 2.5s | 动作切 | 引擎声转弱 | 不出现文字 |

关键列：**「是否配画面」允许为"否"**——这一列存在本身就是在对抗"每句都得配图"的惯性。

### §6.1 「时间」列不能在录音前填

| 列 | 什么时候能定 | 谁定 |
|---|---|---|
| 口播原文 / 是否配画面 / 功能 / 素材类型 / 画面描述 / 切法 / 禁止项 | 定稿之后 | `/package` |
| **时间 / 时长 / 声音卡点** | **只有口播录完才能定** | `/broll` |

字数换算出来的秒数不是秒数：按 `config/platforms.md` 的 3.9–4.9 字/秒估，同一份稿子的误差可以到一倍。拿这种数派动效，渲出来的整数时长跟录音里那句话占多少秒毫无关系，剪辑时只能返工。

```
定稿 → /package：切镜、判功能、写创意方案、渲关键帧静图、冻结视觉合同
     ↓（录终稿口播）
录音 → /broll：妙记出带时间码逐字稿 → 和定稿模糊对齐 → 每镜拿到三位小数的真实 in/out
     → 按真实时长出成片、筛素材、选曲卡点
```

对齐容忍口误和临场加词（difflib 的 equal 块天然跳过增删），对不上的镜明确告警而不是瞎猜。**功能在 `/package` 冻结，`/broll` 只按真实时长执行、不重判功能。**

## §7 素材选择：效果适配与证据真实性

素材类别不表示固定优先级；按准确表达、构图/动作、可读性、真实性和实际获取条件比较合理候选，不强制逐项排除个人素材、录屏、官方影像、动画、图库或 AI。

证据位仍必须提供可独立核验的真实来源：一手实拍、产品界面录屏、日志、官方文档或有出处公开影像。库存泛素材、AI 虚构画面及无出处网图不能充当证据；重演/演示须显式披露。隐喻不是证据。

非证据位允许真实素材、解释动画、图库与 AI 概念表达，按本镜效果选择；动画和真实素材并列比较，用户可选一种或两种。没有准确表达价值的装饰不因来源便宜而采用。

## §8 视觉方案派发用的系统提示词

```
你是一名擅长抖音知识口播、商业内容和 AI 内容的高级视频导演与剪辑师。

你的任务不是逐句配图，也不是尽可能增加 B-roll，而是为口播稿设计一套
信息清晰、节奏快速、风格统一的视觉剪辑方案。

【核心目标】
1. 帮助观众更快理解观点。
2. 为事实和案例提供真实证据。
3. 在注意力可能下降时改变视觉模式。
4. 保留人物口播的信任感和个人辨识度。
5. 避免素材库感、廉价科技感和明显 AI 感。
6. 视觉不能抢夺口播内容本身的注意力。

【决策顺序】
处理每个意义单元时，依次判断：

1. 这句话在文案中的功能是什么：

2. 观众此刻最需要：
   看见讲述者 / 看见事实证据 / 看懂关系或过程 / 看见具体场景 /
   感受情绪 / 获得一次注意力重置

3. 据此选择层级（A 人物 / B 证据 / C 解释动画 / D 具象 / E 隐喻），
   并按表达效果与真实性选择实现方式。

4. 如果以上都答不上来 —— 不配画面，保持人物出镜。
```

```

视觉系统：光线、色调、材质、现实程度

```


## §10 执行层：AI 生成的可控性技巧

决策做完之后的执行细节。决策错了，这些技巧一个都救不了。

### 10.1 首帧锚定法（可控性最大的单点杠杆）

1. **先文生图**产出首帧：构图、主体、风格、色调在这一步定死（图比视频好挑好改）
2. **再图生视频**，提示词只描述"从这张图开始怎么动"
3. 跨镜一致性：每段都重复 `@图片1 锁定主体身份，背景保持不变`，写一次不够
4. 支持首尾帧的模型，首尾帧都给定

### 10.2 镜头四轴：每镜最多动两轴

| 轴 | 含义 | 范围 |
|---|---|---|
| Z | 景别/距离 | Z1 大特写 → Z9 大远景 |
| Y | 高度/角度 | Y1 仰拍 → Y7 俯拍 |
| X | 机位方位 | X1 正面 → X4 背面 |
| F | 焦段+景深+畸变+构图 | 写"85mm"不写"长焦" |

**三轴同动 = 失控。** 未指定时默认：Z4 + Y4 + X2 + 50mm + 浅景深 + 缓入缓出。

### 10.3 长度经验值

- 提示词 300~500 字符往往优于 1800+ 字符——过度精细的提示词是噪声
- 图生视频的稳定甜点是 **5 秒以内**，超过 10 秒基本无意义
- 我们的单镜本来就 2~3 秒，天然落在模型最稳的区间

### 10.4 失控模式自检

| 现象 | 原因 | 解法 |
|---|---|---|
| 人脸/主体崩坏 | 近景 + 大幅旋转 | 拉到 Z4 以上或减小旋转 |
| 主体像石像 | 没写动作 | 显式写身体节奏——**不写动作 = 不动** |
| 段间色调漂移 | 无统一氛围声明 | 每段重复风格锁定句 |
| 构图被裁 | 16:9 图去生 9:16 | 生成前明确画幅与裁切策略 |

### 10.5 拿到素材之后

1. 每条 AI 片段**头尾各剪 0.5~1 秒**（转场处最不稳）
2. 锁一条参考片，其余向它调色
3. 转场只用硬切 / 匹配剪辑 / 叠化
4. **0.3~1 秒快切能掩盖 AI 细微畸变**——与快节奏天然互补
5. 按目标时长的 **2~3 倍**生成备选

## §11 全覆盖模式（无真人出镜）

可选形式，不是默认。`/package` 收到 `全broll` 时启用，写进 `shots.json` 的 `coverage: "full"`，`/broll` 读它执行。默认仍是 `hybrid`。

### 11.1 全覆盖 ≠ 每句一镜

全覆盖的定义是**画面无空档**，不是镜头数按句数翻倍。§1 的功能判定仍是唯一准入，"先判功能再选形式"一个字都不放宽。

差别只在兜底：混合模式下答不出功能的句子回落到真人出镜；全覆盖没有真人可回落，这些句子由**上一镜的持续画面继续覆盖**——

> **持续画面层（bed shot）**：一个视觉横跨 3–5 句持续演进，靠元素逐项入场、镜头缓推缓摇、数据逐个点亮、结构逐层展开维持推进感，而不是切到新画面。
> 判断标准仍是那一条：**新配一镜必须说得出它比"让上一镜继续演进"多解决了什么**。说不出就不切。

镜头数上限按意义单元定（§4、§5），**不按句数定**。逐句配图在全覆盖下破坏力更大：混合模式里还有真人镜稀释，全覆盖里就是一整条 PPT 翻页。

### 11.2 重音由表达设计决定

核心结论、情绪转折、反常识判断与 CTA 可用定格、清屏、留白，也可用有目的的元素运动、镜头变化或人物后方强调。减法是候选手段，不是金句硬门。按口播语义与阅读负荷设计声音，避免画面抢走观点。

### 11.3 全覆盖的素材选择

full 保持无真人、画面无空档的定义，但不限制动效占比或隐喻次数。解释动画、录屏、实拍、图库和 AI 概念画面按本镜表达比较，不设固定来源顺位；证据真实性边界仍保留。

### 11.4 风格锚必须冻结

混合模式下真人本身就是风格锚，各镜 B-roll 风格有些出入不致命。全覆盖下这个锚不存在，画面 100% 自制，风格漂移会立刻暴露成"素材东拼西凑"。所以 `visual-contract.json` 从省钱开关升级为**硬前置**：全覆盖禁止跳过关键帧阶段，必须先冻结视觉合同再进批量生产。

### 11.5 选题适配

全覆盖适合**解释型、信息型、机制拆解型**内容。强个人经历、态度表达、争议判断类**慎用**：这类内容的可信度来源就是"是这个人在说"，去掉出镜等于把最强的信任杠杆丢掉。这个判断在 `/produce` 定选题时就该有意识，不是 `/package` 能补救的。

### 11.6 时间轴风险放大

估算时长在混合模式下错了是剪辑返工；全覆盖下每镜都要渲染，估错就是整批重渲。因此：

- `/package` 一律不出成片、不写绝对时间码（§6.1，全覆盖下更严格）
- `/broll` 拿到真实时间轴后**必须停一次**，出真实秒数版分镜确认表让用户点头，再进批量生产
- 典型冲突：某句实际只念了 1.2 秒但设计了 4 秒动效。混合模式可退回真人镜兜掉，全覆盖没得退，只能合并镜头或精简设计

## §12 已知空白

- **老手与新手需要相反的画面**：帮新手理解的解释动画对已经懂的人有害（expertise reversal）。本账号受众懂与不懂双峰分布，而本文档只有一档策略。
- 竖屏还有三条没写：**纵向构图偏好、一屏一个意思、首帧即封面**。三条都可脚本化检查。
- 字幕带与画面争地**不适用**：本账号字幕、花字、字体在剪映后期做，管线不生成字幕层，只在写稿阶段标金句。

## §13 竖屏交付约束（安全区）

**适用前提：目标主视频确为竖屏。** 本节不是默认画幅。所有镜型（包括沉浸式、静图运镜和透明叠层）先继承主口播视频实际显示比例，用户明确指定目标比例才覆盖。用 `python3 tools/broll_canvas.py probe --video <主视频>` 探测，将来源与尺寸冻结进合同；派发前用 `check --video <主视频> --contract <合同>` 校验，回收后加 `--files <全部成片>` 校验实际输出。MP3 无画幅，不能由音频文件或平台习惯推断 9:16。横屏素材按横屏重新构图，不拉伸或加黑边，不套用下方竖屏安全区。

本节是**平台事实**，不是视觉风格：抖音 UI 会实际盖住画面的一部分，盖住的地方放了信息等于没放。本项目不定版式——**如何在安全区里布局由 visualization 决定**，这里只负责把约束当参数传过去（`/package` 关键帧需求单与 `/broll` 动效需求单的调用合同里各一行）。

### 13.1 被吃掉的区域（1080×1920，保守经验值，未实机校准）

| 边 | 内缩 | 谁占的 |
|---|---|---|
| 上 | 约 10%（≈190px） | 搜索栏、关注/推荐切换 |
| 下 | 约 22%（≈420px） | 账号名、文案、话题、音乐条、进度条 |
| 右 | 约 20%（≈215px） | 头像、点赞、评论、收藏、分享竖排 |
| 左 | 约 5%（≈55px） | 边缘留白 |

→ **核心信息安全区 ≈ x 55–865px、y 190–1500px**，约占画面一半。

校准方法很便宜：在抖音里打开任意一条视频截一张全屏图，量出各 UI 元素实际覆盖范围，回来改这张表。校准前按保守值执行——宁可留白，不要让关键信息压在 UI 下面。

### 13.2 三条后果

1. **关键信息（数字、结论大字、被圈注的那一行）必须整体落在安全区内。** 装饰、底纹、背景可以铺满全画幅。
2. **证据类截图不许整页缩小铺满画面。** 整页塞进 9:16 的结果是关键那行既小又落在被遮区——要按 `定场` 先给完整对象 0.5–1 秒，再**放大裁切**到安全区里配 `圈注`。这是安全区影响最大的一类镜。
3. **不为了避让 UI 把主体挤到左上角。** 安全区是个居中偏上的矩形，构图重心仍应在它的中部。

### 13.3 怎么检查

`/broll` 音画复核时做一次**只读质检**：对每镜成片抽一帧，看关键信息是否越界（ffprobe / 抽帧，不用 ffmpeg 手搓画面）。越界的镜回 visualization 改，不在本项目里修。
