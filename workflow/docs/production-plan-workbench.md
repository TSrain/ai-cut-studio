# 4358 制作计划使用说明

## 入口

打开 `http://127.0.0.1:4358/editor`。未选中具体片段时，在右侧「项目信息」中点「制作计划 → 查看」。时间轴上的「制作计划」是辅助标尺；点击计划块后定位到对应区间，视频外围的网格区域持续显示本段动画、素材、真人镜头、字幕和声音安排，右侧同步为当前段。眼睛按钮开关画布计划标注，计划与标注不会进入视频导出。理解目标和理解困难等内部分析不显示在预览。

## 当前 package 与独立真实素材（2026-10-13）

新 package 按全文表达需求直接应用可用原生模板，唯一 Claude 动画提示词留在总结末尾，不走旧分镜／关键帧批准。新 package/broll 的当前结果保存后，宿主默认另启 parentJobId 绑定的真实素材任务；worker 只交本次 manifest，不递归调用 footage 或混入其结果；历史任务不自动补跑。旧说明里的批准／单候选链接仅用于旧合同和普通识别，不约束该支线。

制作计划的「真实素材审稿与搜集」独立处理当前完整口播；不因有真人、无动画或 Claude 未制作而跳过。免费可复用素材实际下载与核验，推荐自动追加独立静音素材轨道，所有其余可用候选保留「素材 → 本项目」，不会自动加入公共库。旧动画、模板和手调保留。控制台显示「项目候选」「待入轨」「已入轨」，提供逐段审稿、独立报告、全部候选清单与最新报告入口；不要求旧镜头／槽位批准。

package 总结的“真实素材审稿与候选”章节说明逐段理由、不同画面角度、许可／下载／核验、推荐位置及缺口，动画与素材支线状态分开。该功能不执行镜头推拉、字幕、封面和声音，技术通过或已入轨不代表完整播放／听审或最终采用。详见 [真实素材合同](real-footage-contract.md)。

## 制作计划轨道的标注原则

轨道只标注需要加工或补充的区间。完全保留原片、原声的段落不显示计划块，完整计划仍保留其口播上下文和时间定位。音效、音乐调整、镜头切换或推拉、动画、网络素材、本人补录屏/实拍都属于制作工作，即使尚未生成或下载，也需要标注。隐藏原片段落不压缩时间、不移动素材、不重新编号；点击可见计划块仍对应完整计划里的同一镜。分类不明确或新修改与旧标记冲突时先保留显示。

## 从脚本到成片

1. 只有脚本也能生成 package。右侧「生成 / 更新计划」录入正文，生成分镜草案；确认本期分镜及视觉方案后生成关键帧。没有实际口播时，时间仅作估计，不据此制作最终镜头视频。
2. 录完口播后导入主视频，提供或生成实际转写，再运行口播对齐。可靠的段落自动对应真实时间；数字、否定、专名等重要差异进入集中确认，可区分识别错误、口误和有意改稿。新增、删除、重排也需确认；手动调整的位置优先保留。
3. 右侧默认显示精简总览，点击计划块后只显示当前段的候选素材、修改意见与任务状态。输入意见后点「确定修改」，后台 Codex 读取冻结的当前 package 与工程，仅修改选中区间，经版本校验保存后自动刷新。已有模板参数、原生镜头、已核验自动音轨与有自动基线的字幕可以局部调整；新增素材/音效、定制动画和无法安全定位的变更明确记录缺口，不声称已制作。旧任务在语义需求变化后失效；并发改动不覆盖，结果未写回可「基于当前版本重试」。草稿按工程和段落独立保留。手动时间编辑、生成整期、完整计划、交付清单导入、历史和完整任务控制仍在「更多」中。删除只取消本段计划，保留口播及已入轨内容，可撤销或从「已删除的计划」恢复。
4. 运行整期或逐镜 broll，后台持续显示进度。符合当前需求、目标和技术条件的结果可逐项接入；已占用或需要判断的结果进入「集中确认」，不会强行覆盖你的剪辑。
5. 独立真实素材支线默认实际获取，按上节执行；明确只收链接或旧合同任务的网络素材以候选链接交付。对应镜头有未读红点；展开后查看来源、建议区间和描述，按链接自行下载。真正可见的候选才标记已读。
6. 在「素材 → 本项目」用一个上传入口批量导入图片和视频。可拖到时间轴，也可在预览中添加到当前播放头。录屏和后补素材后台识别，集中确认匹配镜头、槽位、区间与采用位置；识别不确定时，先预览，再明确勾选人工内容确认。技术失败不能通过此勾选跳过。
7. 「素材库」为跨项目公共素材。项目素材不会自动变公共；在预览中选择「添加到素材库」后，项目中的原素材仍保留。
8. 未补齐的计划可以在知情后导出；实际被使用但丢失的媒体会阻止导出。计划文字、红点和辅助轨道不出现在视频中。

## 同步与历史

- 工程里的「当前有效计划」是后续 package/broll 的输入。右侧编辑和 Codex 对工程的修改使用同一接口与版本校验；并发改动同一字段时保留冲突供选择。
- 旧 package 为历史快照，不反向覆盖工程，也不被工程修改回写。
- 桌面项目空间的 `.制作资料/剪辑工程/<工程ID>/工程.json` 保存当前工程；当前计划 Markdown、历史、后台任务、审批和归档素材保存在同一制作资料空间。可直接使用的视觉产物仍遵循桌面产物分类。
- Codex 自然语言 package/broll 先按脚本编号发现已绑定工程；有多个工程时明确选择，不猜测覆盖。
- 后台新增素材也能撤销。撤销后的结果不会因为轮询或旧任务回报重新出现；需要时显式重做或重新采用。

## 开发版本与回退

本次实现保存在两个仓库的 `codex/production-plan-integration` 分支。原工作区存在其它未提交修改，因此部署采用逐文件三方整合，不切换原分支、不重置暂存区。

备份分支包括 `codex/production-plan-baseline-20261011` 与 `codex/production-plan-predeploy-v3-20261011`。实际部署的文件清单、旧字节、SHA 校验和回退脚本位于：

`workspace/production-plan-dev/control/deployment/`

首轮部署清单：内容仓库 `content-final/manifest.json`，工作台 `visual-final-v4/manifest.json`；后续补丁的清单与顺序见该目录的 `release.json`。回退按相反顺序执行。

回退时应先确认没有活动制作或导出，按最终 manifest 运行 `apply-integration.py <manifest> --rollback` 进行只读预检，再加 `--apply`。如果文件在部署后又被修改，脚本会拒绝覆盖，需要先合并新改动；不要直接 reset 整个工作区。
