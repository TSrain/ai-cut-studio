# Claude 运行规则（2026-10-13）

适用于自媒体工作流、visualization 中由用户手动运行的 Claude Code。只约束入口、模型任务调度和错误处理，不改变 Codex 编排、动画设计、画幅、交付清单或用户手调。它是运行规则，不是防封承诺，也不是官方限额。

## 入口与优先级

- 用户当前明确指令优先；本文件的运行限制优先于旧命令/技能中的一次派完、无限并行或失败重试描述。具体创作要求仍由当前任务合同决定。
- 自媒体主流程以 `../workflow/AGENTS.md` 和 `.devin/skills/content-*/SKILL.md` 为准；`.claude/commands/package.md`、`broll.md` 只作兼容入口，不恢复旧关键帧审批流程。
- 公开版的动画运行约定为 `../studio/AGENTS.md`。用户手动定制动画使用 `../studio/.devin/skills/custom-animation/SKILL.md`，不要求特定厂商的 Agent，也不重跑完整制作。
- 只有明确续作旧合同才读取旧分支。需要仓库 motion-broll 时，真实路径是 `../studio/.devin/skills/motion-broll/SKILL.md`；不要猜测不存在的旧目录，也不要搜索 benchmark 作为运行时替代。

## 模型任务调度

- 普通 Claude 任务：同一主会话及其后代合计最多 2 个未结束的模型子任务。主会话派发后等待结果，不另起一项并行模型工作；排队项不占槽，运行中、后台执行和尚未结束的子任务都占槽。子任务不得再次派发模型子任务。
- 把任务排成队列，每批至多 2 个；确认上一批结束后再派下一批。单任务直接执行，不为凑并发创建代理；保留全部目标，不因排队减少镜头或降低质量。
- 口播动画专线遵循更严格的现有规定：串行制作，不开模型子代理；两个一批是交付组织方式，不是两个模型同时运行。浏览器渲染仍最多 2 个，与模型任务数分别计算。
- 每个子任务都必须收到本文件路径和相同的停止规则。无法确认旧子任务是否退出时，不启动替代任务。不要用额外 `claude -p`、嵌套 CLI、Agent Team 或后台会话绕过队列。
- 这不是跨窗口的程序锁，无法发现或限制用户另一个 Cursor 窗口的会话。不要宣称实现了账号级限流器；有已知并行会话时先排队，不自行启动更多会话。

## Claude 服务出错时

- 收到 Claude/Anthropic 的 429、额度耗尽、明确限流，停止新的模型派发；记录服务端重置时间或 Retry-After（若提供），结束本轮自动重试。到时也不自动唤醒，由用户恢复。
- 收到 Claude/Anthropic 的 401、403、登录失效、account/organization disabled、suspended 或 unusual activity，停止新的模型派发并尝试取消本次任务创建的仍在运行的子任务；取消无法确认则说明，不启动替代调用。
- 不通过换账号、改设备标识、改请求客户端、换出口或重登循环继续失败请求。允许官方 CLI 正常自动维护登录；不要自行读取/改写登录令牌或实现刷新逻辑。
- 单纯网络超时或 5xx：明确失败且没有仍运行请求时，最多重试 1 次；遵守 Retry-After，没有时至少等 30 秒。结果不明不重发可能重复执行的操作；再次失败停止。
- 第三方素材网站的错误按其自身规则处理，不把第三方 403 说成 Claude 封号；本地渲染/校验错误也不等于账号错误。
- 保留已有文件和进度；可行时保存脱敏错误、时间、任务名、已完成项、未完成项和恢复入口。绝不记录密钥、OAuth token 或完整认证头。若 Claude 已被服务端阻断到无法写文件，如实说明需要用户保留界面报错，不能承诺一定自动落盘。
