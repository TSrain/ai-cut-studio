# 工程内口播粗剪

在 Motion Studio 项目属性的「口播粗剪」中操作。原片始终保留，结果是可恢复的片段引用；导出沿用工程原生视频管线，无需剪映。

## Codex 入口

向 Codex 提供本地原始视频路径并说 `roughcut` 即可；例如 `roughcut /绝对路径/原片.mov`，也可附带“目标两到三分钟”。这是技能请求，不是 shell 命令。全局 `$roughcut` 默认进入本流程；只有明确指定剪映时才使用旧 GUI 分支。无需提供 OriginCut 参考成片。

默认交付已保存、回读的原生工程和当前 SRT，不自动执行 package 或整片导出。同源已有工程先核验并保留手调；重新分析已有制作内容时从原片建副本。时长按完整表达与本次目标判断，不固定保留最后一遍，不把两分钟硬套到所有视频。

## 使用

1. 导入口播原片，打开「口播粗剪」，点击「开始口播粗剪」。已有动画、镜头、配乐或手动剪辑时，使用「从原片新建粗剪副本」，原工程保留。
2. 分析依次读取共享转写、检测停顿、对齐字词、判断全文重复表达。关闭面板或刷新网页后会续接任务；服务重启会明确报失败，可重试并复用共享转写。
3. 查看「已删除」「待检查」候选。每条提供删除理由、「播放原片」和「预览切口」；后者播放切口前后的一小段工程内容，可勾选「循环切口」反复播放，或随时「停止预览」。
4. 用「恢复这段」恢复内容；展开「调整原片切点」修改起止帧。切点使用原片坐标，终点不包含。系统拒绝切半个已对齐字词或侵入保留内容。时间边界或语义受保护的候选，可先播放原片核对，再点「手动删除整段」；只采用该条完整候选，仍拒绝越界、切半单位、重叠、明确保护区及无法同步的人工字幕。手动采用是操作来源，不表示已听审；恢复后可再次删除，撤销会还原采用前状态。
5. 修改进入现有撤销/重做和自动保存。音视频共用片段映射，字幕按实际保留的字词重建。新字幕沿真实单位边界在标点、较长气口、约 18 字或 4 秒处断开；不可拆的保护组保持完整。已有人工字幕保留原有断句与样式。可下载当前 SRT，再从顶部「导出」输出视频。
6. 选中主轨片段可拖动左右边缘，向外恢复原片内容、向内减少内容；操作进入撤销/重做。字幕及后续关联视觉、音频和标记按同一次主轨变化同步移动。影响锁定轨道时整次操作拒绝，不自动解锁。手调后顺序未重复的原片映射仍支持候选恢复；重排或重复引用造成歧义时会保护性拒绝恢复，不覆盖手调。
7. 「恢复粗剪前原片」恢复开始分析时的原片及字幕，此操作也可撤销；它与局部“恢复这段”不同，已有后续制作内容时仍受模型的冲突保护限制。粗剪保存后即可启动 package；审看和微调可与制作同时进行，见下节。

## Roughcut 后立即 Package

日常流程：`roughcut 原片路径` → 粗剪保存 → `给当前工程做 package` → 在控制台审看、调整切点或字幕 → 等制作结果并检查 → 导出。无需另跑 broll。

明确要求导出时先执行 [导出前核对](export-preflight.md)：对照原片显示分辨率、工程画布和实际输出目标。未指定降分辨率时默认保留原片显示分辨率，不能直接沿用 1080p 默认画布。

- package 冻结的是启动时**最新保存工程**的字幕、完整口播正文和主轨映射。派生 SRT 明确使用工程时间，不覆盖原始转写缓存；修改文字、删段及调整切点不触发重复识别。
- 新 v2 任务支持同源顺序剪辑期间的并行制作。发布时依据原片坐标对齐当前时间轴，删除区间不恢复，安全保留区间自动重定位；音频媒体偏移、字幕和段落绑定随之校正。手调、隐藏、锁定和删除记录优先。
- package 完成保存计划时，再从最新字幕生成派生正文/SRT，并绑定来源、主轨映射和字幕指纹。下一轮读取这一版；已生成封面、候选及其他不受影响成果保留。
- 若改动了某段的实际意思，相应旧画面建议会明确列为需校正，其他段继续。对 Codex 说“按当前工程校正 package”，由它检查受影响项并补齐；不需要重新识别整条原片。换原片、变速、重排或重复引用等无法唯一映射的变化，需要以当前工程建立新基线。
- 本轮复用与跨轮复用分开：新轮只有显式选择 `validated-project-artifacts` 并通过依赖核验的成果才复用；不保证所有旧模型提案都不重做。BGM 目前交规划及候选，实际配乐音轨是否已有需另看工程。

## 当前取舍（完整表达优先）

- 全文先选完整口播版本，再处理重录、中断和录制插话。模型输出保留/弃用的原话单位 ID，必须恰好覆盖全文一次，不能自造秒点或改写原话；独立全文二审检查重复、遗漏和衔接。
- 不默认保留最后一遍。比较事实、数字、否定、条件和“可能／一定”等断言强度，选择完整、准确的表达；不能因为后一次措辞不同而把每遍都保留。
- 以保留句为主安排切点，句首约 100ms、句尾约 180ms 余量受邻近原话边界约束；只有保留句内的可靠长静音才局部缩短。删除区由保留范围的补集生成，不独立堆叠大量静音切口，避免留下无话语的细碎视频块。
- 不把呼吸和强调性重复当普通赘词。零时长字与可靠邻字组成不可拆原子组，不平均分配时间；疑似漏字区保留待核对。明确手动采用保留原因和恢复入口，不伪装自动确认。
- 受保护的异常转写区只是“未冒险删除”，不代表“没有重复”。交付前检查零时长字、宽时间组、疑似漏词对应的原片区间及开头结尾；有证据则修正切点和派生字幕，无足够证据则列明待核对位置，不猜内部秒点、不声称全面验收。
- 新字幕使用实际保留字词投影，同原片切口断开；18字或4秒强制断句导致的极短尾巴，满足同句群、同片段及22字／5秒限制时回并。专名纠错使用派生层 captionOverrides，原始 ASR 与 originalText 不变，已有人工字幕不被改写。
- 静音检测尚不是呼吸识别器；技术检查、播放器连续运行、真实听审和用户采用分别记录。
- 历史删除决策模式与旧工程指纹保持兼容；新粗剪默认 complete-takes，不自动改写历史工程。

## 交付前的实际剪辑复核（2026-10-21 用户反馈）

- **先选完整录制遍次，再清理停顿。** ASR 的同一行可能跨越多次重录，不能把前一遍的尾句和后一遍的起句当作一个完整表达。相同论点后一次已讲完整时，应比较整遍的完整性与准确性；不要因措辞有差异，把两个版本都留下，也不要为了逐字保全信息拼出录制时没有说过的一句话。
- **静音结果为空不代表没有停顿。** 有底噪、呼吸或短促杂声时，固定峰值阈值可能漏掉数秒空白。对照实际 PCM 音量和已对齐语音覆盖复核；若明显空白未检出，先处理该缺口，不能带着空静音列表直接交付。RMS/低音量只提供候选证据，不自动等同于无人声。
- **停顿和动作一起检查。** 每个保留片段检查开头、结尾及内部长空白；每个切口检查前后原片的连续邻帧、字音边界和录制动作。录制间转头看屏幕、摆头、准备下一遍等应随废弃遍次移除，正常表达中的自然手势不机械删。句首句尾余量是可用上限参考，不是必须保留的空白。
- **异常对齐要修证据，不要批量强制采用。** 禁止为降低“待检查”数量逐个强制采用所有候选。零时长字、跨重录的宽时间组或首字被拉到前一遍时，复用原转写，在单一完整遍次的真实音频窗口内做局部 forced alignment，并结合音量及口型复核。原始 ASR/分析证据保留；派生字幕保留零时长字的文字并与可靠邻字并组，不能过滤掉这些字，也不能平均分配内部时间。
- **先验证整条，再交用户。** 必须复核完整保留正文、全部切口、内部长停顿、开头结尾和字幕跟随，并将用户指出的位置逐一映射回原片，记录修复前后结果。工程保存、字幕时间合法、模型二审通过只是技术证据。若未真实听审，只能如实说明检查范围，不能称“切口听起来自然”“完整看听通过”；也不能把大量可处理的重复和长空白留作清单后就停止。

该规则由 MVI_7521 的失败交付回归而来：工程原 8 秒附近保留约 2.4 秒转头空白；15–25 秒混入前遍尾句和后遍起句；约 30 秒保留超过 5 秒空白。此例不是时长或停顿参数模板，后续按实际录制判断。

## 运行依赖

视频通过流式导入，默认上限 32 GiB；已知文件大小时先检查磁盘空间，接收后核对实际字节数，失败删除未发布的临时文件。完整原片与预览代理分开，不能用代理替代导出来源。SDR、直角旋转和 VFR 原片可生成保持每帧 PTS 的低清代理；逐帧时钟和复制音轨校验通过才发布，播放器只预载紧邻下一段，导出继续使用原片。真实 `IMG_5666.MOV`（4,975,905,962 字节）已通过新入口导入。

复用 `tools/transcribe.py` 的共享转写和既有飞书配置；原片有已关联 SRT 时无需再次识别。语义分析使用现有 Codex 登录，优先应用自带 CLI。精细对齐使用本地 Qwen3-ForcedAligner-0.6B，只对齐已有文字，不另做 ASR。

默认本地环境：

```text
workspace/roughcut-runtime/.venv/bin/python
workspace/roughcut-runtime/Qwen3-ForcedAligner-0.6B
```

支持 `ROUGHCUT_ALIGN_PYTHON`、`ROUGHCUT_ALIGN_MODEL`、`ROUGHCUT_ALIGN_DEVICE`、`ROUGHCUT_CODEX_BIN`、`EDITOR_WORKFLOW_ROOT` 覆盖。对齐不可用时明确降为段级保护；转写或语义失败不发布伪造结果。可信对齐缓存绑定实际音频身份、时间原点、原始文字及时间码、模型内容、运行库版本和设备；内容变化后重新对齐。语义结构错误最多纠正两次，各次已明确的保留保护不能被纠正过程撤销。

新模式的主选择、独立二审、格式修复及缓存证据保存在任务目录 `complete-takes/`，绑定完整单位内容、提示词版本和验证结果。修改取舍规则须升级 `tools/roughcut_takes.py` 的 `PROMPT_VERSION`。旧模式的 coverage 证据继续保留兼容。

后端任务及日志在 visualization 的 `workspace/roughcut-jobs/<任务ID>/`，工程完整状态在既有 editor-projects 下。分析快照、原始转写和当前字幕分开保存。

新增分析入口：

```sh
python3 tools/roughcut_analyze.py --audio /绝对路径/原片.mp4 --out /绝对路径/analysis.json --work-dir /绝对路径/工作目录 --source-key 工程源身份
```

工程调用应走控制台 API，让来源身份、版本和文件变动校验统一执行。

维护时可在同一任务目录用 `--resume` 恢复：先核验原媒体、转写及分析回执；语义文件缺失或输入不同会重新判断。已有回执 SHA 不符直接拒绝，历史无静音回执则重新测量静音。此选项不跳过来源核验。
